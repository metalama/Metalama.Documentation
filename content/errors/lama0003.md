# LAMA0003: The aspect doesn't support this kind of declaration

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Aspect '<AspectType>' cannot be applied to <DeclarationKind> '<Declaration>', because this aspect does not implement the '<InterfaceType>' interface.` |

## Cause

An aspect declares the kinds of declarations it can be applied to by implementing the generic `IAspect<T>` interface, where `T` is the code model type of the target, for instance `IAspect<IMethod>` for methods or `IAspect<INamedType>` for types. An aspect can implement this interface several times to support several kinds of declarations.

When Metalama executes an aspect, it checks that the aspect class implements `IAspect<T>` for the kind of the target declaration. If it doesn't, Metalama reports LAMA0003 and skips the aspect. In the message, `<DeclarationKind>` is the kind of the target declaration and `<InterfaceType>` is the interface that the aspect would need to implement.

The C# compiler normally prevents this situation: the base aspect classes, such as `TypeAspect` or `OverrideMethodAspect`, carry an `[AttributeUsage]` attribute that matches the interfaces they implement. However, when you implement `IAspect<T>` directly in a class derived from `Attribute` and don't add `[AttributeUsage]`, or when `[AttributeUsage]` allows more targets than the implemented interfaces, C# accepts the attribute on declarations that the aspect can't handle.

## Resolution

Depending on your intent, do one of the following:

* Apply the aspect to a declaration of a kind that it supports.
* Add an `[AttributeUsage]` attribute to the aspect class that allows only the kinds of declarations for which the aspect implements `IAspect<T>`, so that the C# compiler reports wrong usages. Alternatively, derive the aspect from a base class such as `TypeAspect`, which already has the right `[AttributeUsage]`.
* If the aspect should support this kind of declaration, implement `IAspect<T>` for this kind too.
