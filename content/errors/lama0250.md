# LAMA0250: This use of dynamic isn't allowed in a template

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `In a template, 'dynamic' cannot be used as the type of a cast, 'as', 'is', or 'default' expression, as the type of a lambda parameter or return value, or as a type argument of a method.` |

## Cause

In a T# template, `dynamic` stands for a run-time type that's only known when Metalama expands the template. Metalama replaces each `dynamic` expression with code of the actual type. However, when `dynamic` is written as a type in the template, Metalama has no actual type to put in its place.

Metalama reports LAMA0250 when a template uses the `dynamic` type in one of the following places:

* the target type of a cast, for instance `(dynamic) value`;
* the type of an `is` or `as` expression;
* the type of a `default` expression, `default(dynamic)`;
* the type of a parameter or the return type of a lambda expression;
* an explicit type argument of a generic method.

Using `dynamic` as an array element type, a generic type argument of a type, or a tuple element type is reported as <xref:lama0227>.

In the following example, the aspect returns the default value of the return type when a feature is disabled, and the template uses `default(dynamic)`.

## Resolution

Remove the `dynamic` type from the expression:

* To get the default value of the return type of the target method, use `meta.Default( meta.Target.Method.ReturnType )`, as shown in the following example.
* Instead of casting an expression to `dynamic`, use an expression that's already `dynamic`, such as `meta.Proceed()` or the `Value` property of a parameter. To give a type to an expression, use <xref:Metalama.Framework.Code.SyntaxBuilders.ExpressionFactory.WithType*>.
* In lambdas and in type arguments, use the actual type, or build the code with the code model and <xref:Metalama.Framework.Code.SyntaxBuilders.ExpressionFactory>.
