# LAMA0701: No dependency injection framework is registered

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Extensions.DependencyInjection |
| **Message** | `The dependency '<DependencyType>' in type '<TargetType>' cannot be handled because no dependency injection framework is registered. Register a framework by calling the RegisterFramework method from ConfigureDependencyInjection in a fabric.` |

## Cause

The <xref:Metalama.Extensions.DependencyInjection.DependencyAttribute> aspect, the <xref:Metalama.Extensions.DependencyInjection.IntroduceDependencyAttribute> advice, and the `IntroduceDependency` method don't generate the code that pulls a dependency themselves. They delegate this to a dependency injection framework, an implementation of <xref:Metalama.Extensions.DependencyInjection.Implementation.IDependencyInjectionFramework> registered for the project, namespace, or type.

By default, two frameworks are registered: `LoggerDependencyInjectionFramework`, which handles `ILogger` dependencies, and <xref:Metalama.Extensions.DependencyInjection.Implementation.DefaultDependencyInjectionFramework>, which handles other dependencies with the .NET Core pattern. A fabric can remove them with the `UnregisterFramework` method of the options builder passed to <xref:Metalama.Extensions.DependencyInjection.DependencyInjectionExtensions.ConfigureDependencyInjection*>.

Metalama reports LAMA0701 when a dependency must be handled but the list of registered frameworks is empty. In the message, `<DependencyType>` is the type of the dependency and `<TargetType>` is the type into which the dependency must be introduced.

In the following example, the project fabric unregisters both built-in frameworks without registering another one, so the `[Dependency]` aspect on the `_clock` field has no framework to handle it.

## Resolution

Make sure that at least one framework is registered for the type:

* If you unregistered a built-in framework to replace it, register your own framework with the <xref:Metalama.Extensions.DependencyInjection.DependencyInjectionOptionsBuilder.RegisterFramework*> method in the same `ConfigureDependencyInjection` call.
* Otherwise, don't unregister <xref:Metalama.Extensions.DependencyInjection.Implementation.DefaultDependencyInjectionFramework>.
