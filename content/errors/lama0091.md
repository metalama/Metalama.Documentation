# LAMA0091: An extension contribution can't be made after a low-level weaver

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectName>' makes an extension contribution, such as an interceptor registration, but it executes after a low-level aspect weaver, and contributions are processed only before the first low-level aspect weaver. Order the aspect before the aspects that require a low-level weaver.` |

## Cause

Aspects normally transform code with the high-level advising API. Some aspects need a low-level weaver, written with the Metalama SDK, and bind to it with <xref:Metalama.Framework.Aspects.RequireAspectWeaverAttribute?text=[RequireAspectWeaver]>. A low-level weaver runs after the high-level aspects that precede it and rewrites the compilation directly.

Some aspects also make _extension contributions_: they register data that a Metalama extension, such as `Metalama.Extensions.Interceptors`, processes once for the whole pipeline. For instance, an aspect registers interceptors with the `InterceptMethods` method. Extensions process only the contributions made before the first low-level aspect weaver, because after this weaver the compilation has been rewritten.

Metalama reports LAMA0091 when an aspect makes an extension contribution but is ordered to execute after an aspect that requires a low-level weaver. In the message, `<AspectName>` is the aspect that made the contribution. The error is reported on the target of that aspect.

In the following example, `InterceptWrite` registers an interceptor, but the aspect order makes it execute after `Audit`, which requires a low-level weaver. `InterceptPrint`, which executes before `Audit`, is processed normally. A second `AspectOrder` attribute orders `Audit` after the contract aspects of the referenced libraries, so that the weaver doesn't fall between the layers of one of them (see <xref:lama0042?text=LAMA0042>).

## Resolution

Order the aspect that makes the extension contribution before every aspect that requires a low-level weaver, with the <xref:Metalama.Framework.Aspects.AspectOrderAttribute?text=[AspectOrder]> attribute. In the following example, `Audit` executes after both interceptor aspects.
