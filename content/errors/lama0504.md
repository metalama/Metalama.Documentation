# LAMA0504: The introduced member and the existing member differ in staticity

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce member '<Member>' into type '<TargetType>' because it is already defined in type '<DeclaringType>', and one of the two members is static while the other is not.` |

## Cause

When an aspect introduces a method, property, field or event, Metalama checks whether the target type, or one of its visible base types, already defines a member with the same name, or the same signature for methods. If such a member exists, both members must be static, or both must be instance members.

Metalama reports LAMA0504 when one of the two members is static and the other isn't. This check runs before the override strategy is considered, so changing the strategy doesn't remove the error.

In the following example, the `Describable` aspect introduces an instance method `Describe()`, but the `Product` class already has a static method `Describe()`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0504/LAMA0504_Error.cs name="Error"]

## Resolution

Depending on your intent, do one of the following:

* Rename the existing member or the introduced member, so that they no longer conflict.
* If both members represent the same thing, make the template and the existing member both static or both instance members, and choose an override strategy such as `OverrideStrategy.Override` or `OverrideStrategy.Ignore`.
