# LAMA0041: Compile-time code throws an exception

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `An exception of type '<ExceptionType>' was thrown while <Activity>: <ExceptionMessage>. Exception details are in '<DetailsPath>'. To attach a debugger to the compiler, use the '-p:MetalamaDebugCompiler=True' command-line option.` |

## Cause

During compilation, Metalama executes your compile-time code: the `BuildAspect` and `BuildEligibility` methods of aspects, templates, fabrics, validators, and the constructors of these types. Metalama reports LAMA0041 when this code throws an exception that it doesn't handle.

In the message:

* `<Activity>` describes what Metalama was executing, for instance `executing BuildAspect for aspect [LogAttribute] applied to 'Calculator.Add(int, int)'` or `executing the template method 'LogAttribute.OverrideMethod()'`;
* `<ExceptionType>` and `<ExceptionMessage>` are the type and the message of the exception;
* `<DetailsPath>` is the path of a text file that contains the complete exception, including its stack trace, or `(none)` when no file was written.

When possible, the error is reported on the target declaration of the aspect.

Some exceptions are thrown by Metalama itself, but are caused by the aspect code. For instance, Metalama throws an `InvalidOperationException` when an aspect adds an advice to a declaration for which this advice isn't eligible. Such exceptions are also reported as LAMA0041, and their message explains the problem.

## Resolution

Read the exception message and type in the diagnostic message. If they aren't enough to find the cause, open the file given at the end of the message to see the stack trace.

Then, depending on the situation:

* If you're using the aspect, make sure that you're using it as its author intended, for instance by setting its required properties. The following example sets the `Category` property.
* If you're the author of the aspect, fix the bug. Instead of throwing exceptions for invalid usages, define eligibility conditions in `BuildEligibility`, or report an error with `builder.Diagnostics.Report` and skip the aspect with `builder.SkipAspect()`. Before adding an advice, check its eligibility with the `IsAdviceEligible` extension method of the target declaration.
* To debug the compile-time code, build the project with the `-p:MetalamaDebugCompiler=True` command-line option, which lets you attach a debugger to the compiler.
