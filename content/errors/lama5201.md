# LAMA5201: A command can't have both a can-execute method and a can-execute property

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Wpf |
| **Message** | `The CanExecuteMethod and CanExecuteProperty properties cannot both be defined at the same time.` |

## Cause

The <xref:Metalama.Patterns.Wpf.CommandAttribute?text=[Command]> aspect generates a WPF command property from a method. The command's `CanExecute` logic comes from a single member: either a `bool` method or a `bool` property. You can name this member explicitly with the <xref:Metalama.Patterns.Wpf.CommandAttribute.CanExecuteMethod> or the <xref:Metalama.Patterns.Wpf.CommandAttribute.CanExecuteProperty> property of the attribute, but not with both.

Metalama reports LAMA5201 on the target method when both properties are set, for example `[Command( CanExecuteMethod = "CanSave", CanExecuteProperty = "IsSaveEnabled" )]`. The aspect then stops: it doesn't generate the command property and doesn't report any other diagnostic for this method.

In the following example, the `Save` command sets both `CanExecuteMethod` and `CanExecuteProperty`.

## Resolution

Keep only one of the two properties in the `[Command]` attribute:

* If the `CanExecute` logic is a method, keep `CanExecuteMethod` and remove `CanExecuteProperty`.
* If it's a property, keep `CanExecuteProperty` and remove `CanExecuteMethod`. Prefer a property when the declaring type implements <xref:System.ComponentModel.INotifyPropertyChanged>: the command then raises its `CanExecuteChanged` event when the property changes.

You can also remove both properties and rely on the naming convention: for a command named `Save`, the aspect looks for a member named `CanExecuteSave`, `CanSave`, or `IsSaveEnabled`.
