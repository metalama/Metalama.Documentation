# LAMA0661: A variable was renamed because it hides a parameter

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Framework |
| **Message** | `The <VariableKind> '<Name>' is renamed to '<NewName>' in the compiled code, because it hides the parameter '<Name>' of '<Member>', and this parameter is passed by <Description>. The compiled code no longer matches the source code, so the debugger shows the new name. Rename the <VariableKind> in the source code to remove this warning.` |

## Cause

The `Metalama.Extensions.Interceptors` package lets an aspect or fabric redirect calls to a method, and pass a parameter of the calling method to the new target, for instance with `site.Caller.Parameters[0]`. The redirected call then contains the name of that parameter.

When the call is inside a lambda expression or a local function that declares a lambda parameter, a local variable or a parameter with the same name, this variable hides the parameter of the calling method, and the name would designate the wrong variable. The linker therefore renames the hiding variable and its references in the compiled code, and reports LAMA0661 on its declaration. The compiled code no longer matches the source code, so the debugger shows the new name.

In the message, `<VariableKind>` is the kind of the renamed variable, such as lambda parameter, local variable or local function parameter, `<Name>` and `<NewName>` are its old and new names, `<Member>` is the calling method, and `<Description>` describes the redirected call.
