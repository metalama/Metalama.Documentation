# LAMA0750: Members can't be introduced into this kind of type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce a member of kind '<IntroducedDeclarationKind>' because the target type is of kind '<TargetTypeKind>'. Members can be introduced only into a class, a struct, or an interface.` |

## Cause

When an aspect class contains members marked with the <xref:Metalama.Framework.Aspects.IntroduceAttribute?text=[Introduce]> custom attribute, Metalama introduces these members into the target type of the aspect, or into the declaring type when the aspect is applied to a member. Only classes, structs, and interfaces, including records, can receive introduced members.

Metalama reports LAMA0750 when this type is of another kind, typically an enum or a delegate. This can happen because <xref:Metalama.Framework.Aspects.TypeAspect> can be applied to enums and delegates, and because a fabric can add an aspect to all types of a project, enums included. The aspect is then skipped for this target. In the message, `<AspectType>` is the aspect, `<IntroducedDeclarationKind>` is the kind of the member to introduce, and `<TargetTypeKind>` is the kind of the target type, for instance `Enum`.

## Resolution

Do one of the following:

* Apply the aspect to a class, a struct, or an interface. In the following example, the aspect is moved from the enum to the class that uses it.
* When you add the aspect with a fabric, select only the types that can receive members, for instance by filtering on the `TypeKind` property of the types.
* If you're the author of the aspect, add an eligibility condition in its `BuildEligibility` method that rejects enums and delegates, so that the aspect can't be applied to them in the first place.
