# LAMA0231: Only type fabrics can be nested in a run-time type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The compile-time type '<NestedType>' cannot be nested in a run-time type. The only compile-time types that can be nested in a run-time type are classes derived from '<TypeFabric>'. Move '<NestedType>' out of the containing type.` |

## Cause

Metalama builds a separate compile-time assembly that contains your compile-time code, but not your run-time types. The only compile-time types that Metalama extracts from a run-time type are type fabrics, that is, classes derived from <xref:Metalama.Framework.Fabrics.TypeFabric>, because a type fabric amends the type that contains it.

Metalama reports LAMA0231 when any other compile-time type is nested in a run-time type: a class that doesn't derive from `TypeFabric`, for instance a <xref:Metalama.Framework.Fabrics.ProjectFabric> or a class marked with [<xref:Metalama.Framework.Aspects.CompileTimeAttribute>], or a compile-time struct, record, interface, enum, or delegate. The second placeholder of the message is `TypeFabric`.

In the following example, a project fabric is nested in the `OrderService` class.

## Resolution

Depending on your intent, do one of the following:

* If the nested type is meant to amend its containing type, derive it from `TypeFabric`, as in the following example. Keep it `private` (see <xref:lama0230>).
* Otherwise, move the type out of the run-time type, for instance to the namespace level. Project fabrics and compile-time helper types are usually top-level types.
