# LAMA0055: An aspect can't add an aspect of its own type to a declaration processed before its target

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' applied to <ParentTargetKind> '<ParentTarget>' cannot add an aspect of the same type to <ChildTargetKind> '<ChildTarget>' because this <ChildTargetKind> has already been processed by aspects of this type. An aspect can add an aspect of its own type only to a declaration that is processed later, such as a member or a parameter of its target.` |

## Cause

An aspect can add other aspects with `builder.Outbound`, including aspects of its own type. Metalama processes all instances of the same aspect type in a single pass, ordered by the depth of their target declaration: types before their members, and members before their parameters. When an aspect adds an aspect of its own type, the new aspect joins the same pass, so its target must come _after_ the target of the current aspect in this order.

Metalama reports LAMA0055 when an aspect adds an aspect of its own type to a declaration that comes earlier in this order or at the same position, for instance when a method-level aspect adds itself to its declaring type, or when a parameter-level aspect adds itself to its method. In the message, `<AspectType>` is the aspect type, `<ParentTarget>` and `<ParentTargetKind>` are the target of the aspect and its kind, and `<ChildTarget>` and `<ChildTargetKind>` are the declaration to which the aspect tried to add an aspect and its kind. The error is reported on the aspect that adds the other aspect.

When the added aspect has a different type, the order of the two aspect types matters instead, and Metalama reports <xref:lama0022> if it's wrong.

In the following example, the `Log` aspect can be applied to a type or to a method. When it's applied to a method, it tries to add itself to the declaring type, but the type has already been processed.

## Resolution

Reverse the direction: apply the aspect to the outer declaration and let it add aspects of its own type to the inner declarations, which are processed later. For instance, apply the aspect to the type and add it to the methods of the type from the type-level `BuildAspect` method.
