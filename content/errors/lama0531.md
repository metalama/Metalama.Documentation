# LAMA0531: A type with the same name already exists

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce the type '<Type>' into '<TargetNamespaceOrType>' because '<TargetNamespaceOrType>' already contains or inherits a type with the same name and the same number of type parameters. Use a different name, or specify another OverrideStrategy.` |

## Cause

The <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceClass*> method introduces a new class into a namespace or, as a nested type, into a type. Before introducing it, Metalama checks whether the target already has a type with the same name and the same number of type parameters. For a target type, this includes the nested types inherited from its base types and the types introduced by other aspects.

The `whenExists` argument decides what happens in this case. Its default value behaves like `OverrideStrategy.Fail`: Metalama reports LAMA0531. In the message, `<Type>` is the type that the aspect tries to introduce, and `<TargetNamespaceOrType>` is the target namespace or type.

In the following example, the `Memento` aspect introduces a nested class named `Snapshot`, but the target class already has a nested class with this name.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0531/LAMA0531_Error.cs name="Error"]

## Resolution

Do one of the following:

* Give the introduced type a name that doesn't conflict with existing types. If you're the author of the aspect, choose a specific name, as in the following example. Otherwise, rename the existing type.
* Pass `OverrideStrategy.Ignore` as the `whenExists` argument to keep the existing type and skip the introduction. The advice result then refers to the existing type.
* When the conflicting type is a nested type inherited from a base type, pass `OverrideStrategy.New` to introduce a type that hides the inherited one with the `new` modifier.
