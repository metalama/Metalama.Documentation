# LAMA0289: The null-conditional operator can't cross from compile-time to run-time code

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The null-conditional operator cannot be used in the expression '<Expression>' because '<CompileTimeExpression>' is compile-time and '.<RunTimeMember>' returns a run-time value. When the compile-time expression is null, its type is unknown, so type-preserving run-time code cannot be generated. Use a compile-time null check (e.g. an 'if' statement) instead of the '?.' operator.` |

## Cause

Some members of the code model are evaluated at compile time but return a run-time expression. The most common one is the `Value` property of a parameter: the parameter is known at compile time, but its value exists only when the program runs. When a template accesses such a member, Metalama emits run-time code that has the type of the expression.

If the object on which you access the member is a compile-time expression that can be `null`, the null-conditional operator `?.` can't be translated. When the compile-time expression is `null`, there's no declaration to take the type from, so Metalama can't generate the run-time code of the `null` branch. Metalama reports LAMA0289 when the left side of `?.` is a compile-time expression and the member right after `?.` returns a run-time value. In the message, `<Expression>` is the whole expression, `<CompileTimeExpression>` is its compile-time part, and `<RunTimeMember>` is the member.

## Resolution

Replace the `?.` operator with a compile-time null check. Store the compile-time expression in a local variable and test it with an `if` statement. Because the condition is compile-time, Metalama evaluates it while it expands the template and emits the code of the `if` block only when the declaration exists. Inside the block, access the run-time member with the ordinary `.` operator. You can still use `?.` on the run-time value itself, as in the following example.
