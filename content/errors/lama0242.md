# LAMA0242: The type of an expression conflicts with the scope of its sub-expression

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Execution scope mismatch in the expression '<ParentExpression>': the type of the expression is <ParentScope>, but the sub-expression '<ChildExpression>' is <ChildScope>.` |

## Cause

In a T# template, Metalama classifies every expression as either compile-time, which it evaluates while generating the code, or run-time, which it copies into the generated code. The scope of an expression depends on its sub-expressions, but also on its type: an expression of a run-time-only type, such as a type defined in your project, can only exist at run time, while an expression of a compile-time type, such as `IParameter`, can only exist at compile time.

Metalama reports LAMA0242 when the sub-expressions of an expression agree on a scope, but the type of the expression requires the other scope. The message gives the scope of the type and the sub-expression that conflicts with it. This typically happens when you apply the `as` operator to a compile-time object, such as an <xref:Metalama.Framework.Code.IParameter>, while you meant to apply it to the run-time value that the object represents.

## Resolution

Make the sub-expression match the scope of the expression type. To work with the run-time value of a parameter, field, or property, use its <xref:Metalama.Framework.Code.IExpression.Value> property, which is a run-time expression of type `dynamic`.
