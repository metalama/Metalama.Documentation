# LAMA5007: The strictness of the inequality contract is ambiguous

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Patterns.Contracts |
| **Message** | `The meaning of the [<OldName>] attribute on '<Declaration>' is ambiguous because the inequality strictness is not specified. It is now interpreted as <Strictness>, which is non-standard, and this behavior might be changed in the future. Use either [<NewName1>] or [<NewName2>], or specify the DefaultInequalityStrictness property in ContractOptions using the ConfigureContracts fabric extension method.` |

## Cause

The <xref:Metalama.Patterns.Contracts.PositiveAttribute?text=[Positive]>, <xref:Metalama.Patterns.Contracts.NegativeAttribute?text=[Negative]>, <xref:Metalama.Patterns.Contracts.GreaterThanAttribute?text=[GreaterThan]>, and <xref:Metalama.Patterns.Contracts.LessThanAttribute?text=[LessThan]> contracts exist for backward compatibility. Contrary to the usual meaning of their names, they enforce a _non-strict_ inequality: for instance, `[Positive]` accepts zero.

Metalama reports LAMA5007 on each use of these contracts, unless the <xref:Metalama.Patterns.Contracts.ContractOptions.DefaultInequalityStrictness> option specifies how to interpret them. The message gives the current interpretation and names the two unambiguous contracts that can replace the attribute. The contract still works: Metalama generates the non-strict check.

In the following example, `[Positive]` is applied to a `Price` property, so a price of zero is accepted, which may not be the intent.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA5007/LAMA5007_Error.cs name="Warning"]

## Resolution

Do one of the following:

* Replace the attribute with the unambiguous contract that matches your intent. For `[Positive]`, use <xref:Metalama.Patterns.Contracts.StrictlyPositiveAttribute?text=[StrictlyPositive]> to reject zero, or <xref:Metalama.Patterns.Contracts.NonNegativeAttribute?text=[NonNegative]> to keep the current behavior. The following example uses `[StrictlyPositive]`.
* Keep the attributes and set the `DefaultInequalityStrictness` option for the whole project or namespace using the <xref:Metalama.Patterns.Contracts.ContractConfigurationExtensions.ConfigureContracts*> extension method in a fabric. This option decides how all ambiguous contracts in its scope are interpreted.
