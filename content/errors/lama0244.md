# LAMA0244: The type and its base type have incompatible scopes

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Execution scope mismatch: the type '<Type>' is <Scope>, but its base type or interface '<BaseType>' is <BaseScope>.` |

## Cause

Metalama assigns an execution scope to every type. A _compile-time_ type, such as a class marked with <xref:Metalama.Framework.Aspects.CompileTimeAttribute>, exists only while Metalama compiles the project. A _run-time_ type, such as an ordinary class or interface of your project, exists only in the compiled program. Types marked with <xref:Metalama.Framework.Aspects.RunTimeOrCompileTimeAttribute>, and many system types like `IDisposable`, exist in both.

A type can't derive from, or implement, a type that doesn't exist in its own scope. Metalama reports LAMA0244 on the base list of a type when one of its base types or interfaces has an incompatible scope, for instance:

* a compile-time class that derives from a run-time class or implements a run-time interface;
* a run-time class that derives from a compile-time-only class.

The message gives the scope of the type and the scope of the offending base type or interface.

In the following example, the compile-time class `UpperCaseNameFormatter`, used by the `Log` aspect, implements the interface `INameFormatter`, which is a run-time interface because it has no scope attribute.

## Resolution

Make the scopes compatible:

* If the base type or interface only uses types that are available at compile time, mark it with `[RunTimeOrCompileTime]`, as in the following example, so that both run-time and compile-time types can use it.
* Otherwise, remove the base type or interface from the compile-time type, or split the type into a run-time type and a compile-time type.
