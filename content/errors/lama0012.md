# LAMA0012: The invoked member receives the wrong number of arguments

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The member '<Member>' requires <RequiredArgumentsCount> argument(s), but the invocation passes <ActualArgumentsCount>.` |

## Cause

In a template, you can generate a call to a method, a constructor, or an event that you only know as a compile-time declaration, such as an `IMethod`, by calling the `Invoke` method of its invoker. The C# compiler can't check the arguments of this call, because it doesn't know the signature of the target member when it compiles the aspect. Metalama checks them when it executes the template.

Metalama reports LAMA0012 when the number of arguments passed to `Invoke` is different from the number of parameters of the invoked member, and the member has no `params` parameter. Optional parameters aren't taken into account: you must pass a value for each parameter. In the message, `<Member>` is the invoked member, `<RequiredArgumentsCount>` is the number of its parameters, and `<ActualArgumentsCount>` is the number of arguments passed to `Invoke`. The diagnostic is reported on the declaration to which the aspect is applied.

When the member has a `params` parameter and receives too few arguments, Metalama reports <xref:lama0013> instead.

In the following example, the `Audit` aspect calls the `WriteAudit` method of the target type, which has two parameters, with a single argument.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0012/LAMA0012_Error.cs name="Error"]

## Resolution

Pass exactly one argument for each parameter of the invoked member, in the order of the parameters. If your aspect must work with members of several signatures, examine the `Parameters` collection of the member before invoking it, and build the arguments accordingly, or report a diagnostic when the signature isn't supported.
