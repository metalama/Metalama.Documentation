# LAMA0251: A dynamic variable must be initialized with a dynamic expression

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The variable '<Variable>' is declared as 'dynamic', so it must be initialized with an expression of type 'dynamic'. Declare the variable with 'var' or with a non-dynamic type.` |

## Cause

In a T# template, `dynamic` stands for a run-time type that's only known when Metalama expands the template. Metalama infers the actual type of a `dynamic` local variable from its initializer, which must itself be a `dynamic` expression, for instance `meta.Proceed()`, the `Value` property of a parameter, or `meta.Default( type )`.

Metalama reports LAMA0251 when a template declares a local variable of type `dynamic` and initializes it with an expression of another type, for instance a literal, a compile-time value such as `meta.Target.Method.Name`, or an expression cast to a non-dynamic type. It's also reported when a `foreach` statement declares its iteration variable as `dynamic` but iterates over a collection that isn't `dynamic`, such as `meta.Target.Parameters`. The placeholder of the message is the name of the variable.

In the following example, the aspect declares `methodName` as `dynamic`, but initializes it with the name of the target method, which is a compile-time `string`.

## Resolution

Declare the variable with `var` or with its actual type instead of `dynamic`. When the initializer is a compile-time value, the variable becomes a compile-time variable, and Metalama inserts its value in the generated code, as shown in the following example.

If you need a run-time variable of a type that's only known at compile time, initialize it with a `dynamic` expression. In a `foreach` statement over a compile-time collection, declare the iteration variable with `var`.
