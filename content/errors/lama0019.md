# LAMA0019: An expression passed to an out or ref parameter isn't a variable

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot pass the expression '<Expression>' to the 'out' or 'ref' parameter '<ParameterName>' of method '<Method>' because the expression is not a variable.` |

## Cause

In C#, you can only pass a _variable_ to an `out` or `ref` parameter: a local variable, a parameter, a field, or an array element. Properties, indexers, and the results of method calls aren't variables.

When you generate a call with <xref:Metalama.Framework.Code.Invokers.IMethodInvoker.Invoke*>, Metalama adds the `out` or `ref` modifier to the arguments of such parameters. It reports LAMA0019 when it knows that the expression passed to one of these parameters isn't a variable, typically because the expression is the value of a property or the result of another invocation. In the message, `<Expression>` is the generated expression, `<ParameterName>` is the name of the parameter, and `<Method>` is the invoked method. When Metalama can't determine whether the expression is a variable, it doesn't report the error and generates the code as is.

In the following example, the `ParseInto` aspect passes the member named in its argument to the `out` parameter of `int.TryParse`. The target code names the `MaxAttempts` property.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0019/LAMA0019_Error.cs name="Error"]

## Resolution

Pass a variable to the `out` or `ref` parameter:

* Pass a field instead of a property, as in the following example.
* Declare a local variable in the template, pass it to the parameter, then assign its value to the property.
* If you create the expression with `ExpressionFactory.Parse` and you know that it's a variable, set the `isReferenceable` parameter to `true`.
