# LAMA0241: An expression mixes compile-time and run-time sub-expressions

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Execution scope mismatch in the expression '<ParentExpression>': the sub-expression '<SubExpression>' is <SubExpressionScope>, but the other sub-expression '<OtherSubExpression>' is <OtherSubExpressionScope>.` |

## Cause

In a T# template, Metalama classifies every expression as either compile-time, which it evaluates while generating the code, or run-time, which it copies into the generated code. A sub-expression whose value is a compile-time object, such as an `IProperty` or an `IMethod`, can't become part of the generated code. A sub-expression whose value is run-time, such as `meta.Proceed()` or the `Value` of a declaration, can't be evaluated at compile time.

Metalama reports LAMA0241 when an expression combines two such sub-expressions, so that it can be neither compile-time nor run-time. The message gives the two sub-expressions and their scopes. This typically happens in a condition that joins a compile-time test and a run-time test with `&&` or `||`, in an array initializer, or in a cast of a compile-time value to a run-time type.

## Resolution

Split the expression so that each part is entirely compile-time or entirely run-time. For a condition, test the compile-time part in a compile-time `if` statement and, inside it, test the run-time part in a run-time expression or `if` statement. The following example uses this fix.
