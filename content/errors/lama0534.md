# LAMA0534: A field can't be introduced into an interface

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce the field '<Member>' into interface type '<TargetType>'.` |

## Cause

Interfaces describe a contract and don't hold instance state, so Metalama doesn't allow aspects to introduce fields into them. Metalama reports LAMA0534 when the target type of a field introduction is an interface, whether the field comes from a template marked with the <xref:Metalama.Framework.Aspects.IntroduceAttribute?text=[Introduce]> attribute or from the <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceField*> method. The target can be an interface of your source code or an interface introduced by the aspect itself.

In the following example, the `Versioned` aspect introduces a `_version` field, but it's applied to an interface.

## Resolution

Do one of the following:

* Apply the aspect to the classes or structs that implement the interface instead of the interface itself. The following example shows this fix.
* If the interface must expose the value, introduce a property into the interface instead of a field.
* If you're the author of the aspect, prevent it from being applied to interfaces by adding an eligibility condition in its `BuildEligibility` method.
