# LAMA0287: A template can't get the receiver of a member that has none

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot get a receiver in an advice applied to <TargetKind> '<TargetDeclaration>' because <Explanation>.` |

## Cause

In a template, `meta.Receiver` represents the object on which the target member is invoked: `this` in an instance member, or the receiver parameter in an extension member or a classic extension method. `ExpressionFactory.Receiver` returns the same expression as an `IExpression`.

A static member that isn't an extension method has no receiver. Metalama reports LAMA0287 when it expands a template that needs the receiver while the advice is applied to such a member, for instance a static method. The last part of the message explains why no receiver is available. Metalama detects the problem only when it expands the template for a given target, so the same aspect works on instance members and fails on static ones.

In the following example, the `Trace` aspect prints `meta.Receiver`. It works on the instance method `Add`, but fails on the static method `Multiply`.

## Resolution

Depending on your intent, do one of the following:

* Make the template handle members without a receiver: call the `HasReceiver` extension method on the target member in a compile-time `if` statement, and use `meta.Receiver` only in the branch where it returns `true`. The following example uses this approach.
* If the aspect can't work without a receiver, add an eligibility condition to the aspect's `BuildEligibility` method, for instance `MustNotBeStatic`. Metalama then reports that the aspect isn't eligible on static members, and fabrics can skip them.
* Remove the aspect from the static member.
