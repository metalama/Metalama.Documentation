# LAMA5165: A computed property uses a local variable of a mutable type

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Patterns.Observability |
| **Message** | `Local variables of type '<Type>' cannot be observed: only local variables of immutable types, such as primitive types, are supported.` |

## Cause

The <xref:Metalama.Patterns.Observability.ObservableAttribute?text=[Observable]> aspect analyzes the getter of each computed property to find the fields and properties it depends on, including properties of child objects such as `this.Address.City`. It follows these member accesses only when they start from a member of the current object. It doesn't follow an object stored in a local variable.

Metalama reports LAMA5165 when the getter declares a local variable whose type isn't immutable. Because the variable can reference a mutable object, changes to this object's properties aren't tracked, and the computed property isn't notified. Variables of immutable types, such as `int`, `string`, or types marked as immutable, are supported. In the message, `<Type>` is the type of the variable.

In the following example, the getter of `DeliveryCity` stores an `Address` in a local variable and reads its `City` property.

## Resolution

Do one of the following:

* Remove the local variable and access the members through the properties of the current object, as in the following example.
* If the type of the variable is immutable but Metalama doesn't know it, mark it as immutable. For details, see <xref:immutability>.
