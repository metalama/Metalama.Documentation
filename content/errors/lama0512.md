# LAMA0512: The type already implements the interface

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot implement interface '<InterfaceType>' in the type '<TargetType>' because the type already implements it. To skip or override the existing implementation, set the whenExists parameter of ImplementInterface to OverrideStrategy.Ignore or OverrideStrategy.Override.` |

## Cause

The <xref:Metalama.Framework.Aspects.AdviserExtensions.ImplementInterface*> method has a `whenExists` parameter of type <xref:Metalama.Framework.Aspects.OverrideStrategy>, which decides what happens when the target type already implements the interface. Its default value is `OverrideStrategy.Fail`.

Metalama reports LAMA0512 when the strategy is `OverrideStrategy.Fail`, explicitly or by default, and the target type already implements the interface, either in its own code or through a base type. The check also covers the base interfaces of the implemented interface, so `<InterfaceType>` can be one of them.

In the following example, the `Describable` aspect implements `IDescribable` with the default strategy, but `Product` already implements this interface.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0512/LAMA0512_Error.cs name="Error"]

## Resolution

Pass a `whenExists` value that matches your intent:

* `OverrideStrategy.Ignore` skips the types that already implement the interface. The members marked with `[InterfaceMember]` aren't introduced into these types. This is the most common choice.
* `OverrideStrategy.Override` implements the interface members with the aspect's templates even if the type already implements the interface.

Alternatively, don't apply the aspect to types that already implement the interface.

In the following example, the aspect passes `OverrideStrategy.Ignore`: `Product` keeps its own implementation, and `Customer` receives the implementation of the aspect.
