# LAMA0260: A type fabric can't be nested in a compile-time type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The type fabric '<Fabric>' cannot be nested in a compile-time type.` |

## Cause

A type fabric is a class derived from <xref:Metalama.Framework.Fabrics.TypeFabric> and nested in the type that it amends. Fabrics add aspects and advice to run-time code, so the containing type must be a run-time type.

Metalama reports LAMA0260 when a type fabric is nested in a type whose scope is compile-time, that is, a type marked with <xref:Metalama.Framework.Aspects.CompileTimeAttribute> or <xref:Metalama.Framework.Aspects.RunTimeOrCompileTimeAttribute>, or a type that's compile-time for another reason, such as an aspect class.

In the following example, `PriceCalculator` is marked with `[RunTimeOrCompileTime]` and contains a type fabric that adds a logging aspect to its methods.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0260/LAMA0260_Error.cs name="Error"]

## Resolution

Do one of the following:

* If the type doesn't need to be used at compile time, remove the `[CompileTime]` or `[RunTimeOrCompileTime]` attribute so that the type becomes a run-time type, as in the following example.
* If the type must stay compile-time, remove the type fabric: a fabric can't amend compile-time code.
