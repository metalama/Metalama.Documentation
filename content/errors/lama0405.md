# LAMA0405: Metalama can't set a property of the custom attribute

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot instantiate a custom attribute: the property '<Property>' has no setter.` |

## Cause

When an aspect, or another compile-time attribute, is applied with a custom attribute, Metalama instantiates the attribute class at compile time: it calls the constructor, then sets the properties and fields assigned with named arguments, as in `[Log( Category = "Billing" )]`. It finds the properties of the attribute class with reflection.

Metalama reports LAMA0405 when it finds the property named `<Property>` by reflection but can't find any setter for it, public or not.

The C# compiler already rejects a named argument for a property without a setter, so this diagnostic isn't expected in normal code. The known case is a limitation of Metalama: the attribute class _overrides_ a virtual read-write property of its base class with only a getter. C# accepts the named argument because the setter is inherited from the base class, but the property found by reflection on the derived class has no setter, so Metalama can't assign it.

This situation is caused by a limitation of Metalama, so the article has no example.

## Resolution

* In the derived attribute class, override both accessors of the property. The overridden setter can just call `base` to keep the behavior of the base class.
* Alternatively, don't override the property: keep its logic in the base class, or read its value in a separate member.
