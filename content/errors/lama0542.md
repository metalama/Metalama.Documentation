# LAMA0542: An extension block can't contain an indexer with an init accessor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<Aspect>' cannot introduce indexer '<Indexer>' into '<ExtensionBlock>' because the indexer has an 'init' accessor, which the language forbids for an extension member.` |

## Cause

An extension block adds members to an existing type without changing that type. The C# language doesn't allow an `init` accessor in a member of an extension block, because such an accessor is meant to run while an object is being initialized, and an extension block doesn't take part in the construction of the extended type.

Metalama reports LAMA0542 when an aspect calls <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceIndexer*> on an extension block and makes the indexer init-only, for instance by setting its <xref:Metalama.Framework.Code.Writeability?text=Writeability> to `InitOnly`.

In the following example, the aspect introduces an init-only indexer into the extension block of the `IntExtensions` class.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0542/LAMA0542_Error.cs name="Error"]

## Resolution

Introduce the indexer with a regular set accessor, or without a set accessor if the indexer is read-only. In the following example, the aspect no longer makes the indexer init-only.
