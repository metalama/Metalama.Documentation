# LAMA0508: An introduced member can't be both static and sealed

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce sealed member '<Member>' because it is also static.` |

## Cause

In C#, the `sealed` modifier on a member prevents derived classes from overriding it further. It only makes sense on an instance member that overrides a virtual member. A static member can't be overridden, so it can't be sealed. Metalama reports LAMA0508 when an aspect introduces a member that is both static and sealed.

The introduced member is static when the introduction scope is <xref:Metalama.Framework.Aspects.IntroductionScope.Static?displayProperty=nameWithType>, or when the scope is the default one and the template is static. It's sealed when the <xref:Metalama.Framework.Aspects.IntroduceAttribute.IsSealed> property of the custom attribute is set, or when the build action sets the <xref:Metalama.Framework.Code.DeclarationBuilders.IMemberOrNamedTypeBuilder.IsSealed> property.

In the following example, the `Describe` aspect introduces the `GetTypeDescription` method from a static template, and its build action marks the method as sealed.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0508/LAMA0508_Error.cs name="Error"]

## Resolution

Decide whether the introduced member must be static or sealed:

* If the member must be static, don't set `IsSealed` in the custom attribute or in the build action. This is the fix shown in the example below.
* If the member overrides a virtual member of a base class and you want to prevent further overrides, introduce it as an instance member: use a non-static template, or pass <xref:Metalama.Framework.Aspects.IntroductionScope.Instance?displayProperty=nameWithType> as the scope.
