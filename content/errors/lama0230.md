# LAMA0230: A compile-time class nested in a run-time type must be private

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The compile-time type '<Type>' must be private because it is nested in a run-time type.` |

## Cause

A type fabric is a compile-time class nested in the type that it amends. Because the containing type is run-time only, Metalama moves the nested fabric out of it in the compile-time assembly. The fabric must be invisible to the run-time code so that nothing at run time can reference it.

Metalama reports LAMA0230 when a compile-time class nested in a run-time type has any accessibility other than `private`, for instance `public` or `internal`.

In the following example, the type fabric of `OrderService` is `public`.

## Resolution

Make the nested class `private`, as in the following example.

If the class isn't a type fabric, making it private isn't enough, because only type fabrics can be nested in a run-time type (see <xref:lama0231>). Move it out of the containing type instead.
