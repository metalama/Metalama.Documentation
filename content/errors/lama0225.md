# LAMA0225: A dynamic local variable can't be initialized with null or default

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The 'dynamic' keyword cannot be used in the local variable '<Variable>' because it is initialized with a target-typed expression (such as 'default' or 'null'). Initialize the variable with an expression of type 'dynamic', for example 'meta.Default( type )'.` |

## Cause

In a T# template, `dynamic` stands for a run-time type that's only known when Metalama expands the template. Metalama infers the actual type of a `dynamic` local variable from its initializer. A _target-typed_ expression has no type of its own: it takes the type of its destination, so it can't give a type to the variable.

Metalama reports LAMA0225 when a template initializes a local variable of type `dynamic` (or `dynamic?`) with a target-typed expression: the `null` or `default` literal, a `throw` expression, or a `stackalloc` expression, possibly in parentheses. The placeholder of the message is the name of the variable.

In the following example, the aspect returns the default value of the return type when the method throws an exception, and the template initializes `result` with `null`.

## Resolution

Initialize the variable with an expression of type `dynamic`. To get the default value of the return type of the target method, use `meta.Default( meta.Target.Method.ReturnType )`, as shown in the following example.

Casting the initializer doesn't help: a cast to `dynamic` isn't allowed in templates, and a cast to another type doesn't produce a `dynamic` expression. If you know the type of the variable, declare it with this type instead of `dynamic`.
