# LAMA0245: A symbol combines run-time and compile-time elements

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `'<Declaration>' is invalid because it combines run-time and compile-time elements.` |

## Cause

Metalama assigns an execution scope, compile-time or run-time, to every symbol used in a template or in compile-time code. The scope of a generic method or type instance depends on the scopes of its type arguments. When these scopes are incompatible, the symbol has no valid scope.

Usually, Metalama can name the run-time element and the compile-time element that conflict, and reports <xref:lama0226>. LAMA0245 is the fallback when Metalama can't identify the two elements. The placeholder of the message is the invalid symbol.

A known case is a call to `meta.CompileTime` with a value whose type is a compile-time type parameter of a template. Such a type parameter stands for a type of the target code, so a value of this type, like `default(T)`, is a run-time value, while `meta.CompileTime` is a compile-time method. In the following example, the introduced method tries to print the default value of its type parameter at compile time.

## Resolution

Decide whether the expression must be evaluated at compile time or at run time, and remove the elements of the other scope:

* If the value belongs to the target code, as with `default(T)`, use it in run-time code, without `meta.CompileTime`, as in the following example. Metalama replaces `T` with the actual type in the generated code.
* If you need a compile-time value, compute it from compile-time information, like the `IType` of the target declaration, instead of a run-time type.
