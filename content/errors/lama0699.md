# LAMA0699: The implementation of a constructor or indexer can't be inlined

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The implementation of '<TargetDeclaration>' provided by '<AspectType>' cannot be inlined, but Metalama can only generate inlined code for constructors and indexers. Call meta.Proceed() at most once in the template, in a simple statement such as 'meta.Proceed();' or 'return meta.Proceed();'.` |

## Cause

When an aspect overrides a member, <xref:Metalama.Framework.Aspects.meta.Proceed?text=meta.Proceed> stands for the previous implementation of the member: the source code or the override of a previous aspect. Metalama prefers to _inline_ this implementation, that is, to copy its code in place of the `meta.Proceed()` call. When inlining isn't possible, Metalama moves the implementation to a separate, private member and calls this member instead.

Constructors and indexers can't be moved to a separate member, so their implementations must always be inlined. Metalama reports LAMA0699 when an implementation of a constructor or an indexer can't be inlined. An implementation is inlined only when the next template references it once, in a supported statement:

* For a constructor, a single `meta.Proceed();` statement.
* For an indexer accessor, a single `meta.Proceed()` call in a statement such as `return meta.Proceed();`, `var value = meta.Proceed();`, or `meta.Proceed();`.

In the message, `<TargetDeclaration>` is the overridden constructor or indexer, and `<AspectType>` is the aspect that provides the implementation that can't be inlined, or `source code` for the original implementation.

In the following example, the `LogConstructorErrors` aspect retries the constructor by calling `meta.Proceed()` a second time in a `catch` block.

## Resolution

Call `meta.Proceed()` only once in templates that override constructors or indexers, and use it in a simple statement. If you need to execute some logic several times, move it to a method, which can be called any number of times, and override this method instead.
