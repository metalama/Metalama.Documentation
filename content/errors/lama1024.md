# LAMA1024: The interceptor method can't be generated in the requested placement

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Extensions.Interceptors |
| **Message** | `The <Source> cannot generate the interceptor of the <Site> in the requested placement because <Reason>. The call site is left unchanged.` |

## Cause

An _interceptor_ redirects the calls to a method to another method that Metalama generates from a template. The aspect chooses where the generated method goes with `PlaceInCallingType`, `PlaceInType` or `PlaceInStaticClass`, and can adjust the method in the `Configure` delegate. The call site must be able to call the method at that place.

Metalama reports LAMA1024 when the generated method can't be placed as requested for a call site, and it leaves the call site unchanged. The `<Source>` placeholder describes the template and the aspect, `<Site>` the intercepted call, and `<Reason>` the cause. The most common ones are:

* The accessibility that the `Configure` delegate assigns is more restrictive than the call site needs. For instance, a private method of another type can't be called.
* The method is an instance method, but the call site has no `this` (it's in a static method or in a conditional access), or the method isn't placed in the calling type or one of its base types.
* The name given to `PlaceInStaticClass` isn't a valid full class name, or the type given to `PlaceInType` doesn't exist.
* The call site is in top-level statements, whose type can't be named, or the signature contains an anonymous type.

## Resolution

Read the reason in the message, and change the placement or the configuration of the aspect:

* Remove the accessibility assignment, or assign an accessibility that the call site can use.
* Place the method in the calling type with `PlaceInCallingType`, where a private method is enough.
* Make the method static if the call site has no `this`.
* Fix the type or class name given to `PlaceInType` or `PlaceInStaticClass`.
