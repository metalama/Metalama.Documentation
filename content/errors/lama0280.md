# LAMA0280: A compile-time expression can't be set under a run-time condition

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The compile-time expression '<Expression>' cannot be set here because the assignment is in a block whose execution depends on a run-time condition ('<RunTimeCondition>'). In such a block, only compile-time local variables declared in the block can be set.` |

## Cause

In a T# template, compile-time code runs once, while Metalama generates the target code. Run-time statements such as an `if` with a run-time condition, a `catch` or `finally` block, or a local function are only emitted into the generated code: whether their body executes is decided later, when the program runs. When Metalama expands the template, it always walks through such a block, so it can't know whether a compile-time assignment in that block should happen.

For this reason, Metalama reports LAMA0280 when, inside a run-time-conditional block, a template modifies a compile-time expression that isn't a local variable. The modification can be an assignment, a compound assignment like `+=`, an increment or decrement, or passing the expression as an `out` or `ref` argument. The expression can be, for instance, a field or property of a compile-time object, an array element, or a tuple of variables. The first placeholder of the message is the expression, and the second one describes the run-time condition. For a compile-time local variable declared outside the block, Metalama reports <xref:lama0108> instead.

In the following example, the aspect counts `null` arguments with a property of a compile-time object, but the property is incremented inside an `if` statement whose condition, `parameter.Value == null`, is a run-time expression.

## Resolution

Depending on your intent, do one of the following:

* If the value depends on run-time data, use a run-time variable: initialize a local variable with a literal, without `meta.CompileTime`. Metalama then emits the variable and its modifications into the generated code. The following example uses this fix.
* If the assignment doesn't depend on the run-time condition, move it out of the run-time-conditional block.
* If the condition can be evaluated at compile time, make it a compile-time expression, for example by testing properties of `meta.Target` instead of run-time values, so that the `if` statement becomes compile-time.
