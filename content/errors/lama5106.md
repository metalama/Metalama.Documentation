# LAMA5106: The method to invalidate doesn't exist

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Caching |
| **Message** | `Invalid [InvalidateCache] aspect on '<InvalidatingMethod>': there is no method named '<MethodName>' in type '<DeclaringType>'.` |

## Cause

The <xref:Metalama.Patterns.Caching.Aspects.InvalidateCacheAttribute?text=[InvalidateCache]> aspect looks up the cached methods by name among all methods of a type, including inherited ones. By default, this type is the type that declares the invalidating method. When you pass a type as the first argument of the constructor, the aspect searches this type instead.

Metalama reports LAMA5106 when no method of the given name exists in this type. In the message, `<InvalidatingMethod>` is the invalidating method, `<MethodName>` is the name that couldn't be found, and `<DeclaringType>` is the searched type. The typical causes are:

* a typo in a method name written as a string literal;
* a cached method that's declared in another type, while the aspect doesn't specify this type.

If a method of the given name exists but can't be invalidated, for instance because it isn't cached or because its parameters don't match, Metalama reports a different error.

In the following example, the method name is misspelled.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA5106/LAMA5106_Error.cs name="Error"]

## Resolution

* Use the `nameof` operator instead of a string literal. The C# compiler then checks that the method exists.
* If the cached method belongs to another type, pass this type as the first argument of the aspect, before the method names.
