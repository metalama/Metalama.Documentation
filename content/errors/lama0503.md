# LAMA0503: The introduced member has a different type than the existing member

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce member '<Member>' into type '<TargetType>' because it is already defined in type '<DeclaringType>' and has a different type or return type '<ReturnType>'.` |

## Cause

When an aspect introduces a member that already exists in the target type or in a base type, the introduced member and the existing member must have compatible types. Metalama reports LAMA0503 in the following situations:

* A method is introduced with `OverrideStrategy.Override`, and its return type can't be converted to the return type of the existing method by a reference conversion.
* A property or an indexer is introduced, whatever the override strategy, and its type can't be converted to the type of the existing member by a reference conversion.
* An event is introduced, whatever the override strategy, and its type isn't identical to the type of the existing event.

In the message, `<DeclaringType>` is the type that defines the existing member, and `<ReturnType>` is the type or return type of the existing member.

In the following example, the `Versioned` aspect overrides the `GetVersion` method of the base class `Document`. The template returns `int`, but the base method returns `long`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0503/LAMA0503_Error.cs name="Error"]

## Resolution

Depending on your intent, do one of the following:

* Change the type or return type of the template so that it matches the existing member.
* If the existing member isn't meant to be overridden, rename the introduced member or the existing member to remove the conflict.
