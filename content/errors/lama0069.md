# LAMA0069: A diagnostic can be reported or suppressed only inside the type or namespace of the aspect or fabric

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The <AspectOrFabric> cannot report or suppress a diagnostic on '<Declaration>' because it is not contained in '<Container>'.` |

## Cause

Aspects and fabrics can report or suppress diagnostics on several declarations at once by calling the `ReportDiagnostic` or `SuppressDiagnostic` extension methods on a query, for instance one built with `SelectMany`. However, the scope of these declarations is limited:

* An aspect or a type fabric can report or suppress diagnostics only on its target type and on the declarations contained in this type, such as its members and nested types. For an aspect applied to a member, the scope is the declaring type of the member.
* A namespace fabric can report or suppress diagnostics only on declarations contained in its namespace.
* A project fabric can report or suppress diagnostics on any declaration of the current project.

Except for project fabrics, the declaration must also belong to the current project, not to a referenced assembly.

Metalama reports LAMA0069 when the query selects a declaration outside of this scope. In the message, `<AspectOrFabric>` describes the aspect or fabric, `<Declaration>` is the selected declaration, and `<Container>` is the type or namespace in which the declaration should be contained.

In the following example, a type fabric of `OrderService` tries to report a warning on the methods of the base class, `ServiceBase`.

## Resolution

Report or suppress the diagnostic from a place whose scope contains the target declaration:

* Move the type fabric to the type that declares the target declarations, as in the following example.
* Use a project fabric, which can report diagnostics on any declaration of the project.
* To report diagnostics on the classes derived from a type, use an inherited aspect instead of selecting the derived types.
