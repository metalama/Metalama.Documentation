# LAMA0210: Metalama can't generate a serializer for a positional record

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot generate a compile-time serializer for '<Type>' because generated serializers are not currently supported for a positional record class or struct. You can provide a manual serializer (public nested class) derived from ReferenceTypeSerializer (record classes) or ValueTypeSerializer (record structs) instead.` |

## Cause

Metalama serializes aspects, fabrics, and other types implementing <xref:Metalama.Framework.Serialization.ICompileTimeSerializable> when they have cross-project effects. By default, it generates a serializer for each of these types, unless the type declares its own nested serializer.

Metalama can't generate a serializer for a _positional record_, that is, a `record`, `record class`, or `record struct` declared with a parameter list. Metalama reports LAMA0210 when a positional record implements `ICompileTimeSerializable`, directly or through a base type, and doesn't declare a manual serializer. In the message, `<Type>` is the record.

In the following example, the `RetryPolicy` positional record implements `ICompileTimeSerializable` so that the `Retry` aspect can store it in a property.

## Resolution

Do one of the following:

* Add a nested serializer class to the record: derive it from <xref:Metalama.Framework.Serialization.ReferenceTypeSerializer`1> for a record class or from <xref:Metalama.Framework.Serialization.ValueTypeSerializer`1> for a record struct. The following example shows this fix.
* Declare the record without a parameter list, with ordinary properties instead of positional parameters. Metalama can generate serializers for such records.
