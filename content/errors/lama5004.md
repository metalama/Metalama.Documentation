# LAMA5004: Invariant suspension isn't enabled for the type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Contracts |
| **Message** | `The [SuspendInvariantsAttribute] aspect cannot be applied to the method '<Method>' because the IsInvariantSuspensionSupported contract option is not enabled for the type '<Type>'. Enable this option in ContractOptions using a fabric.` |

## Cause

The <xref:Metalama.Patterns.Contracts.SuspendInvariantsAttribute> aspect suspends the verification of invariants while a method executes. Suspending invariants requires additional generated code in the type, so this feature is disabled by default and must be enabled with the <xref:Metalama.Patterns.Contracts.ContractOptions.IsInvariantSuspensionSupported> option.

Metalama reports LAMA5004 when you apply `[SuspendInvariants]` to a method, but the option isn't enabled for the declaring type of the method. If invariants are disabled for the type with the <xref:Metalama.Patterns.Contracts.ContractOptions.AreInvariantsEnabled> option, the aspect is silently skipped instead.

In the following example, the `Update` method has the `[SuspendInvariants]` aspect, but no fabric enables invariant suspension.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA5004/LAMA5004_Error.cs name="Error"]

## Resolution

Set the <xref:Metalama.Patterns.Contracts.ContractOptions.IsInvariantSuspensionSupported> option to `true` from a fabric, for the whole project as in the following example, or for a namespace or a type. See <xref:configuring-contracts> for details. Alternatively, remove the `[SuspendInvariants]` aspect if the method doesn't need to break invariants temporarily.
