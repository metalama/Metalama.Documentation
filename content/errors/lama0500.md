# LAMA0500: The introduced member already exists

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce member '<Member>' into type '<TargetType>' because it is already defined in type '<DeclaringType>'. Use a different OverrideStrategy or skip the member.` |

## Cause

When an aspect introduces a member, such as a method, property, field, event, indexer, constructor or finalizer, Metalama first checks whether the target type, or one of its visible base types, already defines a member with the same name, or the same signature for methods. What happens then depends on the <xref:Metalama.Framework.Aspects.OverrideStrategy> of the advice. The default strategy, `Fail`, reports LAMA0500 and doesn't introduce the member.

In the message, `<Member>` is the member that the aspect tries to introduce, `<TargetType>` is the target type, and `<DeclaringType>` is the type that already defines the member: the target type itself or one of its base types.

## Resolution

Decide what should happen when the member already exists, and specify the override strategy. For declarative advice, set the <xref:Metalama.Framework.Aspects.IntroduceAttribute.WhenExists> property of the `[Introduce]` attribute. For programmatic advice, pass the `whenExists` parameter of the advice method.

* `OverrideStrategy.Override` overrides the existing member. If it's defined in the target type, the template replaces its implementation and can call the original implementation with `meta.Proceed()`. If it's defined in a base type, it must be `virtual` or `abstract`, and the aspect introduces an `override` member.
* `OverrideStrategy.Ignore` keeps the existing member and skips the introduction.
* `OverrideStrategy.New` introduces a member with the `new` modifier. It's only possible when the existing member is defined in a base type.

Alternatively, rename the introduced member or the existing member to remove the conflict.
