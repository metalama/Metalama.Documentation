# LAMA0022: A child aspect must be processed after its parent aspect

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<ParentType>' cannot add a child aspect of type '<ChildType>' because the '<ChildType>' aspect is processed before '<ParentType>'. Use the [AspectOrder] assembly attribute to process '<ParentType>' before '<ChildType>'.` |

## Cause

Metalama processes aspect classes one after the other, in the order defined by the <xref:Metalama.Framework.Aspects.AspectOrderAttribute> assembly-level attributes. When an aspect adds a _child aspect_, for instance with `builder.Outbound.AddAspect`, Metalama can apply the child aspect only if its aspect class hasn't been processed yet. That's why the child aspect class must be processed _after_ the parent aspect class.

Metalama reports LAMA0022 when the parent aspect, `<ParentType>` in the message, adds an aspect of a class, `<ChildType>`, that's processed before it. The error is reported on the parent aspect class.

In the following example, the `LogAllMethods` aspect adds a `Log` aspect to each method of the type, but the `AspectOrder` attribute processes `Log` before `LogAllMethods` at compile time.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0022/LAMA0022_Error.cs name="Error"]

## Resolution

Change the `AspectOrder` attribute so that the parent aspect class is processed before the child aspect class:

* With `AspectOrderDirection.CompileTime`, list the parent aspect class _before_ the child aspect class.
* With `AspectOrderDirection.RunTime`, which is the default direction, list the child aspect class _before_ the parent aspect class.
