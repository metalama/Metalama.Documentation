# LAMA1016: The template can't implement the interceptor method

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Extensions.Interceptors |
| **Message** | `The template '<Template>' cannot implement the interceptor method for the <Site> because <Reason>. The call site is left unchanged.` |

## Cause

An _interceptor_ redirects the calls to a method to another method that Metalama generates, typically from an aspect template that you select with `RedirectToSynthesizedMethod`. Metalama derives the signature of the generated method from the intercepted method, and the `Configure` delegate can adjust it, for instance by adding a parameter.

Metalama reports LAMA1016 when it can't build the generated method from the template, and it leaves the call site unchanged. The `<Reason>` placeholder gives the cause. The most common ones are:

* An added parameter has no value: the `Configure` delegate called `AddParameter`, but `WithArgs` has no property with the same name and `SetArgument` wasn't called for it.
* The value of an added parameter can't be written as a constant, for instance a `DateTime`.
* An added parameter has the name of a parameter of the intercepted method, or isn't passed by value.
* A property of `WithArgs` is neither a parameter of the template nor an added parameter.
* The template has a run-time parameter that the intercepted method doesn't have and that `WithArgs` doesn't provide, or the template provider has no template with the requested name.

## Resolution

Read the reason in the message, and change the aspect so that the template and the generated method agree:

* Give a value to every added parameter, either with a property of `WithArgs` that has the same name or with `SetArgument`. The value must be a constant.
* Rename the added parameter if it conflicts with a parameter of the intercepted method.
* Remove the `WithArgs` properties that match no parameter, and declare in the template every run-time parameter it needs.
