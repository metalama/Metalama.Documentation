# LAMA0533: An abstract member can't be introduced with the Override or New strategy

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce the abstract member '<Member>' with the override strategy '<OverrideStrategy>' because an introduced abstract member cannot override or hide an existing member. Use the override strategy 'Fail' or 'Ignore'.` |

## Cause

When an aspect introduces a member into an abstract class, the introduced member is abstract if its template has no body (an `extern` template) or if the template sets the <xref:Metalama.Framework.Aspects.TemplateAttribute.IsAbstract> property.

The `whenExists` argument of methods like <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceMethod*> sets the <xref:Metalama.Framework.Aspects.OverrideStrategy>, which decides what happens when the target type or one of its base types already has a member with the same signature. The `Override` strategy replaces the implementation of the existing member, and the `New` strategy hides it. Neither strategy makes sense for an abstract member, which has no implementation. Metalama reports LAMA0533 when it introduces an abstract member with either strategy, even if no member with the same signature exists.

In the following example, the `Validatable` aspect introduces an abstract `Validate` method with `OverrideStrategy.Override`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0533/LAMA0533_Error.cs name="Error"]

## Resolution

Do one of the following:

* Use the `Fail` strategy, which is the default, so you can omit the `whenExists` argument, or the `Ignore` strategy, which keeps the existing member. The following example uses `Ignore`.
* If the introduced member must override an existing member, give the template a body so that the introduced member isn't abstract.
