# LAMA5204: A member found by the naming convention has an invalid signature

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Wpf |
| **Message** | `The '<Member>' <Kind> has an invalid signature and cannot be used as a <Role> for <TargetDescription>'<Target>' <AsRequired>by the '<NamingConvention>' naming convention.<InvalidityReason>` |

## Cause

The WPF aspects find helper members by name:

* The <xref:Metalama.Patterns.Wpf.CommandAttribute?text=[Command]> aspect looks for a can-execute method or property. For a command named `Save`, the default names are `CanExecuteSave`, `CanSave`, and `IsSaveEnabled`. You can also set the name with <xref:Metalama.Patterns.Wpf.CommandAttribute.CanExecuteMethod> or <xref:Metalama.Patterns.Wpf.CommandAttribute.CanExecuteProperty>.
* The <xref:Metalama.Patterns.Wpf.DependencyPropertyAttribute?text=[DependencyProperty]> aspect looks for a property-changed method and a validate method. For a property named `Foo`, the default names are `OnFooChanged` and `ValidateFoo`. You can also set the names with <xref:Metalama.Patterns.Wpf.DependencyPropertyAttribute.PropertyChangedMethod> and <xref:Metalama.Patterns.Wpf.DependencyPropertyAttribute.ValidateMethod>.

Metalama reports LAMA5204 on a member that has the expected name but a signature the aspect can't use, when no other member with a valid signature is found for the same role. The aspect isn't applied to the target. The signature rules are:

* A can-execute method must return `bool`, must not be generic, and must have no parameter or one parameter passed by value or `in`.
* A can-execute property must be of type `bool` and have a getter.
* A property-changed method must return `void` and use one of the signatures listed in <xref:wpf-dependency-property>, for example no parameter, the new value, or the old and new values.
* A validate method must return `void` and use one of the signatures listed in <xref:wpf-dependency-property>, for example `ValidateFoo( int value )`.

In the message, `<Member>` and `<Kind>` are the invalid member and its kind, `<Role>` is the role, such as `can-execute property` or `property-changed method`, `<Target>` is the aspect's target, `<NamingConvention>` is the naming convention, and `<InvalidityReason>` explains the signature rule. `<AsRequired>` is `as required` when the member is required, for example because its name was set explicitly in the attribute.

## Resolution

* Fix the signature of the member so that it follows the rules above, for example change the return type of `CanSave` to `bool`.
* If the member isn't meant to be a helper of the aspect, rename it so that it no longer matches the naming convention.
* If you set the member name explicitly in the attribute, check that it names the right member.
