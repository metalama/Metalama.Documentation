# LAMA0203: The equality comparer of the dictionary isn't supported

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot serialize the compile-time dictionary to a run-time value because it has an unsupported equality comparer '<Comparer>'. Only the default comparer and, for string keys, the predefined StringComparer comparers such as StringComparer.OrdinalIgnoreCase are supported.` |

## Cause

When a template uses a compile-time `Dictionary<TKey, TValue>` in a run-time context, Metalama generates code that creates a new dictionary with the same items. To make the run-time dictionary behave like the compile-time one, the generated code must also pass the same equality comparer to the constructor of the dictionary. Metalama can only generate this code for the following comparers:

* the default comparer of the key type;
* for `string` keys, the static instances of `StringComparer`: `Ordinal`, `OrdinalIgnoreCase`, `InvariantCulture`, `InvariantCultureIgnoreCase`, `CurrentCulture`, and `CurrentCultureIgnoreCase`.

Metalama reports LAMA0203 when it expands the template and the dictionary uses any other comparer, for instance an instance of your own class implementing `IEqualityComparer<T>`, or a comparer created by `StringComparer.Create`. The error is reported on the target declaration of the aspect. In the message, `<Comparer>` is the type of the comparer.

## Resolution

Do one of the following:

* Use the default comparer or one of the predefined `StringComparer` instances. In the following example, the custom comparer is replaced by `StringComparer.OrdinalIgnoreCase`, which has the same behavior.
* If you need a custom comparer, write the creation of the dictionary in the run-time code of the template, passing your comparer to the constructor, and add the items one by one.
