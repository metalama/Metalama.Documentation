# LAMA0530: A constructor parameter with the same name was already introduced

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce the parameter '<Parameter>' into '<TargetDeclaration>' because an aspect has already introduced a parameter named '<ExistingParameterName>' into this constructor.` |

## Cause

The <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceParameter*> method appends a parameter to a constructor. Before adding the parameter, Metalama checks whether the constructor already has a parameter with the same name:

* If this parameter is declared in source code, Metalama doesn't report an error. It introduces the new parameter under another name, for instance `p1` instead of `p`.
* If this parameter was introduced by another aspect and has a compatible type, Metalama reuses it, or replaces its type with the more specific one.
* If this parameter was introduced by the _same_ aspect instance, or by another aspect with an incompatible type, Metalama reports LAMA0530.

The most common cause is an aspect that introduces several parameters into the same constructor and computes their names in a way that isn't unique. In the message, `<TargetDeclaration>` is the constructor, shown with the parameters that were already introduced.

In the following example, the `InjectDependencies` aspect introduces one parameter for each field marked with `[Dependency]` and derives the parameter name from the field type. Both fields have the type `TextWriter`, so the aspect tries to introduce two parameters named `textWriter`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0530/LAMA0530_Error.cs name="Error"]

## Resolution

Make sure that the aspect gives a unique name to each parameter it introduces into the same constructor. For instance, derive the name from the name of the field instead of its type, as in the following example.

If two different aspects introduce a parameter with the same name, give the parameters compatible types when they represent the same dependency, so that Metalama reuses the parameter, or different names otherwise.
