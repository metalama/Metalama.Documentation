# LAMA0257: A template member can't be set from an attribute

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The template member '<Member>' cannot be set from an aspect custom attribute. Add a separate aspect property that is not a template and set this property instead.` |

## Cause

The members of an aspect class have two different roles. Regular fields and properties configure the aspect: you can set them from the custom attribute, and templates read their compile-time value. Members marked with a template attribute, such as [<xref:Metalama.Framework.Aspects.IntroduceAttribute>] or [<xref:Metalama.Framework.Aspects.TemplateAttribute>], are templates: they describe code that Metalama adds to the target, and their value is never available to the aspect.

Metalama reports LAMA0257 when a custom attribute that applies an aspect uses a named argument to set a template member.

For instance, if an aspect has a `Category` property marked with [<xref:Metalama.Framework.Aspects.IntroduceAttribute>], applying the aspect with a named argument that sets `Category` reports LAMA0257.

This diagnostic isn't shown in an example: in the current version, this scenario can make Metalama fail with an internal error while it instantiates the aspect, instead of reporting only LAMA0257 (see [#2171](https://github.com/metalama/Metalama/issues/2171)).

## Resolution

Separate the configuration from the introduced member:

1. Add a regular property, without a template attribute, to configure the aspect, and set this property from the custom attribute.
2. Read this property from the template of the introduced member, for instance in the expression body of an introduced property. Metalama replaces the reference with the compile-time value.

If you need more control, introduce the member programmatically from `BuildAspect` and pass the value as a template argument.
