# LAMA0236: Compile-time code references a run-time-only declaration

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot reference '<ReferencedSymbol>' in '<DeclaringSymbol>' because '<ReferencedSymbol>' is run-time-only but '<DeclaringSymbol>' is <DeclaringSymbolScope>. Run-time-only declarations can be referenced only in templates and in run-time code.` |

## Cause

Metalama classifies every declaration as compile-time, run-time, or run-time-or-compile-time. Compile-time code, and run-time-or-compile-time code such as aspect classes, is compiled into a separate assembly that Metalama executes during the build. This assembly doesn't contain the run-time-only types of your project, such as the classes of your application, so compile-time code can't reference them.

Metalama reports LAMA0236 when code that isn't run-time-only references a run-time-only declaration, outside of a template and outside of a `nameof` or `typeof` expression. This typically happens in the following situations:

* A non-template member of an aspect, such as a field, a property, or a helper method, uses a run-time-only type.
* A member of a class marked with <xref:Metalama.Framework.Aspects.CompileTimeAttribute> uses a run-time-only type.

In the message, `<ReferencedSymbol>` is the run-time-only declaration, `<DeclaringSymbol>` is the declaration that references it, and `<DeclaringSymbolScope>` is the scope of `<DeclaringSymbol>`. When the offending member has a run-time-only type, as a field in the example below, `<DeclaringSymbol>` is the containing type instead of the member.

## Resolution

Depending on your intent, do one of the following:

* If the run-time object belongs to the target code, introduce the member into the target type by marking it with <xref:Metalama.Framework.Aspects.IntroduceAttribute>. Introduced members are templates, so they can use run-time types. The following example uses this fix.
* If the code only needs the run-time object while the program runs, move it into a template, for instance by creating the object in the body of `OverrideMethod`.
* If the code only needs to identify the type, use `typeof` or `nameof`, which are allowed, or use the code model, for instance `meta.Target.Type`, at compile time.
* If the referenced type must be available at compile time, mark it with <xref:Metalama.Framework.Aspects.RunTimeOrCompileTimeAttribute>. This is only possible if all its dependencies are also available at compile time.
