# LAMA0045: A live template aspect must have a parameterless constructor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The class '<Type>' must be non-abstract and must have a parameterless constructor because of the [EditorExperienceAttribute(SuggestAsLiveTemplate = true)] attribute.` |

## Cause

When you set the <xref:Metalama.Framework.Aspects.EditorExperienceAttribute.SuggestAsLiveTemplate> property of the <xref:Metalama.Framework.Aspects.EditorExperienceAttribute> to `true`, the IDE offers to apply the aspect as a live template, that is, to write the aspect's output directly into the source code. To do this, Metalama must create an instance of the aspect without any argument, because there's no custom attribute from which it could read constructor arguments.

Metalama reports LAMA0045 when the aspect class can't be instantiated this way: it doesn't have a constructor without parameters, or it's abstract. The option is inherited, so the check also applies to classes derived from an aspect class that has this attribute. When the error is reported, the aspect isn't applied anywhere in the project.

In the following example, the `Log` aspect is offered as a live template, but its only constructor requires a category.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0045/LAMA0045_Error.cs name="Error"]

## Resolution

Do one of the following:

* Add a parameterless constructor to the aspect class. To keep aspect parameters, turn them into properties with default values, which users can still set with named arguments in the custom attribute. The following example shows this fix.
* If the aspect can't work without parameters, don't offer it as a live template: remove the `SuggestAsLiveTemplate = true` setting.
