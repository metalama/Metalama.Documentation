# LAMA0227: dynamic can't be used to build another type in a template

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The type '<Type>' is forbidden in a template: 'dynamic' cannot be used as a generic argument type, an array element type, a tuple element type or a ref type.` |

## Cause

In a T# template, `dynamic` stands for a run-time value or type that Metalama doesn't know when it compiles the aspect. When Metalama expands the template, it replaces each `dynamic` expression with the code of the actual expression. This works only when `dynamic` is used directly as the type of an expression, a local variable, or a template return value.

Metalama reports LAMA0227 when a template uses `dynamic` as a component of another type: as a generic argument (`List<dynamic>`), as an array element type (`dynamic[]`, `new dynamic[5]`), as a tuple element type (`(dynamic, int)`), or with `ref` (`ref dynamic`). The placeholder of the message is the offending type, as written in the template.

In the following example, the aspect copies the argument values of the target method, obtained with `meta.Target.Parameters.ToValueArray()`, into a `List<dynamic?>`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0227/LAMA0227_Error.cs name="Error"]

## Resolution

Replace `dynamic` with a type that the generated code can use:

* Use `object` or `object?` when the values only need to be stored or passed along, as in the following example. A `dynamic` expression converts implicitly to `object`.
* Use the actual type when it's known, or a generic template parameter when it depends on the target declaration.
* To pass all arguments of the target method as an array, use `meta.Target.Parameters.ToValueArray()` directly. It generates an `object[]` expression.
