# LAMA0038: A child aspect can be added only inside the parent's type or namespace

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The <Predecessor> cannot add a child aspect to '<Child>' because it is not contained in '<Parent>'.` |

## Cause

Aspects and fabrics can add _child aspects_ to other declarations, for instance by calling `AddAspect` on a query built with `SelectMany`. However, the scope in which they can add child aspects is limited:

* An aspect or a type fabric can add child aspects only to its target type and to the declarations contained in this type, such as its members and nested types. For an aspect applied to a member, the scope is the declaring type of the member.
* A namespace fabric can add child aspects only to declarations contained in its namespace.
* A project fabric can add child aspects to any declaration of the current project.

Except for project fabrics, the child declaration must also belong to the current project, not to a referenced assembly.

Metalama reports LAMA0038 when the query selects a declaration outside of this scope. In the message, `<Predecessor>` describes the aspect or fabric, `<Child>` is the selected declaration, and `<Parent>` is the type or namespace in which the declaration should be contained.

In the following example, a type fabric of `OrderService` tries to add the `Log` aspect to the methods of the base class, `ServiceBase`.

## Resolution

Add the aspect from a place whose scope contains the target declaration:

* Apply the aspect directly to the target declaration with a custom attribute, as in the following example.
* Add a type fabric to the type that contains the target declaration.
* Use a project fabric, which can add aspects to any declaration of the project.
* To add an aspect to the classes derived from a type, use aspect inheritance instead of selecting the derived types.
