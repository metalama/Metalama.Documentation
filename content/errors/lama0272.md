# LAMA0272: A void template contains a redundant return statement

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Redundant 'return' statements are not allowed in templates. Remove this 'return' statement.` |

## Cause

Metalama doesn't distinguish auxiliary templates from other templates: a `return` statement in a template always becomes a `return` statement in the generated code. When a template calls a `void` auxiliary template, a `return;` in the auxiliary template doesn't return to the calling template. It returns from the target method and skips the code that follows the call, for instance the call to `meta.Proceed()`.

To prevent this mistake, Metalama reports LAMA0272 on the `return;` statements of a `void` method marked with `[Template]` when every execution path of the method ends with such a statement, so that they're redundant in the template. Typical cases are:

* a `return;` as the last statement of the template;
* a `return;` at the end of both branches of an `if...else` statement, of all sections of a `switch` statement that has a `default` section, or of a `try` block and all its `catch` blocks.

Metalama doesn't report LAMA0272 when the end of the template is still reachable, for instance for a `return;` in an `if` statement without `else`. Such a statement intentionally returns from the target method.

## Resolution
