# LAMA0254: The argument of ConfigureAwait after ProceedAsync must be a literal

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The argument of 'ConfigureAwait' after 'meta.ProceedAsync()' must be the literal 'true' or 'false', but it is '<Argument>'. To choose the value at compile time, use a compile-time 'if' statement with a literal argument in each branch.` |

## Cause

In an async template, such as an implementation of `OverrideAsyncMethod`, you can write `await meta.ProceedAsync().ConfigureAwait( false )` to call the overridden method without capturing the synchronization context. Metalama treats the whole `meta.ProceedAsync().ConfigureAwait(...)` expression as a special form of `meta.Proceed()`, and copies the argument of `ConfigureAwait` into the generated code as is.

For this reason, Metalama accepts only a literal as the argument of `ConfigureAwait` in this expression. It reports LAMA0254 when the argument is any other expression, even a compile-time one like an aspect property or a constant. The placeholder of the message is the argument as written in the template.

## Resolution

Depending on your intent, do one of the following:

* If the value depends on a compile-time setting, such as an aspect property, use a compile-time `if` statement with one `meta.ProceedAsync().ConfigureAwait(...)` call per value, each with the literal `true` or `false`, as in the following example. Metalama emits only the branch that matches the setting.
* If the value is always the same, replace the expression with the literal `true` or `false`.
