# LAMA5002: A non-nullable contract is applied to a nullable type

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Patterns.Contracts |
| **Message** | `The [<AspectType>] contract has been applied to '<Declaration>', but its type is nullable.` |

## Cause

The <xref:Metalama.Patterns.Contracts.NotNullAttribute> and <xref:Metalama.Patterns.Contracts.RequiredAttribute> contracts throw an exception when the target is assigned `null`. Metalama reports LAMA5002 when one of these contracts is applied to a field, property, or parameter whose type is nullable, for instance a `string?` or an `int?`. The declaration and the contract contradict each other: the type says that `null` is a valid value, but the contract rejects it.

The warning isn't reported for declarations whose type is a generic type parameter. The contract still applies and generates its null check.

In the following example, the `Email` property is declared as `string?`, but it has a `[NotNull]` contract.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA5002/LAMA5002_Error.cs name="Warning"]

## Resolution

Do one of the following:

* If `null` isn't a valid value, make the type non-nullable, as in the following example. The C# compiler then also warns callers that pass a possibly null value.
* If `null` is a valid value, remove the contract.
* If you need nullable types with non-nullable contracts, disable the warning by setting the `WarnOnNotNullableOnNullable` property of <xref:Metalama.Patterns.Contracts.ContractOptions> to `false` from a fabric, as described in <xref:configuring-contracts>.
