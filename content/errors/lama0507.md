# LAMA0507: An introduced member can't be both static and virtual

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce virtual member '<Member>' because it is also static.` |

## Cause

In a class or a struct, a static member can't be virtual because virtual members are resolved on an instance. Metalama reports LAMA0507 when an aspect introduces a member that is both static and virtual into a type that isn't an interface. Interfaces are exempt because C# allows static virtual members in interfaces.

The introduced member is static when the introduction scope is <xref:Metalama.Framework.Aspects.IntroductionScope.Static?displayProperty=nameWithType>, or when the scope is the default one and the template is static. It's virtual when the template is virtual, when the <xref:Metalama.Framework.Aspects.IntroduceAttribute.IsVirtual> property of the custom attribute is set, or when the build action sets the <xref:Metalama.Framework.Code.DeclarationBuilders.IMemberBuilder.IsVirtual> property.

In the following example, the `Describe` aspect introduces the `GetDescription` method with the static scope, and its build action makes the method virtual.

## Resolution

Decide whether the introduced member must be static or virtual:

* If derived classes need to override the member, introduce it as an instance member: remove the static scope, or use a non-static template. This is the fix shown in the example below.
* If the member must be static, don't make it virtual: remove the `virtual` modifier from the template, and don't set `IsVirtual` in the custom attribute or in the build action.
