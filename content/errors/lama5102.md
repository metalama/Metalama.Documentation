# LAMA5102: The invalidating method lacks a parameter of the cached method

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Caching |
| **Message** | `The [InvalidateCache] aspect applied to '<InvalidatingMethod>' cannot invalidate '<CachedMethod>': the invalidating method does not contain a parameter named '<ParameterName>'. Make sure '<InvalidatingMethod>' contains a parameter named '<ParameterName>' or add the [NotCacheKey] attribute to the '<ParameterName>' parameter in '<CachedMethod>'.` |

## Cause

To remove a value from the cache, the <xref:Metalama.Patterns.Caching.Aspects.InvalidateCacheAttribute?text=[InvalidateCache]> aspect rebuilds the cache key of the invalidated method from the arguments of the invalidating method. It matches the parameters of both methods by name, regardless of their order. Every parameter of the cached method that's part of the cache key must have a parameter of the same name in the invalidating method.

Metalama reports LAMA5102 when a parameter `<ParameterName>` of the cached method `<CachedMethod>` has no parameter of the same name in the invalidating method `<InvalidatingMethod>`, and the parameter isn't excluded from the cache key with the <xref:Metalama.Patterns.Caching.NotCacheKeyAttribute?text=[NotCacheKey]> attribute.

> [!NOTE]
> Because of a bug in the current version of Metalama.Patterns.Caching, the message shows the cached method instead of the invalidating method in place of `<InvalidatingMethod>`, as in the following example.

In the following example, `GetPrice` has a `productId` parameter, but the corresponding parameter of `UpdatePrice` is named `product`.

## Resolution

Do one of the following:

* Add the missing parameter to the invalidating method, or rename the existing one so that it has the same name as in the cached method, as in the following example.
* If the parameter of the cached method shouldn't be part of the cache key, add the `[NotCacheKey]` attribute to it. This changes the caching behavior: calls that differ only by this parameter share the same cache entry.
* If the methods are too different to be matched, invalidate the cache imperatively by calling the `Invalidate` method of the caching service.
