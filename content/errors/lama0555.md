# LAMA0555: A union can't hold an instance field, an automatic property or a field-like event

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce <MemberKind> into the union '<TargetType>' because a union declaration permits no instance field, no automatic property and no field-like event. Introduce a property whose accessors have a body, or an event whose accessors have a body.` |

## Cause

A union declaration, written with the `union` keyword of C# 15, stores its value in a form that the compiler controls. For this reason, the language forbids members that add state to it: an instance field, an automatic property (which has a hidden field) and a field-like event (which also has a hidden field). Static members, methods, nested types, and properties or events whose accessors have a body are allowed.

When an aspect introduces a union with `IntroduceUnion` and then calls <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceField*>, <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceAutomaticProperty*> or <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceEvent*> with a field-like event template to add such a member, Metalama reports LAMA0555 instead of letting the C# compiler report an error in generated code that you can't edit. The `<MemberKind>` placeholder describes the refused member, and `<TargetType>` is the union.

## Resolution

Do one of the following:

* Introduce a property whose accessors have a body, using <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceProperty*> with a template. Such a property holds no field.
* Introduce an event with explicit `add` and `remove` accessors instead of a field-like event.
* Introduce a static member, which holds no state of the value.
* Introduce the member into a regular class or struct instead of the union.
