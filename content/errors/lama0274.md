# LAMA0274: A template must be declared in an aspect, a fabric, or a template provider

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The template '<Template>' is contained in '<ContainingType>', which is not an aspect, a fabric, or a type implementing ITemplateProvider.` |

## Cause

Templates, that is, members marked with a template attribute such as <xref:Metalama.Framework.Aspects.TemplateAttribute?text=[Template]> or <xref:Metalama.Framework.Aspects.IntroduceAttribute?text=[Introduce]>, can only be declared in an aspect, in a fabric, or in a type that implements the <xref:Metalama.Framework.Aspects.ITemplateProvider> interface.

Metalama reports LAMA0274 when a template is declared in any other type. The `<Template>` placeholder is the template and `<ContainingType>` is the type that contains it. This often happens when you move auxiliary templates to a separate helper class and forget to implement <xref:Metalama.Framework.Aspects.ITemplateProvider>, or when the helper class is `static`, because a static class can't implement an interface.

In the following example, the `LogEntry` template is declared in the static class `LoggingTemplates`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0274/LAMA0274_Error.cs name="Error"]

## Resolution

Do one of the following:

* Make the containing type implement <xref:Metalama.Framework.Aspects.ITemplateProvider>. If the type is a static class, remove the `static` modifier and add a `private` constructor to prevent instantiation. The templates themselves can remain `static`.
* Move the template to the aspect or fabric that uses it.

In the following example, `LoggingTemplates` implements <xref:Metalama.Framework.Aspects.ITemplateProvider>.
