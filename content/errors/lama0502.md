# LAMA0502: The introduced member can't override the base member

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce member '<Member>' into type '<TargetType>' because it is already defined in type '<DeclaringType>' and is static, non-virtual or sealed, so it cannot be overridden. Use OverrideStrategy.New to hide the existing member, or OverrideStrategy.Ignore to keep it.` |

## Cause

When an aspect introduces a method, property, event or indexer with the `OverrideStrategy.Override` strategy, and a member with the same signature already exists in a base type, Metalama introduces an `override` member in the target type. As in C#, this is only possible when the base member is `virtual`, `abstract` or `override`, and isn't `sealed`.

Metalama reports LAMA0502 when the base member can't be overridden because it's static, non-virtual or sealed. In the message, `<TargetType>` is the target type and `<DeclaringType>` is the base type that defines the existing member.

In the following example, the `Resettable` aspect overrides the `Reset` method in `ShoppingCart`, but the `Reset` method of the base class `Cart` isn't virtual.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0502/LAMA0502_Error.cs name="Error"]

## Resolution

Depending on your intent, do one of the following:

* If you own the base type, make the base member `virtual`, or remove its `sealed` modifier.
* Use `OverrideStrategy.New` to introduce a member that hides the base member with the `new` modifier. Code that calls the member through the base type still calls the base member.
* Use `OverrideStrategy.Ignore` to keep the base member and skip the introduction.

In the following example, the `Reset` method of `Cart` is made virtual, so the aspect introduces an `override` method in `ShoppingCart`.
