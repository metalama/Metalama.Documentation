# LAMA5203: An existing member has the name of the member to introduce

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Wpf |
| **Message** | `The name of the existing <Kind> '<Member>', defined in or inherited by the type '<DeclaringType>', conflicts with the <IntroducedKind> name determined by the '<NamingConvention>' naming convention. Rename the existing <Kind> or change the naming convention.` |

## Cause

The WPF aspects introduce a member whose name comes from a naming convention:

* The <xref:Metalama.Patterns.Wpf.CommandAttribute?text=[Command]> aspect introduces a command property. With the default naming convention, a method named `Save`, `ExecuteSave`, or `SaveAsync` gets a property named `SaveCommand`.
* The <xref:Metalama.Patterns.Wpf.DependencyPropertyAttribute?text=[DependencyProperty]> aspect introduces a static registration field that holds the <xref:System.Windows.DependencyProperty> object. For a property named `Foo`, the field is named `FooProperty`, as WPF requires.

Before introducing the member, the aspect checks whether the type already has a member or a nested type with that name, including members inherited from base types. If it does, Metalama reports LAMA5203 and the aspect isn't applied to the target. A typical case is a hand-written `SaveCommand` property left in the class after adding `[Command]` to the `Save` method, or a hand-written `FooProperty` field after adding `[DependencyProperty]` to the `Foo` property.

In the message, `<Kind>` and `<Member>` are the kind and the name of the existing member, `<DeclaringType>` is the type that contains the aspect's target, `<IntroducedKind>` is `command property` or `registration field`, and `<NamingConvention>` is the name of the naming convention that determined the name, for example `default` or `explicitly-configured`.

## Resolution

* If the existing member is a hand-written implementation of the command or the dependency property, remove it: the aspect generates it.
* Otherwise, rename the existing member.
* For a command, you can also change the name of the generated property: rename the target method, or add a naming convention with a different <xref:Metalama.Patterns.Wpf.Configuration.CommandNamingConvention.CommandPropertyName> pattern through the <xref:Metalama.Patterns.Wpf.Configuration.CommandExtensions.ConfigureCommand*> fabric extension method. In the current version, the <xref:Metalama.Patterns.Wpf.CommandAttribute.CommandPropertyName> property of the attribute is taken into account only when <xref:Metalama.Patterns.Wpf.CommandAttribute.CanExecuteMethod> or <xref:Metalama.Patterns.Wpf.CommandAttribute.CanExecuteProperty> is also set.
* For a dependency property, keep the WPF convention `FooProperty` whenever possible, because WPF tools and XAML rely on it. Renaming the C# property also renames the field.
