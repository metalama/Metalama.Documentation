# LAMA5100: The invalidated method isn't cached

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Caching |
| **Message** | `The [InvalidateCache] aspect applied to '<InvalidatingMethod>' cannot invalidate '<InvalidatedMethod>': this method is not cached by the [Cache] aspect.` |

## Cause

The <xref:Metalama.Patterns.Caching.Aspects.InvalidateCacheAttribute?text=[InvalidateCache]> aspect makes a method, called the _invalidating method_, remove from the cache the values of the methods whose names you pass to the attribute. These methods must be cached by the <xref:Metalama.Patterns.Caching.Aspects.CacheAttribute?text=[Cache]> aspect.

Metalama reports LAMA5100 when the aspect finds a method with the given name, but this method doesn't have the `[Cache]` aspect. In the message, `<InvalidatingMethod>` is the invalidating method and `<InvalidatedMethod>` is the method that isn't cached. When several overloads have the given name, the diagnostic is reported only if none of them can be invalidated.

In the following example, `UpdatePrice` invalidates `GetPrice`, but `GetPrice` doesn't have the `[Cache]` aspect.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA5100/LAMA5100_Error.cs name="Error"]

## Resolution

Do one of the following:

* Add the `[Cache]` aspect to the invalidated method, as in the following example. You can also add it with a fabric.
* If the method isn't meant to be cached, remove its name from the `[InvalidateCache]` attribute, or remove the attribute.
* If you meant a method of another type, use the constructor of `[InvalidateCache]` that accepts the declaring type.
