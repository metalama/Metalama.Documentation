# LAMA0543: An extension block can't contain a member with this modifier

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<Aspect>' cannot introduce '<Member>' into '<ExtensionBlock>' because the member is '<Modifier>', which the language forbids for an extension member.` |

## Cause

An extension member isn't a member of the extended type, so the C# language forbids the modifiers that make sense only in a class hierarchy. The forbidden modifiers are `abstract`, `virtual`, `override`, `new`, `sealed`, `partial` and `protected`.

Metalama reports LAMA0543 when an aspect calls <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceIndexer*> on an extension block and the indexer has one of these modifiers. `<Modifier>` in the message names the modifier. Metalama also checks the accessors: an indexer with a `protected` get or set accessor is rejected even if the indexer itself is public.

In the following example, the template of the set accessor is `protected`, so the aspect introduces an indexer with a protected set accessor.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0543/LAMA0543_Error.cs name="Error"]

## Resolution

Remove the modifier named in the message, or give the accessor the same accessibility as the indexer. In the following example, the template of the set accessor is `public`.
