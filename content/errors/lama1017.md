# LAMA1017: The accessibility of the generated interceptor method is inconsistent

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Extensions.Interceptors |
| **Message** | `The generated interceptor method '<Method>' must be <Accessibility>, but its signature contains the type '<Type>', which is less accessible. Choose a placement in a type that can access this type. The call sites are left unchanged.` |

## Cause

An _interceptor_ redirects the calls to a method to another method that Metalama generates from a template. The generated method has the parameters and the return type of the intercepted method. By default, Metalama places it in a generated internal static class, so it must be at least `internal` to be called from the call sites.

The C# rules of accessibility consistency forbid a method from exposing a type that is less accessible than the method itself. Metalama reports LAMA1017 when a parameter type or the return type of the generated method, such as a private nested type, is less accessible than the accessibility that the call sites need. Metalama then leaves the call sites unchanged.

In the following example, `Process` has a parameter of the private nested type `Order`, so a method of the generated internal class can't replace it.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA1017/LAMA1017_Error.cs name="Error"]

## Resolution

Choose a placement in a type that can access the less accessible type. When the calls to the intercepted method are in the type that declares the private type, use `PlaceInCallingType`: the generated method is then private, and it can expose the type. You can also use `PlaceInType` with a type that can access it.

Alternatively, make the type in the signature more accessible.
