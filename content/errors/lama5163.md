# LAMA5163: The property can't be observed through a computed property

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Patterns.Observability |
| **Message** | `Changes to the children of the '<Property>' property cannot be observed because '<Property>' is not an auto-property. Access the child through an auto-property or a field of '<DeclaringType>' instead.` |

## Cause

The <xref:Metalama.Patterns.Observability.ObservableAttribute?text=[Observable]> aspect supports computed properties that read properties of child objects, such as `this.Address.City`, when the type of the child object implements <xref:System.ComponentModel.INotifyPropertyChanged>. To track changes to `City`, the aspect subscribes to the <xref:System.ComponentModel.INotifyPropertyChanged.PropertyChanged?text=PropertyChanged> event of the object stored in `Address`, and it updates this subscription when `Address` changes.

This tracking only works when the parent property is an auto-property or a field. Metalama reports LAMA5163 when a computed property reads a child of a _non-auto_ property declared on the same type, for example a property computed from other properties. The aspect doesn't detect that the child's value changes, so the computed property isn't notified. In the message, `<Property>` is the non-auto property and `<DeclaringType>` is the type that declares it.

For a property of a base type that doesn't implement <xref:System.ComponentModel.INotifyPropertyChanged>, Metalama reports <xref:lama5166?text=LAMA5166> instead.

In the following example, `DeliveryCity` reads `City` through `DeliveryAddress`, which is a computed property.

## Resolution

Do one of the following:

* Access the child property through auto-properties or fields, as in the following example. If needed, repeat the condition of the computed property.
* If the computed property never changes after the object is constructed, turn it into a get-only auto-property initialized in the constructor.
