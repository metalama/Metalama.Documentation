# LAMA0229: A run-time-or-compile-time type can't be nested in a run-time class

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The type '<Type>' cannot be both run-time and compile-time, like an aspect class or a [RunTimeOrCompileTime] class, because it is nested in a run-time-only type. Move it out of the containing type.` |

## Cause

Metalama builds a separate compile-time assembly that contains your aspects, fabrics, and other compile-time code. Run-time-only types aren't copied to this assembly. When a run-time type contains nested types, Metalama only extracts the nested types that are compile-time only, such as type fabrics. It can't extract a type that must exist both at run time and at compile time.

Metalama reports LAMA0229 when a type whose scope is both run-time and compile-time is nested in a run-time-only type. This applies to every kind of type (class, struct, record, interface, enum, or delegate) marked with [<xref:Metalama.Framework.Aspects.RunTimeOrCompileTimeAttribute>], and implicitly to aspect classes, because <xref:Metalama.Framework.Aspects.IAspect> is run-time-or-compile-time.

## Resolution

Move the type out of the run-time type, for instance to the namespace level, as in the following example.

If the type only needs to exist at compile time, you can instead mark it with [<xref:Metalama.Framework.Aspects.CompileTimeAttribute>], but only private type fabrics can be nested in a run-time type (see <xref:lama0230?text=LAMA0230> and <xref:lama0231?text=LAMA0231>), so you'll usually still need to move it.
