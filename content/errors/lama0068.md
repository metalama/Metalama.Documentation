# LAMA0068: The compile-time code contains C# errors

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The compile-time code of the project contains C# errors, so it cannot be compiled. Fix the C# errors reported in the compile-time code.` |

## Cause

Before Metalama can execute your aspects, fabrics, and other compile-time types, it compiles them into a separate _compile-time assembly_. To do this, Metalama first checks every compile-time type of the project for C# errors.

When a compile-time type contains C# errors, Metalama reports these errors and can't build the compile-time assembly. It then also reports LAMA0068, so that the failure is never silent, whatever the logging configuration. LAMA0068 itself has no location: the C# errors reported next to it point to the faulty code.

## Resolution

1. Look at the other errors of the build, typically `CS` errors, and find the ones located in compile-time code: aspects, fabrics, templates, or types marked with <xref:Metalama.Framework.Aspects.CompileTimeAttribute?text=[CompileTime]> or <xref:Metalama.Framework.Aspects.RunTimeOrCompileTimeAttribute?text=[RunTimeOrCompileTime]>.
2. Fix these errors. Remember that compile-time code can only use the .NET Standard 2.0 API, the Metalama API, and the packages explicitly made available to compile-time code.
3. Rebuild the project. LAMA0068 disappears when the compile-time code compiles.
