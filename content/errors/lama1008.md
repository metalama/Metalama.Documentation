# LAMA1008: The type has no method of the name selected for interception

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Extensions.Interceptors |
| **Message** | `The <Source> intercepts methods named '<Name>' declared by '<Type>', but no such method exists.<Detail>` |

## Cause

Metalama.Extensions.Interceptors lets an aspect or a fabric replace the calls to selected methods with calls to other methods. In a registration made with the `InterceptMethods` method, the `Type` method selects the declaring type, and the `Methods` method selects the intercepted methods by name.

Metalama reports LAMA1008 when the declaring type doesn't declare an ordinary method of one of these names. The registration then intercepts no call. The usual causes are a misspelled name, a method that the type inherits from its base type instead of declaring it, or a name that designates a property, an event, or a C# 14 extension member, whose accessors can't be intercepted in this version.

In the message, `<Source>` describes the aspect or fabric that made the registration, `<Name>` is the selected name, and `<Type>` is the declaring type. `<Detail>` is empty, or it's an additional sentence when the name designates a property, an event, or an extension member.

In the following example, the fabric selects the method `Prnt`, but the `Printer` class declares `Print`.

## Resolution

Depending on the cause, do one of the following:

* Correct the name given to `Methods`. In the following example, the name matches the `Print` method.
* Select the base type that declares the method, instead of the type that inherits it.
* If the name designates a property, an event, or an extension member, remove the registration.
