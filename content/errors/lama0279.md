# LAMA0279: An abstract or empty template can't be called

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The template '<Template>' cannot be called because it is abstract or marked with [Template(IsEmpty = true)]. Call a template that has an implementation instead, for example a virtual template with a default implementation.` |

## Cause

When a template calls an auxiliary template, Metalama expands the body of the called template into the generated code. An abstract template has no body, and a template marked with `[Template(IsEmpty = true)]` is only a placeholder meant to be overridden, so neither can be expanded.

Metalama reports LAMA0279 when the call to an auxiliary template resolves to such a template. The typical situations are:

* An aspect base class calls one of its own abstract templates. Metalama reports the error even if every derived aspect overrides the template.
* A template calls a template through the interface that declares it, for instance after a cast to the interface.
* A template calls an empty template of a base class, for instance `base.OverrideAsyncMethod()` in an aspect derived from <xref:Metalama.Framework.Aspects.OverrideMethodAspect>, or `OverrideAsyncMethod()` when the aspect doesn't override it.

## Resolution

Depending on the situation, do one of the following:

* In an aspect base class, make the template `virtual` instead of `abstract`, and give it a default implementation, which can be empty. Derived aspects can still override it, and Metalama expands the override. The following example uses this fix.
* When you call a template declared in an interface, call it on the aspect class that implements it.
* Don't call an empty template of the base class. Write the code you need in your own template instead.
