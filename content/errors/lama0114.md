# LAMA0114: A template can't reference `this` in a static member

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot reference 'this' in an advice applied to <TargetKind> '<TargetDeclaration>' because <Explanation>.` |

## Cause

In a template, <xref:Metalama.Framework.Aspects.meta.This> represents the current instance of the target type, and Metalama generates a `this` expression for it. Some code model operations also generate `this` implicitly, for instance when the template invokes an instance member of the target type without specifying the receiver.

A static member has no current instance. Metalama reports LAMA0114 when it expands a template that needs `this` while the advice is applied to a static member, for instance a static method or the static constructor. The last part of the message explains why no instance is available. Metalama detects the problem only when it expands the template for a given target, so the same aspect works on instance members and fails on static ones.

In the following example, the `Trace` aspect prints `meta.This`. It works on the instance method `Add`, but fails on the static method `Multiply`.

## Resolution

Depending on your intent, do one of the following:

* Make the template handle static members: test `meta.Target.Method.IsStatic`, or the `IsStatic` property of the relevant declaration, in a compile-time `if` statement, and use `meta.This` only in the branch for instance members. The following example uses this approach.
* If the aspect can't work without an instance, add the `MustNotBeStatic` condition to the aspect's `BuildEligibility` method. Metalama then reports that the aspect isn't eligible on static members, and fabrics can skip them.
* Remove the aspect from the static member.
