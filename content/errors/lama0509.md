# LAMA0509: OverrideStrategy.New can't hide a member declared in the same type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce member '<Member>' into type '<TargetType>' with OverrideStrategy.New because the member is already declared in the type.` |

## Cause

When an aspect introduces a method, property, field, event, or indexer, the <xref:Metalama.Framework.Aspects.OverrideStrategy> of the advice decides what happens if the member already exists. You set it with the <xref:Metalama.Framework.Aspects.IntroduceAttribute.WhenExists> property of the `[Introduce]` attribute, or with the `whenExists` parameter of the programmatic advice methods.

With `OverrideStrategy.New`, Metalama introduces the member with the `new` modifier, which hides a member with the same signature inherited from a base type. This only works when the existing member is declared in a base type. C# doesn't allow two members with the same signature in the same type, so Metalama reports LAMA0509 when the target type itself declares the member.

In the following example, the `Describe` aspect introduces a `Describe` method with `OverrideStrategy.New`, but the `Product` class already declares `Describe`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0509/LAMA0509_Error.cs name="Error"]

## Resolution

Choose the strategy that matches your intent for types that already declare the member:

* Use `OverrideStrategy.Override` to override the existing member with the template. Call `meta.Proceed()` in the template to invoke the original implementation.
* Use `OverrideStrategy.Ignore` to keep the existing member unchanged.
* Remove or rename the member in the target type if it shouldn't be there.

Keep `OverrideStrategy.New` for members that are inherited from a base type.
