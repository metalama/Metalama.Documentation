# LAMA5001: The type can't satisfy the range of the contract

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Contracts |
| **Message** | `The [<AspectType>] contract cannot be applied to '<Declaration>' because the value range <Range> cannot be satisfied by the type <TargetBasicType>.` |

## Cause

Range contracts, such as <xref:Metalama.Patterns.Contracts.RangeAttribute>, <xref:Metalama.Patterns.Contracts.GreaterThanOrEqualAttribute>, or <xref:Metalama.Patterns.Contracts.StrictlyNegativeAttribute>, verify that a numeric value lies within a range. At compile time, the contract compares the bounds of the range with the values that the type of the target can hold.

Metalama reports LAMA5001 when no value of the type can satisfy the range, so the check would always fail. This happens when the minimum bound is greater than the largest value of the type, or when the maximum bound is smaller than the smallest value of the type, for instance a range starting at 1024 on a `byte`, or a strictly negative range on an unsigned type. The message shows the range in interval notation and the name of the type. The contract isn't applied.

In the following example, the `Port` property is a `byte`, which can't hold any value between 1024 and 65535.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA5001/LAMA5001_Error.cs name="Error"]

## Resolution

Do one of the following:

* Change the type of the target to a numeric type that can hold the values of the range, as in the following example.
* Correct the bounds of the contract if they're wrong.
