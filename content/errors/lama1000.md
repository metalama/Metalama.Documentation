# LAMA1000: The interception scope must be inside the target of the aspect

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Extensions.Interceptors |
| **Message** | `The <Predecessor> cannot add an interceptor to '<Child>' because '<Child>' is not contained in '<Parent>'.` |

## Cause

Metalama.Extensions.Interceptors lets an aspect or a fabric replace the calls to selected methods, in the source code of the current project, with calls to other methods. An aspect or fabric registers an interceptor with the `InterceptMethods` method of its adviser, builder, or amender. The declaration on which you call this method is the _interception scope_: only the calls located inside this declaration are intercepted.

An aspect or fabric can register interceptors only under its own target, so that it can't change the behavior of code that it doesn't own. The scope must be contained in the closest type of the aspect target. When the target is a namespace, the scope must be contained in that namespace. When the target is the compilation, any declaration of the current project is accepted, but not the declarations of referenced assemblies.

Metalama reports LAMA1000 when the scope isn't contained in the target. In the message, `<Predecessor>` describes the aspect or fabric, `<Child>` is the scope, and `<Parent>` is the declaration that should contain it.

In the following example, the `RedirectLogging` aspect is applied to `Checkout`, but it registers the interceptor on `OrderService`.

## Resolution

Register the interceptor on the target of the aspect or on a declaration inside it, or apply the aspect to a declaration that contains the scope. To intercept calls in the whole project, use a project fabric. In the following example, the aspect is applied to `OrderService` and registers the interceptor on its target.
