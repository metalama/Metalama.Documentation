# LAMA0117: Code that isn't compile-time references a compile-time-only declaration

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot reference '<ReferencedSymbol>' in '<DeclaringSymbol>' because '<ReferencedSymbol>' is compile-time-only but '<DeclaringSymbol>' is <DeclaringScope>. Consider adding [CompileTime] to '<DeclaringSymbol>', or do not use '<ReferencedSymbol>' in '<DeclaringSymbol>'.` |

## Cause

Metalama assigns a scope to every declaration. _Compile-time-only_ declarations, like the code model (`IMethod`, `IDeclaration`), `meta`, and types marked with `[CompileTime]`, exist only while Metalama compiles your project. _Run-time_ declarations are part of the compiled program. Members of aspect classes that are neither templates nor marked with `[CompileTime]` are _run-time-or-compile-time_: they're compiled into both the compile-time assembly and the run-time assembly.

Code that runs at run time can't use compile-time-only declarations, because they don't exist at run time. Metalama reports LAMA0117 when a declaration whose scope is run-time or run-time-or-compile-time references a compile-time-only declaration outside of a template, `typeof`, or `nameof`. In the message, `<DeclaringSymbol>` is the declaration containing the reference, `<ReferencedSymbol>` is the compile-time-only declaration, and `<DeclaringScope>` is the scope of `<DeclaringSymbol>`.

## Resolution

Depending on your intent, do one of the following:

* If the code is meant to run at compile time, add `[CompileTime]` to the declaration or to its containing type. The following example adds `[CompileTime]` to the helper method.
* If the code is meant to run at run time, remove the reference to the compile-time-only declaration. To generate run-time code from compile-time information, use a template instead.
