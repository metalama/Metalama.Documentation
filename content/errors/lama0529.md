# LAMA0529: An inherited member must be virtual to implement an interface member

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot override the member '<Member>' to implement an interface member because '<Member>' is inherited from a base type and is either not virtual or sealed. Make '<Member>' virtual and not sealed.` |

## Cause

When an aspect implements an interface with the <xref:Metalama.Framework.Aspects.AdviserExtensions.ImplementInterface*> method and passes `OverrideStrategy.Override` as the `whenExists` argument, Metalama doesn't introduce a new member when the target type already has a method, property, or event with the same name and signature as an interface member. Instead, it overrides the existing member with the template marked with <xref:Metalama.Framework.Aspects.InterfaceMemberAttribute?text=[InterfaceMember]>.

When the existing member is declared in the target type itself, Metalama modifies it in place. When the member is inherited from a base type, Metalama must introduce an `override` member into the target type, which is only possible if the inherited member is virtual and isn't `sealed`. Otherwise, Metalama reports LAMA0529. In the message, `<Member>` is the inherited member.

In the following example, the `Disposable` aspect implements `IDisposable` on `FileLogger`, but the `Dispose` method inherited from `LoggerBase` isn't virtual.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0529/LAMA0529_Error.cs name="Error"]

## Resolution

Do one of the following:

* Make the inherited member `virtual` and remove any `sealed` modifier, so that Metalama can override it in the target type. The `override` member calls the base implementation where the template calls `meta.Proceed()`. The following example shows this fix.
* If the base type already implements the interface and the aspect doesn't need to change its behavior, pass `OverrideStrategy.Ignore` instead of `OverrideStrategy.Override`.
* If you can't make the member virtual, apply the aspect to the base type that declares the member instead of the derived type.
