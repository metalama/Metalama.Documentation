# LAMA0044: An aspect or fabric can't set options outside of its scope

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The <Predecessor> cannot set options for '<Child>' because it is not contained in '<Parent>'.` |

## Cause

Aspects and fabrics can set hierarchical options, for instance with the `SetOptions` method or with a configuration extension method such as `ConfigureContracts`. They can do this only for declarations within their own scope:

* A type fabric, or an aspect applied to a type or a member, can set options for its type and the members and nested types of this type.
* A namespace fabric can set options for its namespace and the types it contains.
* A project fabric, or an aspect applied to the compilation, can set options for any declaration of the current project.

Metalama reports LAMA0044 when a query selects a declaration outside of this scope, or a declaration of a referenced assembly, and then sets options for it. In the message, `<Predecessor>` describes the aspect or fabric, `<Child>` is the declaration for which options are set, and `<Parent>` is the type or namespace that limits the scope.

The same ID is reported with the message `The <Predecessor> cannot add a validator to '<Child>' because it is not contained in '<Parent>'.` when an aspect or fabric adds a validator, with the `Metalama.Extensions.Validation` package, to a declaration outside of its scope. The rule and the resolution are the same.

## Resolution

Set the options from a fabric whose scope includes the declarations you want to configure:

* To configure only the current type, call the method on the type fabric's amender directly, without selecting other declarations. The following example shows this fix.
* To configure a namespace, use a namespace fabric in this namespace.
* To configure the whole project, use a project fabric.
