# LAMA5202: The can-execute property of a command should be public

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Patterns.Wpf |
| **Message** | `The can-execute property of the command method '<Method>' is not public, but INotifyPropertyChanged integration is enabled. Because INotifyPropertyChanged implementations usually raise the PropertyChanged event only for public properties, the CanExecuteChanged event of the command might not be raised. Make the property public or disable INotifyPropertyChanged integration.` |

## Cause

When the `CanExecute` logic of a <xref:Metalama.Patterns.Wpf.CommandAttribute?text=[Command]> method is a property, and the declaring type implements <xref:System.ComponentModel.INotifyPropertyChanged>, the aspect subscribes to the `PropertyChanged` event and raises the command's <xref:System.Windows.Input.ICommand.CanExecuteChanged> event when the can-execute property changes. This integration is enabled by default.

Many `INotifyPropertyChanged` implementations raise `PropertyChanged` only for public properties. If the can-execute property is `private`, `protected`, or `internal`, the command might never learn that the property changed, and the bound button stays enabled or disabled.

Metalama reports LAMA5202 on the can-execute property when all the following conditions are true:

* the can-execute member found for the command, by naming convention or with <xref:Metalama.Patterns.Wpf.CommandAttribute.CanExecuteProperty>, is a property, not a method;
* INotifyPropertyChanged integration is enabled;
* the declaring type implements `INotifyPropertyChanged`;
* the property isn't `public`.

In the message, `<Method>` is the method to which `[Command]` is applied. The command is still generated, and the integration is still in place.

## Resolution

* Make the can-execute property `public`. This is the usual fix, and it makes the property available to data binding too.
* If your `INotifyPropertyChanged` implementation does raise `PropertyChanged` for non-public properties, or if you don't need `CanExecuteChanged`, disable the integration by setting <xref:Metalama.Patterns.Wpf.Configuration.CommandOptionsBuilder.EnableINotifyPropertyChangedIntegration> to `false` in a fabric, through the <xref:Metalama.Patterns.Wpf.Configuration.CommandExtensions.ConfigureCommand*> extension method. In the current version, setting the `EnableINotifyPropertyChangedIntegration` property of the `[Command]` attribute itself has no effect.
* Use a can-execute method instead of a property. The integration doesn't apply to methods, so the command doesn't raise `CanExecuteChanged` automatically.
