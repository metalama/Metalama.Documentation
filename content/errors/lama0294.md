# LAMA0294: A C# feature isn't supported in compile-time code

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The declaration '<Declaration>' cannot use the C# feature '<Feature>', because compile-time code is compiled for netstandard2.0, which does not support this feature.` |

## Cause

Metalama compiles compile-time code, such as aspects, fabrics, and types marked with `[CompileTime]` or `[RunTimeOrCompileTime]`, into a separate assembly that targets .NET Standard 2.0, whatever the target framework of your project. Some C# features require support from the runtime and can't be used in this assembly.

Metalama reports LAMA0294 when a compile-time or run-time-or-compile-time type uses such a feature. Currently, the only feature checked is _inline arrays_: a struct marked with the `[InlineArray]` attribute, which requires .NET 8 or later. The first placeholder of the message is the feature, and the second is the declaration that uses it.

This diagnostic replaces <xref:lama0281>, which earlier versions of Metalama reported in the same situation.

In the following example, the `Log` aspect uses a compile-time inline array.

## Resolution

Do one of the following:

* In compile-time code, use a regular array or another collection type instead of an inline array, as in the following example.
* If only run-time code uses the type, remove the `[CompileTime]` or `[RunTimeOrCompileTime]` attribute so that the type stays in run-time code, where inline arrays are supported when the project targets .NET 8 or later. Templates can still use the type in run-time expressions.
