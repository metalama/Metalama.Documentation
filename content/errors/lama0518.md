# LAMA0518: The template of an explicit interface property has an extra accessor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot implement the interface property '<InterfaceProperty>' in the type '<TargetType>' explicitly because the template '<TemplateMember>' has the '<AccessorKind>' accessor, which the interface property does not have. Remove the accessor from the template or implement the property implicitly.` |

## Cause

When an aspect implements an interface with <xref:Metalama.Framework.Aspects.AdviserExtensions.ImplementInterface*>, you can set the <xref:Metalama.Framework.Aspects.InterfaceMemberAttribute.IsExplicit> property of the <xref:Metalama.Framework.Aspects.InterfaceMemberAttribute?text=[InterfaceMember]> attribute to `true` to introduce an explicit implementation of the interface member.

In C#, an explicit implementation of a property must have exactly the accessors of the interface property. An implicit implementation can add accessors, for instance a public setter to a read-only interface property, but an explicit one can't.

Metalama reports LAMA0518 when the template of an explicit implementation has a `get`, `set`, or `init` accessor that the interface property doesn't declare. In the message, `<AccessorKind>` is the extra accessor.

In the following example, the `IDescribable.Description` property is read-only, but the template, which is an explicit implementation, also has a setter.

## Resolution

Do one of the following:

* Remove the extra accessor from the template property. The following example uses this fix.
* If the target type needs the extra accessor, implement the property implicitly: remove `IsExplicit = true` from the `[InterfaceMember]` attribute. The introduced property is then public.
