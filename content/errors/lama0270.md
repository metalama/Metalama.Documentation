# LAMA0270: A template can only be called as a stand-alone statement

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The template call '<Call>' cannot be part of another expression or statement. A template can only be called as a stand-alone statement.` |

## Cause

A template can call an _auxiliary template_, a method marked with `[Template]`. Metalama doesn't generate a method call: it expands the auxiliary template and inserts the statements it generates at the place of the call. For this reason, the call must be a stand-alone statement, like `this.Log();`.

Metalama reports LAMA0270 when the call to an auxiliary template is part of another expression or statement, for instance:

* the expression of a `return` statement or the initializer of a local variable;
* an argument of another method call;
* a part of a `for` statement, such as its condition;
* a conditional access, like `templates?.Log()`;
* the initializer of a field introduced with `[Introduce]`.

Even when the auxiliary template returns a value, you can't use this value in an expression: its `return` statements become `return` statements of the target method.

## Resolution

Call the auxiliary template as a stand-alone statement. If you need a value, produce it outside of the auxiliary template:

* Make the auxiliary template `void`, call it as a statement, and keep the code that produces the value, like `meta.Proceed()`, in the calling template, as in the following example.
* If the auxiliary template must end the target method with a value, make it `void` and call `meta.Return(...)` in it to generate the `return` statement.
* If you only need to compute a compile-time value, use a compile-time method instead of a template.
