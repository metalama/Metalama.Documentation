# LAMA0905: The declaration can't be used from this context

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Extensions.Architecture |
| **Message** | `The '<ValidatedDeclaration>' <ValidatedDeclarationKind> cannot be <UsageKind> by the '<ReferencingDeclaration>' <ReferencingDeclarationKind>.<OptionalSpace><Description>` |

## Cause

Metalama.Extensions.Architecture lets you restrict the code that can use a type, a member, or a namespace. You define these rules with attributes such as <xref:Metalama.Extensions.Architecture.Aspects.CanOnlyBeUsedFromAttribute>, <xref:Metalama.Extensions.Architecture.Aspects.CannotBeUsedFromAttribute>, <xref:Metalama.Extensions.Architecture.Aspects.InternalsCanOnlyBeUsedFromAttribute>, and <xref:Metalama.Extensions.Architecture.Aspects.InternalsCannotBeUsedFromAttribute>, or with the <xref:Metalama.Extensions.Architecture.ArchitectureExtensions.CanOnlyBeUsedFrom*> and <xref:Metalama.Extensions.Architecture.ArchitectureExtensions.CannotBeUsedFrom*> methods in a fabric.

Metalama reports LAMA0905 on each reference to a constrained declaration from code that the rule doesn't allow. References from within the constrained type itself are never reported. A `var` local variable whose inferred type is the constrained type also counts as a reference. The message contains the following parts:

* `<ValidatedDeclaration>` and `<ValidatedDeclarationKind>` are the referenced declaration and its kind, for example `'Order' type`.
* `<UsageKind>` is `assigned` for an assignment and `referenced` for any other kind of reference.
* `<ReferencingDeclaration>` and `<ReferencingDeclarationKind>` are the referencing declaration and its kind. Depending on the rule, it's a type or a namespace.
* `<OptionalSpace><Description>` is the text of the rule's `Description` property, if any.

## Resolution

Depending on your intent, do one of the following:

* Change the referencing code so that it respects the rule, typically by going through the API that the rule allows. The description in the message often says which one.
* If the referencing code is legitimately allowed to use the declaration, extend the scope of the rule, for instance by adding the type or namespace to the `Types` or `Namespaces` property, or define an exclusion with the `ExclusionPredicateType` property.
* To accept a single violation, suppress the warning with `#pragma warning disable LAMA0905`.
