# LAMA0284: The scope of a lambda or anonymous method can't be determined

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The scope of the anonymous method or lambda expression with a block body cannot be determined. Use 'meta.RunTime' or 'meta.CompileTime' to resolve the ambiguity.` |

## Cause

In a template, every statement is either compile-time, meaning that it runs during compilation, or run-time, meaning that it's copied to the generated code. For a lambda expression with an expression body, Metalama infers the scope from the expression. For a lambda expression with a block body, or for an anonymous method (`delegate { ... }`), Metalama must learn the scope from the context, for instance from the run-time method to which the lambda is passed as an argument.

Metalama reports LAMA0284 when such a lambda or anonymous method appears in a context that doesn't determine its scope, for instance when it's assigned to a local variable.

In the following example, a lambda with a block body is assigned to a local variable of type `Action<object?>`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0284/LAMA0284_Error.cs name="Error"]

## Resolution

Make the scope of the lambda or anonymous method explicit:

* To include it in the generated code, wrap it in `meta.RunTime`, for instance `meta.RunTime( new Action<object?>( ... ) )`, as in the following example.
* To run it at compile time, wrap it in `meta.CompileTime`.

Alternatively, pass the lambda directly as an argument of a run-time method, which determines its scope.
