# LAMA0233: A template-only API is used outside of a template

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot use '<ReferencedSymbol>' in '<DeclaringSymbol>' because it is only allowed inside a template.<Explanation>` |

## Cause

Some compile-time APIs are _template-only_: they only make sense while Metalama expands a template, because they generate run-time code at the place where they're used. These include most members of the `meta` class that return `dynamic` or insert statements, such as <xref:Metalama.Framework.Aspects.meta.This?text=meta.This>, `meta.Proceed`, and `meta.InsertStatement`, the `Value` property of `IExpression`, and any API whose signature includes `dynamic`, such as `ExpressionFactory.Capture`.

Metalama reports LAMA0233 when such an API is used in compile-time code that isn't a template, for instance in `BuildAspect`, in a fabric, or in a compile-time helper method. Using the API in a `nameof` or `typeof` expression is allowed. In the message, `<DeclaringSymbol>` is the declaration that contains the code and `<ReferencedSymbol>` is the template-only API. For some APIs, the message ends with a suggested replacement.

In the following example, the `GetTarget` helper method returns an `IExpression`, so it's compile-time code, but it isn't a template. It uses `meta.This`, which is template-only.

## Resolution

Depending on your intent, do one of the following:

* Replace the template-only API with its compile-time equivalent, which returns an `IExpression` instead of a `dynamic` value. For instance, use <xref:Metalama.Framework.Code.SyntaxBuilders.ExpressionFactory.This*?text=ExpressionFactory.This> instead of `meta.This`, and pass an `IExpression` directly instead of reading its `Value` property. The following example uses this fix.
* Move the code into the template itself, or turn the helper method into an auxiliary template by marking it with <xref:Metalama.Framework.Aspects.TemplateAttribute>.
