# LAMA0506: The introduced member conflicts with a member of a different kind

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce member '<Member>' into type '<TargetType>' because there is already a <DeclarationKind> of the same name declared in the type or in a base type.` |

## Cause

When an aspect introduces a member, Metalama looks for an existing member with the same name in the target type and in its base types. If it finds a member of the same kind, the <xref:Metalama.Framework.Aspects.IntroduceAttribute.WhenExists> property, or the `whenExists` parameter of the advice method, decides what happens: the introduction can fail, be ignored, override the existing member, or hide it.

However, Metalama can't override or hide a member of a different kind. For instance, a property can't override a field, and a method can't share its name with a property. Metalama reports LAMA0506 in this situation, whatever the value of `WhenExists`. In the message, `<DeclarationKind>` is the kind of the existing member, for example `field` or `property`.

## Resolution

Depending on your intent, do one of the following:

* Remove or rename the existing member if the aspect is meant to provide it. This is the fix shown in the example below.
* Rename the introduced member. For declarative advice, set the <xref:Metalama.Framework.Aspects.IntroduceAttribute.Name> property of the custom attribute.
* Change the kind of the introduced member so that it matches the existing member, then set `WhenExists` to choose how the aspect handles the existing member.
