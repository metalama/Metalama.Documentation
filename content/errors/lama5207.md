# LAMA5207: No naming convention matches the target

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Wpf |
| **Message** | `No <ArtifactKind> naming convention matched '<Target>'. Add a naming convention that matches this name, or do not remove the default naming convention.` |

## Cause

The <xref:Metalama.Patterns.Wpf.CommandAttribute?text=[Command]> and <xref:Metalama.Patterns.Wpf.DependencyPropertyAttribute?text=[DependencyProperty]> aspects evaluate their naming conventions in order of priority. A naming convention that doesn't recognize the name of the target is skipped, and the next one is tried. For example, a <xref:Metalama.Patterns.Wpf.Configuration.CommandNamingConvention> whose <xref:Metalama.Patterns.Wpf.Configuration.CommandNamingConvention.CommandNamePattern> is `^Vykonat(?<CommandName>.+)$` skips a method named `ExecuteSave`. The same applies to <xref:Metalama.Patterns.Wpf.Configuration.DependencyPropertyNamingConvention.PropertyNamePattern>.

The default naming convention is evaluated last and accepts any name. Therefore, Metalama reports LAMA5207 only when the default naming convention has been removed, with <xref:Metalama.Patterns.Wpf.Configuration.CommandOptionsBuilder.RemoveNamingConvention*> or <xref:Metalama.Patterns.Wpf.Configuration.DependencyPropertyOptionsBuilder.RemoveNamingConvention*> in a fabric, and none of the remaining naming conventions matches the target. The aspect isn't applied.

In the message, `<ArtifactKind>` is `command` or `dependency property`, and `<Target>` is the aspect's target.

In the following example, a fabric removes the default naming convention and adds a convention that recognizes only methods named `RunXxx`. The `ExecuteSave` method doesn't match it.

## Resolution

* Rename the target so that it matches one of your naming conventions, for example `VykonatSave` instead of `ExecuteSave` in the preceding example.
* Add a naming convention that matches this name, for example a catch-all convention without `CommandNamePattern`, which uses the default algorithm to find the command name.
* Don't remove the default naming convention: keep it as a fallback after your custom conventions.
