# LAMA0901: The interface can only be implemented by the project that defines it

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Extensions.Architecture |
| **Message** | `The '<Interface>' interface can only be implemented by the '<AssemblyName>' project or by another project that has access to its internals.` |

## Cause

The <xref:Metalama.Extensions.Architecture.Aspects.InternalOnlyImplementAttribute> aspect protects an interface from being implemented outside of its project. Once other projects implement an interface, you can no longer add members to it without breaking them. Other projects can still use the interface, for instance as a parameter or return type.

Metalama reports LAMA0901 when a type lists the interface among its base types, and the project of this type doesn't have access to the internals of the project that defines the interface. A project has access to these internals when it's the same project, or when the defining project grants it access with the <xref:System.Runtime.CompilerServices.InternalsVisibleToAttribute> attribute.

In the message, `<Interface>` is the protected interface and `<AssemblyName>` is the name of the project that defines it.

In the following example, the `IPaymentMethod` interface is defined in a referenced project and marked with `[InternalOnlyImplement]`. The referencing project implements it in the `GiftCardPayment` class.

## Resolution

Depending on your intent, do one of the following:

* Move the implementation to the project that defines the interface, and use it from the other project. The following example does this.
* If the implementing project is trusted, for instance a test project or a companion project of the same product, grant it access to the internals of the defining project with the `InternalsVisibleTo` assembly attribute.
* If you own the interface and want other projects to implement it, remove the `[InternalOnlyImplement]` attribute.
