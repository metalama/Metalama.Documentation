# LAMA0654: An overridden record member reads a property that the compiler reads through its backing field

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Framework |
| **Message** | `The original implementation of '<Member>' generated for record '<RecordType>' reads the property '<Property>', whereas the C# compiler reads its backing field. The property is declared with the 'field' keyword and its getter has a body, so the getter can return a value other than the one that the backing field holds, and the two implementations then differ. Declare the property explicitly with a backing field, or give it an automatic getter.` |

## Cause

The C# compiler generates the `Equals` and `GetHashCode` methods of a record. These generated methods compare the backing fields of the properties, not the properties themselves. When an aspect overrides one of these methods, for instance with <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceMethod*> and <xref:Metalama.Framework.Aspects.OverrideStrategy>, Metalama must write the original implementation as source code so that the aspect can call it with <xref:Metalama.Framework.Aspects.meta.Proceed*?text=meta.Proceed()>. Source code can't name the compiler-generated backing field of a property declared with the `field` keyword, so Metalama reads the property instead.

When the getter of such a property returns something else than the backing field, the original implementation that Metalama writes isn't the one that the compiler generates: it compares the values returned by the getter, not the values stored in the fields. Metalama reports LAMA0654 on the property. In the message, `<Member>` is the overridden method, `<RecordType>` is the record, and `<Property>` is the property.

Metalama doesn't report the warning when the getter is automatic, or when its body only returns `field`.

## Resolution

Make sure that reading the property is the same as reading its backing field:

* Give the property an automatic getter, and move the logic to the setter or to another member.
* Declare the property explicitly with a backing field of your own.
