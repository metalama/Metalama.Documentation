# LAMA0054: The project references an unsupported version of Metalama.Framework

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The project references the following version(s) of Metalama.Framework: <SelectedVersions>. The project must reference a single version of Metalama.Framework, and this version must not be higher than '<SupportedVersion>', the version of the Metalama engine that compiles the project.` |

## Cause

The `Metalama.Framework` package contains both the `Metalama.Framework` assembly, which your project references, and the Metalama engine, which transforms your project during compilation. The engine can only process code written against its own version of `Metalama.Framework` or an older one.

Before it transforms the project, Metalama checks the references of the compilation to the `Metalama.Framework` assembly, and reports LAMA0054 in the following situations:

* The compilation references several versions of the `Metalama.Framework` assembly.
* The compilation references a version of `Metalama.Framework` that's higher than the version of the engine.

In the message, `<SelectedVersions>` lists the versions of `Metalama.Framework` referenced by the project, and `<SupportedVersion>` is the version of the engine. Metalama doesn't transform the project.

This situation shouldn't happen when the project references `Metalama.Framework` only with a `PackageReference`, because the assembly and the engine then come from the same package. It typically comes from a direct reference to a `Metalama.Framework.dll` file, for instance with a `Reference` item and a `HintPath`, whose version doesn't match the package.

This diagnostic depends on the references and package versions of the project, so it can't be shown in an example.

## Resolution

1. Check the versions given in the message.
2. Remove any direct reference to a `Metalama.Framework.dll` file, and reference `Metalama.Framework` only through a `PackageReference`.
3. Align the version of all `Metalama.*` packages across the projects of the solution, for instance with [central package management](https://learn.microsoft.com/nuget/consume-packages/central-package-management).
4. Rebuild the project.
