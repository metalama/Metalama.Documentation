# LAMA0550: The Initialize method of a non-sealed class must be public and virtual

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot add an initializer to the 'Initialize' method of type '<TargetType>' because the method is not both 'public' and 'virtual' (or 'override'). Since '<TargetType>' is not sealed, its 'Initialize' method must be 'public virtual' so that derived types can extend the initialization. Make the method 'public virtual', or make the type 'sealed'.` |

## Cause

When an aspect calls <xref:Metalama.Framework.Aspects.AdviserExtensions.AddInitializer*> with <xref:Metalama.Framework.Advising.InitializerKind.AfterObjectInitializer>, Metalama adds the aspect's code to the `Initialize( InitializationContext )` method of the target type, which implements <xref:Metalama.Framework.RunTime.Initialization.IInitializable>. Metalama calls this method after the object initializer. If the target type doesn't have an `Initialize` method, Metalama introduces one, and makes it `public virtual` when the type isn't sealed. If the type already has a hand-written `Initialize( InitializationContext )` method, Metalama adds the aspect's code to this method.

In a class that isn't sealed, a derived class must be able to override `Initialize` and call `base.Initialize(...)`, so that the initialization logic of all levels of the hierarchy runs. Metalama reports LAMA0550 when the hand-written `Initialize` method of a non-sealed class isn't `public`, or is neither `virtual` nor `override`.

## Resolution

Do one of the following:

* Make the `Initialize` method `public virtual`, or `public override` if it overrides a base implementation.
* If the class isn't meant to be derived from, mark it as `sealed`.
* Remove the hand-written `Initialize` method and let Metalama introduce it.
