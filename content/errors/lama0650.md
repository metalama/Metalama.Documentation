# LAMA0650: The base implementation can't be invoked on another instance

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot invoke the base implementation of '<Member>' on an instance other than 'this', because C# allows base calls only on the current instance. Use InvokerOptions.Final to invoke the member on another instance.` |

## Cause

In a template, you can invoke a member through an invoker and choose which implementation is called with <xref:Metalama.Framework.Code.Invokers.InvokerOptions>. With <xref:Metalama.Framework.Code.Invokers.InvokerOptions.Base?text=InvokerOptions.Base>, Metalama calls the implementation that precedes the current aspect layer. When this implementation is inherited from a base class, or when the member overrides or hides a base member, Metalama must generate a `base.Member(...)` access.

C# allows `base` access only on the current instance. Metalama reports LAMA0650 when you combine `InvokerOptions.Base` with `WithObject`, so that the member would be invoked on another object, such as a parameter. The `<Member>` placeholder is the invoked member.

In the following example, the `LogComparison` aspect invokes the base implementation of `Vehicle.Describe` on the `other` parameter.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0650/LAMA0650_Error.cs name="Error"]

## Resolution

Do one of the following:

* Use `InvokerOptions.Final`, or omit `WithOptions`, to call the final implementation of the member on the other instance. This generates an ordinary call, such as `other.Describe()`, which goes through virtual dispatch.
* If you really need the base implementation, invoke the member on the current instance instead of another object.
