# LAMA5107: Several overloads of the method to invalidate are suitable

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Caching |
| **Message** | `Invalid [InvalidateCache] aspect on '<InvalidatingMethod>': there are several suitable overloads of the '<MethodName>' method. Set the AllowMultipleOverloads property to true to invalidate all of them.` |

## Cause

The <xref:Metalama.Patterns.Caching.Aspects.InvalidateCacheAttribute?text=[InvalidateCache]> aspect identifies the cached methods by name only. When several overloads have this name, the aspect considers an overload _suitable_ if it's cached and if each of its parameters, except those marked with <xref:Metalama.Patterns.Caching.NotCacheKeyAttribute?text=[NotCacheKey]>, matches a parameter of the invalidating method by name and type.

To prevent you from invalidating more methods than you intended, Metalama reports LAMA5107 when more than one overload is suitable and the <xref:Metalama.Patterns.Caching.Aspects.InvalidateCacheAttribute.AllowMultipleOverloads> property isn't set to `true`. In the message, `<InvalidatingMethod>` is the invalidating method and `<MethodName>` is the name of the overloaded method.

In the following example, both overloads of `GetProducts` are cached, and the parameters of both can be matched with the parameters of `AddProduct`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA5107/LAMA5107_Error.cs name="Error"]

## Resolution

* If you want to invalidate all suitable overloads, set the `AllowMultipleOverloads` property to `true`, as in the following example.
* If you want to invalidate only one overload, rename the cached methods so that each of them has a distinct name, and pass the name of the method you want to invalidate.
