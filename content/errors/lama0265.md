# LAMA0265: Static interface members can't be accessed on a compile-time type parameter

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Accessing the static interface member '<Member>' is not supported on the compile-time template type parameter '<TypeParameter>'. Call a run-time generic method that accesses the member instead, or make the type parameter run-time.` |

## Cause

A template method can have compile-time type parameters, marked with the <xref:Metalama.Framework.Aspects.CompileTimeAttribute?text=[CompileTime]> attribute. When Metalama expands the template, it replaces each compile-time type parameter with the type passed by the aspect, for instance `int`.

When a type parameter is constrained to an interface with static abstract members, like `INumber<T>`, C# lets you access these members through the type parameter, for instance `T.Zero`. Metalama doesn't support this syntax when `T` is a compile-time template type parameter, and reports LAMA0265. In the message, `<Member>` is the name of the member and `<TypeParameter>` is the type parameter.

In the following example, the `PrintZero` template accesses `T.Zero`, where `T` is a compile-time type parameter.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0265/LAMA0265_Error.cs name="Error"]

## Resolution

Do one of the following:

* Move the access to a run-time generic helper method, and call this method from the template with `T` as the type argument. The generated code calls the helper with the actual type.
* Remove the `[CompileTime]` attribute from the type parameter. The introduced method then becomes a generic method, and the static member is accessed at run time.
