# LAMA0521: The custom attribute is already present on the declaration

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce the custom attribute '<AttributeType>' into '<TargetDeclaration>' because this attribute is already present on the declaration. To keep or replace the existing attribute, set the 'whenExists' parameter to 'Ignore' or 'Override'.` |

## Cause

The <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceAttribute*> advice adds a custom attribute to a declaration. Its `whenExists` parameter, of type <xref:Metalama.Framework.Aspects.OverrideStrategy>, determines what happens when the declaration already has an attribute of the same type. The default value, `OverrideStrategy.Default`, is the same as `OverrideStrategy.Fail`.

Metalama reports LAMA0521 when the declaration already has an attribute of the type being introduced, whether written in source code or added by another aspect, and `whenExists` is `Fail` or `Default`. Metalama compares only the attribute type, not the constructor arguments.

In the following example, the `DefaultDebuggerDisplay` aspect adds a `[DebuggerDisplay]` attribute to each target class, but the `Product` class already has one.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0521/LAMA0521_Error.cs name="Error"]

## Resolution

Decide how the aspect handles an existing attribute, and pass the corresponding `whenExists` argument to `IntroduceAttribute`:

* `OverrideStrategy.Ignore` keeps the existing attribute and skips the introduction. Use it when the attribute written by the user should win. The following example shows this fix: `Product` keeps its own `[DebuggerDisplay]` attribute, and `Customer` receives the default one.
* `OverrideStrategy.Override` removes the existing attributes of this type and adds the new one.
* `OverrideStrategy.New` adds the attribute even if one already exists. Use it only for attribute types that allow multiple instances (`AllowMultiple = true`).

Alternatively, remove the attribute from the declaration, or don't apply the aspect to it.
