# LAMA0020: The type can't be found

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | ``Cannot find the type '<TypeName>' of assembly '<AssemblyName>' in the project or its references. Use the reflection name of the type: separate nested types with '+', and write generic types with a backtick followed by the number of type parameters, for example 'System.Collections.Generic.List`1'.`` |

## Cause

Metalama reports LAMA0020 when compile-time code, such as a template or a `BuildAspect` method, asks for a type that doesn't exist in the compilation of the target project or in its references. In the message, `<TypeName>` is the requested type name and `<AssemblyName>` is the assembly expected to contain it. When the type is requested by name only, the assembly is unknown and `<AssemblyName>` is empty.

The most common causes are:

* You pass a type name to <xref:Metalama.Framework.Code.TypeFactory.GetType*>, but the name isn't a valid _reflection name_. Reflection names differ from C# names: nested types are separated from their parent with `+`, and generic types are written with a backtick and the number of type parameters, without type arguments.
* The type name is misspelled, or it lacks its namespace.
* The type exists in the assembly that compiled your aspect, but not in the version of this assembly referenced by the target project.

In the following example, the `Log` aspect looks up the nested `Logging.ConsoleLogger` class using a `.` instead of a `+`.

## Resolution

* Pass the reflection name of the type, as in the following example. To check a name, look at the value of `typeof(T).FullName`.
* When the type is known when you write the aspect, prefer passing `typeof(T)` to `TypeFactory.GetType` instead of a string.
* If the type is optional, use `TypeFactory.TryGetType` and handle the case where the type doesn't exist.
* If the type comes from a package, make sure that the target project references a version of the package that contains the type.
