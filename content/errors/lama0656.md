# LAMA0656: The Initialize method isn't called in an expression tree

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Framework |
| **Message** | `The 'Initialize' method of '<Type>' is not called after this object creation expression, because the expression is in a lambda expression converted to an expression tree, and an expression tree cannot contain this call.` |

## Cause

When an aspect adds an initializer of kind <xref:Metalama.Framework.Advising.InitializerKind.AfterObjectInitializer>, the target type implements <xref:Metalama.Framework.RunTime.Initialization.IInitializable>. Metalama rewrites every object creation expression of this type, such as `new Document { Title = title }`, so that it calls the <xref:Metalama.Framework.RunTime.Initialization.IInitializable.Initialize*> method after the object initializer.

An expression tree can't contain this call. When the object creation expression is in a lambda expression converted to an expression tree (<xref:System.Linq.Expressions.Expression`1>), Metalama keeps the expression unchanged and reports LAMA0656 on it. The created object isn't initialized: the code that the aspect adds to `Initialize` doesn't run for this object. This situation is common with <xref:System.Linq.IQueryable`1> and with query providers such as Entity Framework, whose methods receive their lambda expressions as expression trees. It also applies to the lambda expressions that the compiler generates for a query expression, such as `from title in titles select new Document { Title = title }`. In the message, `<Type>` is the type of the created object.

Lambda expressions converted to a delegate aren't affected. Metalama rewrites the object creation expressions that they contain.

## Resolution

Create the object in a method, and call this method from the lambda expression. The expression tree then contains a method call, which is allowed, and Metalama rewrites the object creation expression in the method so that it calls `Initialize`.

The query provider must be able to evaluate the call to your method. Check that your provider supports a call to a method of your code in this position of the query.
