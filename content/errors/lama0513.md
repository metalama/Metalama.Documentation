# LAMA0513: The type arguments of the generic interface aren't specified

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot implement interface type '<InterfaceType>' in the type '<TargetType>' because it is a canonical generic instance. Specify all type arguments of the generic interface type. If needed, use type parameters of the target type.` |

## Cause

A type can only implement a constructed generic interface, such as `IEquatable<Product>`, where every type argument is known. When you pass an unbound generic type such as `typeof(IEntity<>)` to <xref:Metalama.Framework.Aspects.AdviserExtensions.ImplementInterface*>, Metalama receives the _canonical generic instance_ of the interface, whose type arguments are its own type parameters, for instance `IEntity<T>`. This type can't be added to the base list of the target type.

Metalama reports LAMA0513 when the interface passed to `ImplementInterface` is such a canonical generic instance.

In the following example, the `Entity` aspect passes `typeof(IEntity<>)` without a type argument.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0513/LAMA0513_Error.cs name="Error"]

## Resolution

Specify all type arguments of the interface:

* If the type arguments are known in advance, pass a closed type such as `typeof(IEntity<Customer>)`.
* Otherwise, build the constructed type with the code model: get the generic interface with `GetNamedTypeByReflectionType` and call `MakeGenericInstance` with the type arguments, for instance the target type itself. If the target type is generic, you can pass its type parameters.
