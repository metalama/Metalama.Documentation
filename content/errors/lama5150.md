# LAMA5150: The OnPropertyChanged method is missing or can't be overridden

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Observability |
| **Message** | `The class '<Class>' implements the PropertyChanged event, but neither it nor its base classes define an overridable 'void OnPropertyChanged(string)' or 'void OnPropertyChanged(PropertyChangedEventArgs)' method. The method must be public or protected, virtual or override, and not sealed. It can also be named 'NotifyOfPropertyChange' or 'RaisePropertyChanged'.` |

## Cause

When the <xref:Metalama.Patterns.Observability.ObservableAttribute?text=[Observable]> aspect is applied to a class that already has a `PropertyChanged` event, either declared in the class or inherited from a base class, the aspect doesn't introduce its own event. Instead, it reuses the existing implementation, which requires an `OnPropertyChanged` method that the aspect can override to react to the notifications raised by the base class.

Metalama reports LAMA5150 when neither the class nor its base classes define such a method. The aspect looks for a method that:

* is named `OnPropertyChanged`, `NotifyOfPropertyChange`, or `RaisePropertyChanged`;
* is an instance method that returns `void` and is `public` or `protected`;
* is `virtual` or `override`, and not `sealed`;
* takes a `string` or a <xref:System.ComponentModel.PropertyChangedEventArgs> as its parameter.

Typical causes are a base class whose `OnPropertyChanged` method isn't `virtual` or is `private`, and a base class that raises the `PropertyChanged` event directly without any helper method.

## Resolution

Add a suitable method to the base class, or change the existing one:

* Make the existing `OnPropertyChanged` method `virtual`, and `protected` or `public`.
* If the base class raises the `PropertyChanged` event directly, add a `protected virtual` `OnPropertyChanged` method with a `string` parameter that raises the event, and call it from the existing code.
* If you can't change the base class, for instance because it belongs to a third-party library, remove the `[Observable]` aspect from the derived class and implement <xref:System.ComponentModel.INotifyPropertyChanged> manually.

The aspect also needs a method with a single `string` parameter to _raise_ notifications. When the overridable method takes a `PropertyChangedEventArgs`, make sure that the class also has such a method, otherwise Metalama reports another error.
