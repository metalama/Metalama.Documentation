# LAMA0891: A mutable static field of an aspect must be marked [RunTime]

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Framework |
| **Message** | `'<Type>' is a run-time-or-compile-time type, but the static member '<Member>' <Cause>. A static field of a type that is loaded at compile time is shared by every aspect instance, every target and every compilation, and at design time it keeps its value for as long as the analysis process runs. Mark the member with [RunTime] so that it exists only at run time, or make it read-only and of an immutable type.` |

## Cause

A run-time-or-compile-time type exists both in your program and in the compile-time assembly that Metalama loads into the compiler and IDE processes. Aspects are run-time-or-compile-time types, and so are the types marked with <xref:Metalama.Framework.Aspects.RunTimeOrCompileTimeAttribute?text=[RunTimeOrCompileTime]>. At compile time, a static field of such a type is shared by every aspect instance, every target, and every compilation that the process handles, just like a static field of a compile-time type (see <xref:lama0889?text=LAMA0889>).

Metalama reports LAMA0891 on a static field, static automatic property, or static field-like event of a run-time-or-compile-time type when the member isn't marked `[RunTime]` and either:

* isn't read-only: the field isn't `readonly` or `const`, the property has a setter or an `init` accessor, or the member is an event, or
* is read-only but of a type that isn't immutable, for instance `List<T>`, `Dictionary<TKey, TValue>`, or an array.

`<Cause>` says which of the two applies: `is not read-only`, or `is of type '<MemberType>', which is not immutable (path: <Path>)`, where the path explains why the type isn't immutable. The rules for immutable types are those of <xref:lama0890?text=LAMA0890>. Template members and introduced members aren't reported, and neither is a member whose own type is run-time-only.

## Resolution

Choose one of the following options:

* If the value never changes, make the member read-only and of an immutable type: add the `readonly` modifier or remove the setter, and replace a mutable type such as `List<T>` with `ImmutableArray<T>`. The following example uses this fix.
* If only run-time code uses the member, mark it with <xref:Metalama.Framework.Aspects.RunTimeAttribute?text=[RunTime]>. Metalama then removes it from the compile-time assembly, so it can't be shared between compilations. Compile-time code, such as `BuildAspect`, can no longer access it. The initializer of the member is still validated as code that can run at compile time, so it can't reference run-time-only declarations such as `Console` (<xref:lama0236?text=LAMA0236>). Assign such a value from run-time code instead.
* If the member holds state that varies between targets, don't keep it in a static member. Use the properties of the aspect or aspect options instead.

The `[RunTime]` option exists only for run-time-or-compile-time types. In a compile-time type, a run-time member is an error (<xref:lama0292?text=LAMA0292>), which is why <xref:lama0889?text=LAMA0889> and <xref:lama0890?text=LAMA0890> don't suggest it.
