# LAMA0039: A child aspect is added to an ineligible declaration

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The <Predecessor> cannot add a child aspect of type '<AspectType>' to '<Child>' because <Reason>.` |

## Cause

Fabrics and aspects can add aspects to other declarations programmatically, typically by selecting declarations with a query and calling its `AddAspect` method. The added aspects are called _child aspects_. Like any aspect, a child aspect can define eligibility conditions in its `BuildEligibility` method.

Metalama reports LAMA0039 when `AddAspect` selects a declaration that doesn't satisfy the eligibility conditions of the child aspect. The diagnostic is reported on the fabric or on the parent aspect. In the message, `<Predecessor>` describes the parent fabric or aspect, `<AspectType>` is the child aspect, `<Child>` is the ineligible declaration, and `<Reason>` explains which condition failed.

When you apply an aspect directly with a custom attribute, the same situation is reported as <xref:lama0037>.

In the following example, the `Log` aspect requires an instance method, but the fabric adds it to all methods of the `Calculator` class, including a static method.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0039/LAMA0039_Error.cs name="Error"]

## Resolution

Depending on your intent, do one of the following:

* Replace `AddAspect` with `AddAspectIfEligible`, which silently skips the declarations that aren't eligible. The following example uses this approach.
* Filter the query with `Where` so that it selects only eligible declarations, for instance `Where( m => !m.IsStatic )`.
* If you're the author of the child aspect and the condition is too strict, relax it in the aspect's `BuildEligibility` method.
