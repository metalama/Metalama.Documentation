# LAMA0200: The compile-time value can't be converted to a run-time value

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `A compile-time value cannot be converted to a run-time value because the type '<Type>' is not supported. Use a supported type or a type that implements the IExpressionBuilder interface.` |

## Cause

When a template uses a compile-time value in a run-time context, for instance in a `return` statement, as an argument of a run-time method, or in a call to <xref:Metalama.Framework.Aspects.meta.RunTime*?text=meta.RunTime>, Metalama evaluates the value at compile time and generates C# code that creates an equivalent value at run time. This conversion is only possible for a limited set of types: literals, enums, one-dimensional arrays, tuples, reflection objects, `List<T>`, `Dictionary<TKey, TValue>`, and a few others. It's also possible for any type that implements the <xref:Metalama.Framework.Code.SyntaxBuilders.IExpressionBuilder> interface.

Metalama reports LAMA0200 when it compiles the template and finds that the type of the value isn't supported. It checks the type arguments and array element types too, so `<Type>` can be a type argument rather than the type of the whole value: for a `Dictionary<string, MethodOverloadCount>`, `<Type>` is `MethodOverloadCount`.

In the following example, the aspect computes a dictionary of `MethodOverloadCount` objects at compile time and returns it from an introduced method. The `MethodOverloadCount` class exists at both compile time and run time, but Metalama doesn't know how to generate the code that creates an instance of it.

## Resolution

Do one of the following:

* If you own the type, implement the <xref:Metalama.Framework.Code.SyntaxBuilders.IExpressionBuilder> interface. Its <xref:Metalama.Framework.Code.SyntaxBuilders.IExpressionBuilder.ToExpression> method returns a C# expression that creates an equivalent value at run time. Use the <xref:Metalama.Framework.Code.SyntaxBuilders.ExpressionBuilder> class to build it.
* Convert the value to a supported type before you use it in run-time code, for instance a list of strings or a tuple.
* Use only the supported members of the value, for instance a `string` property, instead of the whole object.

In the following example, `MethodOverloadCount` implements <xref:Metalama.Framework.Code.SyntaxBuilders.IExpressionBuilder>, so Metalama generates a call to its constructor for each item of the dictionary.
