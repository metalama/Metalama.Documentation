# LAMA0516: The override strategy isn't supported for interfaces

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot implement the interface '<InterfaceType>' in the type '<TargetType>' because the strategy 'whenExists=<Strategy>' is not supported for interfaces. Use Fail, Ignore, or Override. To handle conflicts with individual members, use the WhenExists property of the [InterfaceMember] attribute.` |

## Cause

The `whenExists` parameter of <xref:Metalama.Framework.Aspects.AdviserExtensions.ImplementInterface*> determines what Metalama does when the target type, or one of its base types, already implements the interface. It accepts only the following values of <xref:Metalama.Framework.Aspects.OverrideStrategy>:

* `Fail` (the default): Metalama reports an error.
* `Ignore`: the advice is ignored.
* `Override`: the members of the interface are implemented again, overriding existing members when necessary.

Metalama reports LAMA0516 for any other value, which in practice means `OverrideStrategy.New`: an interface implementation can't be redefined with the `new` modifier.

In the following example, the `Describable` aspect passes `OverrideStrategy.New` to `ImplementInterface`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0516/LAMA0516_Error.cs name="Error"]

## Resolution

Pass `OverrideStrategy.Fail`, `OverrideStrategy.Ignore`, or `OverrideStrategy.Override` to `ImplementInterface`. `Ignore` is the most common choice: it skips the interface when the type already implements it.

To control what happens when the target type already contains a member with the same signature as an interface member, use the <xref:Metalama.Framework.Aspects.InterfaceMemberAttribute.WhenExists> property of the `[InterfaceMember]` attribute instead.
