# LAMA0071: The type arguments of a generic method can't be inferred

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot infer the type arguments for method '<Method>'. Supply the type arguments explicitly using IMethod.MakeGenericInstance.` |

## Cause

When a template gets a generic method from the code model, for instance with `meta.Target.Type.Methods.OfName( ... )`, the <xref:Metalama.Framework.Code.IMethod> represents the generic method _definition_: its type arguments are still its type parameters, such as `T`. When you call `Invoke` on this method, Metalama must decide which type arguments to generate in the invocation.

Metalama tries to infer each type argument from the types of the arguments that you pass to `Invoke`, by matching them with the types of the parameters. Metalama reports LAMA0071 when this inference fails, for instance because:

* A type parameter doesn't appear in the types of the parameters that receive an argument.
* The arguments give conflicting types for the same type parameter, for instance `int` and `string`.
* A parameter has a generic type, such as `List<T>`, and the argument has a different generic type, such as `HashSet<int>`.

In the message, `<Method>` is the generic method. The error is located on the declaration to which the aspect is applied.

In the following example, the `Audit` aspect invokes the generic method `WriteAudit<TCategory>( string operation )`, but `TCategory` can't be inferred from a `string` argument.

## Resolution

Supply the type arguments explicitly by calling <xref:Metalama.Framework.Code.IMethod.MakeGenericInstance*> on the method before invoking it. Extension methods of `GenericExtensions` add overloads that accept a list of <xref:Metalama.Framework.Code.IType> or `System.Type` arguments. The `WithTypeArguments` methods suggested by older versions of Metalama are obsolete. In the following example, the aspect passes the target type as the type argument.

If the arguments should allow the inference, check that their types match the types of the parameters.
