# LAMA0902: The naming convention pattern isn't a valid regular expression

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Extensions.Architecture |
| **Message** | `The string '<Pattern>' is not a valid regular expression: <ErrorMessage>` |

## Cause

The <xref:Metalama.Extensions.Architecture.Aspects.DerivedTypesMustRespectRegexNamingConventionAttribute> aspect enforces a naming convention on all types derived from the target type. Its pattern is a .NET regular expression.

Before it validates the derived types, the aspect parses the pattern. If parsing fails, Metalama reports LAMA0902 on the target type and skips the aspect, so the naming convention isn't enforced. In the message, `<Pattern>` is the pattern and `<ErrorMessage>` is the error returned by the .NET regular expression parser.

A frequent cause is passing a star pattern, such as `*Service`, which is the syntax of <xref:Metalama.Extensions.Architecture.Aspects.DerivedTypesMustRespectNamingConventionAttribute>. In a regular expression, `*` must follow the expression it repeats.

In the following example, the `[DerivedTypesMustRespectRegexNamingConvention]` attribute receives the star pattern `*Service`.

## Resolution

Do one of the following:

* Fix the regular expression, using the error given in the message. For instance, write `^.*Service$` instead of `*Service`, as in the following example.
* If a star pattern is enough, use the `[DerivedTypesMustRespectNamingConvention]` attribute instead, where `*` matches any sequence of characters.
