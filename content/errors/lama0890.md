# LAMA0890: A static field of a compile-time type must be of an immutable type

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Framework |
| **Message** | `'<Type>' is a compile-time type, but the static member '<Member>' is of type '<MemberType>', which is not immutable. A static field of a compile-time type is shared by every aspect instance, every target and every compilation, and at design time it keeps its value for as long as the analysis process runs. Use an immutable type, such as an immutable collection. Path: <Path>.` |

## Cause

A static field of a compile-time type is shared by every aspect instance, every target, and every compilation that the compiler or IDE process handles (see <xref:lama0889?text=LAMA0889>). The `readonly` modifier prevents only the reassignment of the field. If the type of the field is mutable, such as `List<string>`, `Dictionary<string, int>`, or an array, any code can still change the object that the field references, and the change leaks into the following compilations.

Metalama reports LAMA0890 on a static field or static automatic property of a compile-time type that is read-only but whose type isn't immutable. A type is immutable when it's a primitive type, `string`, an enum, a delegate, an immutable collection such as `ImmutableArray<T>` or `ImmutableDictionary<TKey, TValue>`, another well-known immutable type, a type marked with `[ImmutableType]`, or a type declared immutable with a `MetalamaImmutableType` item in the project file. Nullable types and tuples are immutable when their components are. Arrays, `object`, and `dynamic` are never immutable.

In the message, `<Type>` is the compile-time type, `<Member>` is the member, `<MemberType>` is its type, and `<Path>` is the chain from `<Type>` to the mutable type, followed by the reason why that type isn't immutable. A member that isn't read-only is reported only once, with <xref:lama0889?text=LAMA0889>.

## Resolution

Choose one of the following options:

* Replace the mutable type with an immutable one: `ImmutableArray<T>` instead of `List<T>` or an array, `ImmutableDictionary<TKey, TValue>` instead of `Dictionary<TKey, TValue>`, or `ImmutableHashSet<T>` instead of `HashSet<T>`. The following example uses `ImmutableArray<string>`.
* If the type is yours and is immutable, mark it with `[ImmutableType]`. Metalama then verifies the type itself.
* If the type isn't yours and you know that it's immutable, declare it with a `MetalamaImmutableType` item in the project file (see <xref:lama0885?text=LAMA0885>).
* If the member is deliberately a thread-safe cache whose values don't depend on the compilation, suppress the warning with `#pragma warning disable LAMA0890` around the declaration.
