# LAMA1001: The interception scope is not valid

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Extensions.Interceptors |
| **Message** | `The <Source> cannot use the <ScopeKind> '<Scope>' as an interception scope. A scope must be a namespace, a type, a member or the compilation, and it must be declared in the source code of the current project.` |

## Cause

Metalama.Extensions.Interceptors lets an aspect or a fabric replace the calls to selected methods, in the source code of the current project, with calls to other methods. An aspect or fabric registers an interceptor with the `InterceptMethods` method of its adviser, builder, or amender. The declaration on which you call this method is the _interception scope_: only the calls located inside this declaration are intercepted.

A scope must be a namespace, a type, a member (method, constructor, property, indexer, field or event) or the compilation. Other declarations, such as parameters and type parameters, can't be scopes. The scope must also be declared in the source code of the current project, because Metalama can intercept only the calls that exist in this source code. A type from a referenced assembly, such as `Console`, can't be a scope.

Metalama reports LAMA1001 when a query or adviser returns a declaration that doesn't satisfy these rules. In the message, `<Source>` describes the aspect or fabric, `<ScopeKind>` is the kind of the declaration, and `<Scope>` is the declaration.

## Resolution

Select a scope that is declared in your project: a namespace, a type, a member or the whole compilation. To intercept the calls to a method of a referenced assembly, register the interceptor on the declaration that contains the calls, and name the intercepted method with the `Type` and `Methods` methods of the interception builder.
