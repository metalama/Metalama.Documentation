# LAMA0293: A template with a try-catch block can't override an async iterator

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectName>' cannot override the async iterator method '<TargetMethod>' because the expanded template contains 'yield return' inside a try block with a catch clause, which is not allowed by C#. Use a dedicated async iterator template or restructure the template to avoid wrapping 'meta.Proceed()' in a try-catch block.` |

## Cause

When an aspect overrides an async iterator method, that is, an `async` method that returns `IAsyncEnumerable<T>` or `IAsyncEnumerator<T>` and uses `yield return`, and the aspect doesn't provide a dedicated template for async iterators, Metalama applies the default <xref:Metalama.Framework.Aspects.OverrideMethodAspect.OverrideMethod> template, or the <xref:Metalama.Framework.Aspects.OverrideMethodAspect.OverrideAsyncMethod> template, and interprets it as an async iterator. The result of `meta.Proceed()` is buffered, and each `return` statement of the template becomes a loop of `yield return` statements.

C# doesn't allow a `yield return` statement inside a `try` block that has a `catch` clause, nor inside the `catch` or `finally` blocks of such a statement. Metalama reports LAMA0293 when the expanded template would contain such a statement, typically because the template wraps `meta.Proceed()` and the `return` statement in a try-catch block. The first placeholder of the message is the aspect, and the second is the overridden method.

## Resolution

Do one of the following:

* Implement the <xref:Metalama.Framework.Aspects.OverrideMethodAspect.OverrideAsyncEnumerableMethod> template, or <xref:Metalama.Framework.Aspects.OverrideMethodAspect.OverrideAsyncEnumeratorMethod> for `IAsyncEnumerator<T>`, and enumerate <xref:Metalama.Framework.Aspects.meta.ProceedAsyncEnumerable> without a try-catch block around `yield return`. The default template remains in use for the other methods. This approach also streams the items instead of buffering them.
* Restructure the default template so that `meta.Proceed()` and the `return` statement aren't inside a try-catch block. A `try` block with only a `finally` clause is allowed.
* Exclude async iterator methods from the targets of the aspect, for instance with an eligibility condition.
