# LAMA1010: A call can't have more than one interceptor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Extensions.Interceptors |
| **Message** | `The <Site> is intercepted by more than one interceptor: <Sources>. At most one interceptor can apply to a call site.` |

## Cause

Metalama.Extensions.Interceptors lets aspects and fabrics replace the calls to selected methods with calls to other methods. A call can be replaced only once, so at most one interceptor can apply to a given call.

Metalama evaluates every registration whose scope and selection contain the call. A registration can decline the call, for instance with `Skip` in a `ForEachSite` delegate. Metalama reports LAMA1010 when more than one registration returns an interceptor instead of declining. It doesn't matter whether the registrations come from different aspects, from an aspect and a fabric, from several instances of the same aspect, or from the same fabric. In that case, Metalama doesn't intercept the call.

In the message, `<Site>` describes the call, and `<Sources>` lists the aspects and fabrics whose registrations returned an interceptor.

## Resolution

Make sure that a single registration intercepts each call:

* Remove one of the registrations, or merge them into one interceptor. The following example keeps a single registration.
* Narrow the scope of the registrations, so that they no longer overlap.
* In a `ForEachSite` delegate, return `Skip` for the calls that another registration must handle.
