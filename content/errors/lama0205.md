# LAMA0205: The non-serializable base type has no parameterless constructor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot generate a compile-time serializer for '<Type>' because the base type '<BaseType>' is not compile-time serializable and does not have a public or protected parameterless constructor. Make '<BaseType>' implement ICompileTimeSerializable, or add a public or protected parameterless constructor to it.` |

## Cause

When Metalama builds the compile-time code of a project, it generates a serializer and a _deserializing constructor_ for every type that implements <xref:Metalama.Framework.Serialization.ICompileTimeSerializable> and doesn't have a manual serializer. When the base type of such a type isn't itself serializable, Metalama doesn't serialize the state of the base type, and the generated deserializing constructor calls the parameterless constructor of the base type.

Metalama reports LAMA0205 when the type `<Type>` implements <xref:Metalama.Framework.Serialization.ICompileTimeSerializable> but its base type `<BaseType>` doesn't, and `<BaseType>` has no public or protected parameterless constructor.

In the following example, the `LogCategory` class is serializable, but its base class `NamedItem` isn't, and the only constructor of `NamedItem` requires a name.

## Resolution

Do one of the following:

* Make the base type implement <xref:Metalama.Framework.Serialization.ICompileTimeSerializable>, so that Metalama also serializes its fields and properties. This is usually the right fix when the base type has state, like the `Name` property in the example.
* Add a public or protected parameterless constructor to the base type. After deserialization, the fields and properties of the base type then have the values set by this constructor, not the serialized ones.
* If you can't change the base type, write a manual serializer for the derived type, as described in <xref:aspect-serialization>.
