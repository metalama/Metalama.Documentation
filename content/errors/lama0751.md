# LAMA0751: An interface marked with [InternalImplement] is implemented outside its project

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Framework |
| **Message** | `The interface '<InterfaceType>' cannot be implemented by the type '<ImplementingType>' because of the [InternalImplement] constraint.` |

## Cause

The <xref:Metalama.Framework.Utilities.InternalImplementAttribute> custom attribute marks an interface that only the project declaring it, or a project that sees its internals, can implement. Metalama applies it to many of its own interfaces, such as the code model interfaces, so that it can add members to them in later versions without breaking your code.

LAMA0751 was meant to report a type that implements such an interface in violation of this constraint. However, the current version of Metalama defines this diagnostic but never reports it. When your code implements an interface marked with `[InternalImplement]`, Metalama reports the error <xref:lama0120> instead.

Because Metalama never reports this diagnostic, it can't be shown in an example.

## Resolution

You don't need to take any action for LAMA0751 itself. If you see <xref:lama0120>, don't implement the interface in your code. Use the implementations that Metalama provides, for instance through the code model or the factory methods of the API.
