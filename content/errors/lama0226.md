# LAMA0226: A construct can't combine run-time and compile-time elements

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `'<Symbol>' is invalid because '<RunTimeSymbol>' is run-time but '<CompileTimeSymbol>' is compile-time.` |

## Cause

Metalama assigns an execution scope to every type and member. _Compile-time_ types, like the code model types `IMethod` or `IParameter`, exist only while Metalama compiles the project. _Run-time_ types, like the classes of your project, exist only in the compiled program. Some types, like `string` or `Dictionary<TKey, TValue>`, are available in both scopes, and the scope of a generic type instance depends on its type arguments.

Metalama reports LAMA0226 when a construct depends on both a run-time-only element and a compile-time-only element, so that it can exist in neither scope. The most common cases are:

* a generic type or method instance whose type arguments include a run-time-only type and a compile-time-only type, for instance `Dictionary<IParameter, Customer>`, or a call to `meta.CompileTime` with a run-time type argument;
* a type that has both a run-time-only and a compile-time-only base type or interface.

The first placeholder of the message is the invalid construct, the second one is the run-time element, and the third one is the compile-time element.

## Resolution

Decide whether the construct is compile-time or run-time, and replace the elements of the other scope:

* For a run-time construct, replace the compile-time elements with run-time values. For instance, use the name of the parameter, a `string`, instead of the `IParameter`, as shown in the following example.
* For a compile-time construct, replace the run-time types with compile-time representations, for instance an `IType` or `IExpression` instead of a run-time type.
* For a type with conflicting base types, split it into a run-time type and a compile-time type.
