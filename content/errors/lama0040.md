# LAMA0040: A fabric must have a public parameterless constructor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The type '<Type>' must have a public parameterless constructor.` |

## Cause

Metalama creates the instances of some of your compile-time types itself:

* fabrics, that is, classes derived from `ProjectFabric`, `TransitiveProjectFabric`, `NamespaceFabric`, or `TypeFabric`;
* compiler plug-ins, such as aspect weavers, which are classes annotated with `[MetalamaPlugIn]`.

To create these instances, Metalama calls the public constructor that has no parameter. Metalama reports LAMA0040 when the type doesn't have such a constructor, for instance because its only constructor takes parameters or isn't public. In the message, `<Type>` is the name of the type. Metalama then ignores the fabric or the plug-in.

The diagnostic isn't attached to any location in the source code, so it appears without a file name in the error list.

In the following example, the fabric receives the name of the target type through a constructor parameter, so Metalama can't instantiate it.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0040/LAMA0040_Error.cs name="Error"]

## Resolution

Make sure that the type has a public parameterless constructor:

* Remove the constructor parameters, and define the values in the class itself, for instance as constants or fields with an initializer. The following example uses a constant.
* If the constructor isn't public, make it public, or remove it to let C# generate an implicit public constructor.
