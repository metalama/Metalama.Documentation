# LAMA0043: An aspect suggests a code fix

| | |
|---|---|
| **Severity** | Hidden |
| **Reported by** | Metalama.Extensions.CodeFixes |
| **Message** | `Code fix` |

## Cause

In Roslyn, a code fix must be attached to a diagnostic. When an aspect, a fabric, or a validator wants to offer a code fix without reporting any warning or error, it calls one of the `Suggest` extension methods of the `Metalama.Extensions.CodeFixes` package, for instance `builder.Diagnostics.Suggest( codeFix, declaration )`. Metalama then reports LAMA0043, defined by <xref:Metalama.Framework.Diagnostics.CodeFixHelper.SuggestionDiagnostic>, at the given location and attaches the code fix to it.

LAMA0043 has the `Hidden` severity: it doesn't appear in the error list and doesn't affect the build. Its only effect is that the IDE offers the code fix in the lightbulb or refactoring menu when the caret is on the declaration.

In the following example, the `Log` aspect suggests a code fix that excludes a method from logging. The snapshot shows the hidden diagnostics and the title of their code fixes.

## Resolution

LAMA0043 doesn't indicate a problem, so no resolution is needed. You can apply the suggested code fix from the IDE or ignore it.

The following example shows the code after you apply the code fix suggested for `GetBalance`. The method now has the `[NotLogged]` attribute, so the aspect no longer logs it and no longer suggests the code fix there.
