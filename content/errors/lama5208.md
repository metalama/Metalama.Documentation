# LAMA5208: A synchronous command method can't accept a CancellationToken

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Wpf |
| **Message** | `The '<Method>' method has a CancellationToken parameter, but it does not return a Task and the Background property of the [Command] attribute is not set to true.` |

## Cause

The <xref:Metalama.Patterns.Wpf.CommandAttribute?text=[Command]> aspect supports cancellation through a <xref:System.Threading.CancellationToken> parameter in the last position, for example `ExecuteAsync( CancellationToken cancellationToken )` or `ExecuteAsync( string query, CancellationToken cancellationToken )`. The token is supplied by an <xref:Metalama.Patterns.Wpf.AsyncDelegateCommand>, which the aspect generates in two cases:

* the method returns a <xref:System.Threading.Tasks.Task>;
* the <xref:Metalama.Patterns.Wpf.CommandAttribute.Background> property of the attribute is `true`.

A method that returns `void` and runs in the UI thread becomes a synchronous <xref:Metalama.Patterns.Wpf.DelegateCommand>, which can't be canceled. Metalama reports LAMA5208 on the target method when its last parameter is a `CancellationToken`, it returns `void`, and `Background` isn't `true`. The command property isn't generated.

In the message, `<Method>` is the target method.

In the following example, the `Search` method accepts a `CancellationToken`, but it returns `void` and runs in the UI thread.

## Resolution

Choose one of the following options:

* Make the method asynchronous: return `Task`, typically with the `async` modifier, and pass the token to the asynchronous operations you call.
* Keep the `void` method and run it in a background thread by setting `Background = true` in the attribute, for example `[Command( Background = true )]`.
* Remove the `CancellationToken` parameter if the command doesn't need to be canceled.
