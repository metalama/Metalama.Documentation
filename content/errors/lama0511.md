# LAMA0511: The [InterfaceMember] template doesn't have the type of the interface member

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot implement interface '<InterfaceType>' in the type '<TargetType>' because the aspect member '<DeclarativeIntroduction>', marked with the [InterfaceMember] attribute, does not have the same type or return type as the corresponding interface member '<InterfaceMember>'.` |

## Cause

When an aspect calls <xref:Metalama.Framework.Aspects.AdviserExtensions.ImplementInterface*>, Metalama looks in the aspect class for members marked with <xref:Metalama.Framework.Aspects.InterfaceMemberAttribute?text=[InterfaceMember]> that match each member of the interface by name and parameters. These members are the templates of the interface implementation.

Metalama reports LAMA0511 when such a template has the name and parameters of an interface member but not the same type: the return type of a method, or the type of a property or event. A different `ref` kind also triggers the error. The check applies to both implicit and explicit implementations. In the message, `<DeclarativeIntroduction>` is the aspect member and `<InterfaceMember>` is the interface member.

In the following example, the `Describe` template returns `object`, but `IDescribable.Describe()` returns `string`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0511/LAMA0511_Error.cs name="Error"]

## Resolution

Give the `[InterfaceMember]` template exactly the same type as the interface member. In the following example, the template returns `string`.
