# LAMA5006: The range contract is redundant for the type of the declaration

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Patterns.Contracts |
| **Message** | `The [<AspectType>] contract is redundant on '<Declaration>' because the value range <Range> is always satisfied by the type <TargetBasicType>.` |

## Cause

Range contracts, such as <xref:Metalama.Patterns.Contracts.RangeAttribute?text=[Range]>, <xref:Metalama.Patterns.Contracts.NonNegativeAttribute?text=[NonNegative]>, or <xref:Metalama.Patterns.Contracts.LessThanOrEqualAttribute?text=[LessThanOrEqual]>, check at run time that a value lies within a range. Metalama reports LAMA5006 when every bound of the range is at or beyond the limits of the numeric type of the field, property, or parameter, so that no value of the type can violate the contract. For instance, a `uint` can't be negative, and a `byte` is always within `[0, 255]`.

Because the check could never fail, Metalama doesn't generate it and ignores the contract. The message shows the range, where `∞` means that the range has no bound on that side, and the name of the type.

In the following example, the `[NonNegative]` contract is applied to a `uint` property.

## Resolution

Depending on your intent, do one of the following:

* Remove the contract, because the type already enforces the range. The following example shows this fix.
* If you meant a stricter condition, use a contract that expresses it, for instance <xref:Metalama.Patterns.Contracts.StrictlyPositiveAttribute?text=[StrictlyPositive]> to exclude zero, or narrow the bounds of the `[Range]` contract.
