# LAMA0556: A custom attribute can't be added to a compiler-synthesized member

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce a custom attribute on '<Member>' because the compiler synthesizes that member and there is no declaration on which to write the attribute.` |

## Cause

When an aspect introduces a type such as a record, the C# compiler synthesizes some of its members from the type declaration: for instance `PrintMembers`, `Equals`, `GetHashCode`, the copy constructor and the primary constructor of a record. These members are present in the code model, but they have no syntax of their own, so Metalama has no declaration on which to write an attribute.

Metalama reports LAMA0556 when an aspect calls <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceAttribute*> on such a member, instead of ignoring the attribute silently. The `<Member>` placeholder is the targeted member.

In the following example, the `GenerateRecord` aspect introduces a record and tries to add an attribute to its synthesized `PrintMembers` method.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0556/LAMA0556_Error.cs name="Error"]

## Resolution

Add the attribute to a declaration that exists in the source code:

* For a property that a positional parameter of a record declares, add the attribute to the property. Metalama writes it on the parameter with the `property:` target.
* For the type itself or for a member that you introduce explicitly, add the attribute to that declaration.
