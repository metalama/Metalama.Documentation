# LAMA0248: Compile-time code can't be unsafe

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `'<Declaration>' cannot contain unsafe code because it is <Scope> code.` |

## Cause

Metalama extracts your compile-time code, such as aspects, fabrics, and classes marked with [<xref:Metalama.Framework.Aspects.CompileTimeAttribute>], into a separate compile-time assembly. Metalama doesn't allow unsafe code in this compile-time code.

Metalama reports LAMA0248 when the declaration of a type or member whose scope isn't run-time-only has the `unsafe` modifier. This applies to compile-time declarations and to run-time-or-compile-time declarations. Aspect classes are run-time-or-compile-time, because <xref:Metalama.Framework.Aspects.IAspect> is. The first placeholder of the message is the declaration, and the second one is its scope, for instance `compile-time` or `run-time-or-compile-time`.

When the `unsafe` declaration is a template, for instance an `OverrideMethod` method, Metalama reports <xref:lama0249> instead.

In the following example, the `Log` aspect class has the `unsafe` modifier.

## Resolution

Remove the `unsafe` modifier from the compile-time declaration, and rewrite the code that needs it without pointers, for instance with `Span<T>` or with the methods of the `Unsafe` and `MemoryMarshal` classes.

If the unsafe code belongs to the run-time part of your project, move it to a run-time type that doesn't contain any compile-time code.
