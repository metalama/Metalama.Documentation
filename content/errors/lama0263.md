# LAMA0263: A lambda in a template can't return a dynamic expression

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Expression-bodied lambdas whose expression is of type 'dynamic' are not supported. Cast the expression to a non-dynamic type, for example 'object' or 'IExpression'. Alternatively, use a local function, or, for a void expression, a lambda with a block body.` |

## Cause

In a template, many expressions have the type `dynamic`, for instance the `Value` property of a parameter, <xref:Metalama.Framework.Aspects.meta.This?text=meta.This>, or the result of `meta.Proceed()`. When such an expression is the body of a lambda, the lambda returns `dynamic`, which can change the type of the surrounding expression, for instance the result of a LINQ `Select` call. Metalama doesn't support this case.

Metalama reports LAMA0263 for any lambda in a template whose expression body has the type `dynamic`. Lambdas with a block body aren't concerned.

In the following example, a lambda returns the value of the first parameter of the target method, which is `dynamic`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0263/LAMA0263_Error.cs name="Error"]

## Resolution

Do one of the following:

* Cast the body of the lambda to a non-dynamic type. In a run-time lambda, cast it to the type you need, for instance `object`, as in the following example. In a compile-time lambda, for instance in a `Select` call on `meta.Target.Parameters`, cast it to `IExpression`.
* Use a local function instead of the lambda.
* If the expression is `void`, use a lambda with a block body.
