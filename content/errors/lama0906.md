# LAMA0906: The declaration doesn't respect the naming convention set by a fabric

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Extensions.Architecture |
| **Message** | `The <DeclarationKind> '<Declaration>' does not respect the naming convention set by a fabric. The <DeclarationKind> name should match the "<Pattern>" pattern.` |

## Cause

In a fabric, you can select declarations and require their names to follow a convention with the <xref:Metalama.Extensions.Architecture.ArchitectureExtensions.MustRespectNamingConvention*> method, where `*` matches any substring, or with the `MustRespectRegexNamingConvention` method, which takes a regular expression.

Metalama reports LAMA0906 for each selected declaration whose name doesn't match the pattern. In the message, `<Declaration>` is the declaration, `<DeclarationKind>` its kind, and `<Pattern>` the pattern as a regular expression. When you use `MustRespectNamingConvention`, the message shows the regular expression that Metalama generates from your pattern, for example `^.*Reader$` for `*Reader`.

In the following example, a fabric requires all classes derived from `TextReader` to have a name ending with `Reader`, but the `TextLoader` class doesn't respect this convention.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0906/LAMA0906_Error.cs name="Warning"]

## Resolution

Rename the declaration so that its name matches the pattern given in the message. If the declaration is a legitimate exception, change the query in the fabric so that it doesn't select this declaration, for instance with a `Where` clause.
