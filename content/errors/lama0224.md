# LAMA0224: A dynamic local variable must be initialized

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The 'dynamic' keyword cannot be used in the local variable '<Variable>' because it is not initialized. Initialize the variable in its declaration, or use 'meta.DefineLocalVariable' to declare a run-time variable without an initializer.` |

## Cause

In a T# template, `dynamic` stands for a run-time type that's only known when Metalama expands the template, for instance the return type of the target method. Metalama infers the actual type of a `dynamic` local variable from its initializer. Without an initializer, there's nothing to infer the type from.

Metalama reports LAMA0224 when a template declares a local variable of type `dynamic` (or `dynamic?`) without an initializer. The placeholder of the message is the name of the variable.

In the following example, the template declares `result` before a `try` block and assigns it inside the block.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0224/LAMA0224_Error.cs name="Error"]

## Resolution

Depending on your intent, do one of the following:

* Initialize the variable in its declaration. If needed, move the declaration to where the value is available, for instance inside the `try` block, as shown in the following example.
* Initialize the variable with a `dynamic` expression that gives it the right type, for instance `meta.Default( meta.Target.Method.ReturnType )`.
* Declare the variable with `meta.DefineLocalVariable`, passing its type, which generates a run-time variable without an initializer. Use the `Value` property of the returned expression to read or write the variable.
