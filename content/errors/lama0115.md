# LAMA0115: A `meta.Target` member isn't available for the current target

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The template '<Advice>' cannot use '<Expression>' when applied to the <TargetKind> '<TargetDeclaration>' because no '<MissingKind>' is available in this context.<AlternativeSuggestion>` |

## Cause

The <xref:Metalama.Framework.Aspects.meta.Target> property gives a template access to the declaration being advised through members like `Method`, `Property`, `Field`, `FieldOrProperty`, `Indexer`, `Parameter`, `Event`, `Constructor`, or `Type`. Each of these members is available only when it makes sense for the current target. For instance, `meta.Target.Field` is available when the advice is applied to a field, but not when it's applied to a property.

Metalama reports LAMA0115 when it expands a template and the template reads a `meta.Target` member that isn't available for the current target. In the message, `<Expression>` is the member, such as `meta.Target.Field`, `<TargetDeclaration>` is the declaration being advised (for an accessor template, the accessor), and `<MissingKind>` is the kind of object that's missing. When a more general member exists, the message suggests it.

In the following example, the `LogRead` aspect reads `meta.Target.Field.Name`, but it's applied to the property `Name`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0115/LAMA0115_Error.cs name="Error"]

## Resolution

Use a member of `meta.Target` that's available for every declaration the aspect can be applied to:

* For aspects applied to fields and properties, use `meta.Target.FieldOrProperty`. If the aspect can also be applied to indexers, use `meta.Target.FieldOrPropertyOrIndexer`.
* Use the more general `meta.Target.Declaration` or `meta.Target.Member` when the template only needs common information like the name.
* If the template needs a specific kind of declaration, restrict the aspect to it in its `BuildEligibility` method.
