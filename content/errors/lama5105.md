# LAMA5105: [InvalidateCache] doesn't name any method to invalidate

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Caching |
| **Message** | `Invalid [InvalidateCache] aspect on '<Method>': the constructor parameters must contain at least one method name.` |

## Cause

The <xref:Metalama.Patterns.Caching.Aspects.InvalidateCacheAttribute?text=[InvalidateCache]> aspect removes from the cache the results of the cached methods whose names you pass to its constructor. Because the method names are a `params` array, C# accepts the attribute without any argument, or with only a type argument, but then the aspect has nothing to invalidate.

Metalama reports LAMA5105 when the list of method names is empty or `null`. The `<Method>` placeholder is the invalidating method, that is, the method to which the aspect is applied.

In the following example, the aspect is applied without any method name.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA5105/LAMA5105_Error.cs name="Error"]

## Resolution

Pass the names of the cached methods to invalidate, preferably with the `nameof` operator. If the cached methods belong to a different type, pass this type as the first argument, followed by the method names.
