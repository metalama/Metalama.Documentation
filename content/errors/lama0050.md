# LAMA0050: The weaver of an aspect can't be found

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The weaver type '<WeaverType>' required to weave aspect '<AspectType>' is not found in the project. Make sure that the project references the assembly that defines this weaver, and that the weaver type is annotated with [MetalamaPlugIn].` |

## Cause

Weaver-based aspects don't implement their transformations with the `BuildAspect` method but with a low-level weaver built with the Metalama SDK. The aspect class is bound to its weaver by the <xref:Metalama.Framework.Aspects.RequireAspectWeaverAttribute> attribute, which gives the full name of the weaver type. Metalama loads the weavers from the compile-time code of the current project and of its references: a weaver is a class that implements `IAspectWeaver` and is annotated with `[MetalamaPlugIn]`.

Metalama reports LAMA0050 when the project applies at least one instance of a weaver-based aspect, but no loaded weaver has the full name given by `[RequireAspectWeaver]`. In the message, `<WeaverType>` is this full name, and `<AspectType>` is the name of the aspect. Typical causes are:

* The weaver is defined in a separate assembly or package that the current project doesn't reference.
* The weaver class isn't annotated with `[MetalamaPlugIn]`, so Metalama doesn't load it.
* The name passed to `[RequireAspectWeaver]` as a string doesn't match the full name of the weaver type, for instance because of a typo, a renamed class, or a different namespace. For a nested type, the name must use the reflection syntax, with `+` between the containing type and the nested type.

Declaring a weaver-based aspect without its weaver isn't an error in itself: Metalama reports LAMA0050 only when the aspect is applied. The diagnostic isn't attached to any location in the source code.

## Resolution

* Make sure that the project where the aspect is applied references the project or package that defines the weaver. When the aspect and its weaver are distributed as a package, check that the package contains the weaver assembly.
* Make sure that the weaver class implements `IAspectWeaver`, is annotated with `[MetalamaPlugIn]`, and has a public parameterless constructor.
* When the aspect project can reference the weaver type, pass the type itself to `[RequireAspectWeaver]` with `typeof` instead of a string. The compiler then verifies the name for you.
