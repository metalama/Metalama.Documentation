# LAMA0247: A template returns a void result where a value is expected

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot apply the aspect '<Aspect>' to '<Target>': the template returns '<Expression>', of type '<Type>', from a method or local function whose return type is '<ReturnType>'.` |

## Cause

In a template, the type of `meta.Proceed()` is the return type of the target method, which Metalama only knows when it applies the aspect. When the target method returns `void`, `meta.Proceed()` has no value.

Metalama reports LAMA0247 when it expands a template that returns such a `void` expression from a context that expects a value. The typical case is a `return meta.Proceed();` statement in a local function that has a non-`void` return type, like `bool`, when the aspect is applied to a `void` method. Because local functions in templates can't use `dynamic` in their signature (see <xref:lama0246>), their return type is fixed, while the target method can return anything.

The message gives the returned expression, its type, and the return type of the local function or method. Metalama reports the error on the target declaration.

In the following example, the `RetryOnFailure` aspect wraps `meta.Proceed()` in a local function that returns `bool`, so it can call the method a second time when the first call fails. The aspect is also applied to a method that returns `void`.

## Resolution

Make sure that the template returns `void` expressions only where no value is expected:

* Apply the aspect only to methods whose return type matches the local function, as in the following example. If you're the author of the aspect, add an eligibility condition on the return type in `BuildEligibility`, so that the aspect can't be applied to other methods.
* If the aspect must support `void` methods, handle them in a separate branch of the template, for instance with a compile-time `if` on `meta.Target.Method.ReturnType`, where `meta.Proceed()` is called as a statement.
