# LAMA1004: The methods of a type introduced by an aspect can't be intercepted

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Extensions.Interceptors |
| **Message** | `The <Source> cannot intercept uses of members of '<Type>' because this type is introduced by an aspect. Uses of its members do not exist in the source code.` |

## Cause

Metalama.Extensions.Interceptors lets an aspect or a fabric replace the calls to selected methods with calls to other methods. An aspect or fabric registers an interceptor with the `InterceptMethods` method. The `Type` method of the registration builder selects the type that declares the intercepted methods.

Interceptors apply only to the calls that are written in the source code. A type that an aspect introduces doesn't exist in the source code, so no source code can contain a call to its methods.

Metalama reports LAMA1004 when the type given to `Type` is introduced by an aspect, for example the result of `IntroduceClass`. In the message, `<Source>` describes the aspect or fabric that made the registration, and `<Type>` is the introduced type.

In the following example, the aspect introduces the `Printer` class and then registers an interceptor for its `Print` method.

## Resolution

Select a type that exists in the source code, or in a referenced assembly, as the declaring type of the intercepted methods. In the following example, the `Printer` class is declared in the source code and the aspect intercepts its `Print` method.
