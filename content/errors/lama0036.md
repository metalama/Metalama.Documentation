# LAMA0036: A template of the base class has the same name

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The class '<ClassName>' defines a new template named '<TemplateName>', but the base class '<BaseClassName>' already defines a template of the same name. Rename the template, or make the template of the base class virtual and override it.` |

## Cause

Advice methods such as `Override` or `IntroduceMethod` identify templates by their name. Therefore, all templates of an aspect class, including the templates inherited from its base classes, must have different names.

Metalama reports LAMA0036 when a class derived from an aspect class defines a template that has the same name as a template of a base class, but doesn't override it. This happens, for instance, when the derived class hides the base template with the `new` modifier. In the message, `<TemplateName>` is the template name, `<ClassName>` is the derived class, and `<BaseClassName>` is its base class.

Metalama reports this error when it loads the aspect class, whether or not the aspect is used.

## Resolution

Do one of the following:

* If the derived class should change the behavior of the base template, make the base template `virtual` and override it in the derived class. Don't add the `[Template]` attribute to the override: it inherits the attribute of the base method. The following example shows this fix.
* If both templates are needed, rename the template of the derived class.
