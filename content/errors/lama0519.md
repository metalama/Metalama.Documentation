# LAMA0519: An implicit interface implementation must be public

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot implicitly implement the interface '<InterfaceType>' with the member '<TemplateMember>' because this member or one of its accessors is not public. Make the member and its accessors public, or set the IsExplicit property of the [InterfaceMember] attribute to true.` |

## Cause

When an aspect calls <xref:Metalama.Framework.Aspects.AdviserExtensions.ImplementInterface*>, Metalama looks in the aspect class for members marked with the <xref:Metalama.Framework.Aspects.InterfaceMemberAttribute?text=[InterfaceMember]> attribute and uses them as templates for the members of the interface. By default, these members are introduced as _implicit_ implementations, that is, as members of the target type that implement the interface by their name and signature.

In C#, an implicit interface implementation must be public. Metalama copies the accessibility of the template to the introduced member, so it reports LAMA0519 when the template is private, protected, or internal. For a property, every accessor that the interface requires must also be public: a public property with a `private set` accessor triggers the error when the interface declares a setter.

In the message, `<InterfaceType>` is the interface, and `<TemplateMember>` is the template member of the aspect class.

## Resolution

Do one of the following:

* Make the template member public, together with the accessors required by the interface. The following example shows this fix.
* If you don't want the member to be part of the public surface of the target type, set the <xref:Metalama.Framework.Aspects.InterfaceMemberAttribute.IsExplicit> property of the attribute to `true`. Metalama then introduces an explicit interface implementation, which has no accessibility modifier.
