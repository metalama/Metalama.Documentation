# LAMA5152: A field or property has a struct type that implements INotifyPropertyChanged

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Observability |
| **Message** | `The type '<Type>' of the <Kind> '<FieldOrProperty>' is a struct that implements INotifyPropertyChanged. The [Observable] aspect does not support structs that implement INotifyPropertyChanged.` |

## Cause

When a field or property of an observable class has a type that implements <xref:System.ComponentModel.INotifyPropertyChanged>, the <xref:Metalama.Patterns.Observability.ObservableAttribute?text=[Observable]> aspect treats its value as a child object: it can subscribe to the `PropertyChanged` event of the value to propagate the changes of its properties. This mechanism relies on reference semantics and can't work with a struct, because every read of the field or property returns a copy of the value.

Metalama reports LAMA5152 on each field or property processed by the aspect whose type is a value type that implements `INotifyPropertyChanged`, including a type parameter constrained to `struct` and `INotifyPropertyChanged`. In the message, `<Kind>` is the kind of declaration, `<FieldOrProperty>` is the field or property, and `<Type>` is its type.

In the following example, the `Position` property has the type `Coordinates`, a struct that implements `INotifyPropertyChanged`.

## Resolution

Do one of the following:

* Make the struct immutable and remove its implementation of `INotifyPropertyChanged`. To change the value, assign a new instance to the property: the aspect then raises the notification for the property itself. The following example uses a `readonly record struct`.
* Change the struct into a class, so that the aspect can observe its changes as a child object.
* If the property doesn't need change notifications, exclude it from the aspect with the <xref:Metalama.Patterns.Observability.NotObservableAttribute?text=[NotObservable]> attribute.
