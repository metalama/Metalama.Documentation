# LAMA5111: A parameter classifier prevents the method from being cached

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Caching |
| **Message** | `The [Cache] aspect cannot be applied to the method '<Method>' because the classifier '<Classifier>' marked the parameter '<ParameterName>' as ineligible.` |

## Cause

A _parameter classifier_ is a compile-time class implementing <xref:Metalama.Patterns.Caching.Aspects.Configuration.ICacheParameterClassifier>, registered with the `AddParameterClassifier` method of the caching options, usually from a fabric. For each parameter of a method cached with the <xref:Metalama.Patterns.Caching.Aspects.CacheAttribute> aspect, the classifier decides whether the parameter is part of the cache key, is excluded from it, or makes the method impossible to cache.

Metalama reports LAMA5111 when a classifier returns `CacheParameterClassification.Ineligible()` for a parameter. Classifiers typically do this for parameter types that can't be turned into a reliable cache key. In the message, `<Classifier>` is the classifier, shown as the result of its `ToString` method, which is the full name of its type by default, and `<ParameterName>` is the name of the parameter. The `[Cache]` aspect isn't applied.

In the following example, a classifier marks all parameters of type `Stream` as ineligible, and the cached `CountLines` method has a `Stream` parameter.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA5111/LAMA5111_Error.cs name="Error"]

## Resolution

Do one of the following:

* Change the method so that its parameters can be part of the cache key. In the following example, the method receives the path of the file instead of a stream.
* Remove the `[Cache]` aspect from the method if the method can't be cached.
* If the parameter doesn't affect the result, change the classifier so that it returns `CacheParameterClassification.ExcludeFromCacheKey` for this parameter instead of `Ineligible()`.
