# LAMA0883: An immutable type derives from a mutable base type

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Framework |
| **Message** | `'<Type>' must be written in an immutable style because it is an aspect, a fabric, a validator, or another type bound by the [ImmutableType] contract, but its base type '<BaseType>' is not immutable. Path: <Path>.` |

## Cause

Aspects, fabrics, validators, and the types that you mark with the `[ImmutableType]` attribute must be written in an immutable style, because an aspect instance is reused for all its targets. See <xref:lama0882?text=LAMA0882> for the rationale and for the rules that decide whether a type is immutable.

Metalama reports LAMA0883 when such a type, `<Type>`, derives from a base class `<BaseType>` that isn't immutable. A base class is immutable if it's itself bound by the contract, that is, marked with `[ImmutableType]` or derived from a type that requires immutability, such as <xref:Metalama.Framework.Aspects.OverrideMethodAspect>. It's also immutable if Metalama knows it to be immutable, as for `System.Attribute`, or if the project declares it immutable. The base classes `object` and `System.ValueType` are always accepted. An abstract base class that isn't marked is also reported by this diagnostic, not by <xref:lama0884?text=LAMA0884>. `<Path>` shows the chain from `<Type>` to `<BaseType>` and the reason, for example `LogAttribute -> CategorizedAttribute (an interface or abstract type that is not marked [ImmutableType])`.

The diagnostic is reported on the name of the derived type, and not on the members inherited from the base type, because the author of the derived type can't fix a member declared by the base type.

## Resolution

Choose one of the following options:

* If you own the base type, mark it with `[ImmutableType]`, as in the following example. Metalama then checks its members with the rules described in <xref:lama0882?text=LAMA0882>, so fix the diagnostics that it reports on them: <xref:lama0880?text=LAMA0880>, <xref:lama0881?text=LAMA0881>, and <xref:lama0882?text=LAMA0882>. Because an aspect is also bound by the `[Durable]` contract, the base type of an aspect must be marked `[Durable]` too, otherwise <xref:lama0873?text=LAMA0873> is reported.
* If you don't need the base class, derive from an immutable type instead, such as <xref:Metalama.Framework.Aspects.OverrideMethodAspect>, or implement the interface directly.
* If the base type isn't yours and you know that it's immutable, declare it with a `MetalamaImmutableType` item in the project file, using its full metadata name (see <xref:lama0885?text=LAMA0885>).
* If the warning is unwanted on one declaration, suppress it with `#pragma warning disable LAMA0883`.
