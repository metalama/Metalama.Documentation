# LAMA0013: The invoked member receives too few arguments

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The member '<Member>' requires at least <RequiredArgumentsCount> argument(s), but the invocation passes <ActualArgumentsCount>.` |

## Cause

In a template, you can generate a call to a method or a constructor that you only know as a compile-time declaration, such as an `IMethod`, by calling the `Invoke` method of its invoker. The C# compiler can't check the arguments of this call, because it doesn't know the signature of the target member when it compiles the aspect. Metalama checks them when it executes the template.

When the invoked member ends with a `params` parameter, you can pass any number of arguments for this parameter, including none, but you must pass one argument for each parameter that precedes it. Metalama reports LAMA0013 when you pass fewer arguments than that. In the message, `<Member>` is the invoked member, `<RequiredArgumentsCount>` is the number of parameters before the `params` parameter, and `<ActualArgumentsCount>` is the number of arguments passed to `Invoke`. The diagnostic is reported on the declaration to which the aspect is applied.

For a member without a `params` parameter, Metalama reports <xref:lama0012> instead.

In the following example, the `Audit` aspect calls the `WriteAudit` method of the target type without any argument, although the method requires a `methodName` argument before its `params` parameter.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0013/LAMA0013_Error.cs name="Error"]

## Resolution

Pass one argument for each parameter that precedes the `params` parameter, then any number of arguments for the `params` parameter. If your aspect must work with members of several signatures, examine the `Parameters` collection of the member before invoking it.
