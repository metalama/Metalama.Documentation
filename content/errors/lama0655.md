# LAMA0655: An overridden record member reads the backing field of a replaced event

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The original implementation of '<Member>' generated for record '<RecordType>' reads the backing field of the field-like event '<Event>', which the event no longer has. An aspect overrides the event with templates that do not call the original implementation, so the linker replaces the event by one that stores no handler and the generated body cannot be compiled. Call 'meta.Proceed()' in the templates that override the event.` |

## Cause

The `Equals` and `GetHashCode` methods that the C# compiler generates for a record compare the backing fields, including the field of each field-like event. When an aspect overrides one of these methods, Metalama writes the original implementation as source code so that the aspect can call it with <xref:Metalama.Framework.Aspects.meta.Proceed*?text=meta.Proceed()>.

When an aspect overrides the accessors of a field-like event with templates that never call `meta.Proceed()`, the original implementation of the event isn't used, and the event keeps no backing field. The original implementation of `Equals` or `GetHashCode` then reads a field that doesn't exist, so it can't be compiled. Metalama reports LAMA0655 on the event. In the message, `<Member>` is the overridden method, `<RecordType>` is the record, and `<Event>` is the event.

In the following example, the `LogEquals` aspect overrides the `Equals` method of the record and the accessors of the `Changed` event, but the accessor template doesn't call `meta.Proceed()`.

## Resolution

Call `meta.Proceed()` in the templates that override the accessors of the event, so that the event keeps its backing field. If the aspect must discard the handlers of the event, don't override `Equals` or `GetHashCode` of the same record.
