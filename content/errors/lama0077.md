# LAMA0077: An aspect weaver is provided by two assemblies

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect weaver '<WeaverType>' is provided by two different assemblies: '<FirstAssembly>' and '<SecondAssembly>'. This typically happens when two versions of the same aspect library are referenced, for instance through a package and through a project reference. Remove one of the conflicting references.` |

## Cause

Weaver-based aspects implement their transformations with a low-level weaver built with the Metalama SDK. The aspect class is bound to its weaver by the <xref:Metalama.Framework.Aspects.RequireAspectWeaverAttribute> attribute, which gives the full name of the weaver type. Metalama loads the weavers, the classes annotated with `[MetalamaPlugIn]`, from the compile-time code of the current project and of its references, and identifies each weaver by its full type name. See <xref:aspect-weavers>.

Metalama reports LAMA0077 when two loaded weavers have the same full type name but come from assemblies with different identities, for instance two versions of the same assembly. Metalama then can't know which weaver you mean. This typically happens when the same aspect library reaches the project through two routes, for instance as a NuGet package and through a project reference, or as two packages that depend on different versions of the library. In the message, `<WeaverType>` is the full name of the weaver type, and `<FirstAssembly>` and `<SecondAssembly>` are the full names of the two assemblies.

When the same assembly, with the same identity, is loaded twice, Metalama doesn't report LAMA0077: the two weavers are interchangeable, and Metalama silently keeps one of them.

The diagnostic isn't attached to any location in the source code.

## Resolution

1. Use the two assembly names given in the message to find how each one reaches the project. In Visual Studio, look under the **Dependencies** node of the project. On the command line, inspect the `project.assets.json` file under `obj`, or a binary build log.
2. Remove one of the routes, so that a single version of the aspect library is referenced. For instance, remove the `PackageReference` if the project also references the library's project, or align the versions of the packages that bring the library.
3. Rebuild the project.
