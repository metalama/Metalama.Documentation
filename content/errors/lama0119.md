# LAMA0119: A file with compile-time code must import a Metalama namespace

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Framework |
| **Message** | `The compile-time declaration '<Declaration>' is in a file that does not have a using directive for the '<Namespace>' namespace or one of its main child namespaces. This may cause an inconsistent design-time experience. Add a using directive such as 'using <Namespace>.Aspects;' to the file.` |

## Cause

To keep the IDE responsive, Metalama decides which files contain compile-time code with a fast check that only looks at the `using` directives of each file. A file passes this check only if it has a `using` directive for `Metalama.Framework` or one of its main child namespaces, such as `Metalama.Framework.Aspects`, `Metalama.Framework.Code`, or `Metalama.Framework.Fabrics`, or if it has a `global using` directive.

Metalama reports LAMA0119 when a file fails this fast check but still declares compile-time or run-time-or-compile-time code, for instance a class marked with `[CompileTime]`, an aspect, or a fabric. This typically happens when you reference Metalama types by their fully qualified names or through a `using` alias. The build itself still works, but at design time, Metalama may not notice when you edit this file, so the IDE can show outdated or inconsistent results.

Metalama reports the warning on each compile-time declaration of the file, so you may see it on both a type and its members.

## Resolution

Add a `using` directive for a Metalama namespace to the file, typically `using Metalama.Framework.Aspects;`, and use the short names of the Metalama types. In the following example, the file imports `Metalama.Framework.Aspects` and the class uses the short `[CompileTime]` attribute.
