# LAMA5155: An observable type can't hide a base member with new

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Observability |
| **Message** | `The '<Member>' <Kind> is 'new'. This is not supported by the [Observable] aspect.` |

## Cause

The <xref:Metalama.Patterns.Observability.ObservableAttribute?text=[Observable]> aspect raises the `PropertyChanged` event by property name. When a derived class declares a field or property with the `new` modifier, the derived member and the hidden base member share the same name, so a notification can't tell which one changed. For this reason, the aspect doesn't support members declared with `new`.

Metalama reports LAMA5155 for each field or property declared with the `new` modifier in a type to which the `[Observable]` aspect applies. Remember that the aspect is inherited: it also applies to the classes derived from a class marked with `[Observable]`. In the message, `<Kind>` is the kind of declaration (`field` or `property`) and `<Member>` is its name.

In the following example, `DiscountedProduct` inherits the aspect from `Product` and hides its `Price` property.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA5155/LAMA5155_Error.cs name="Error"]

## Resolution

Remove the `new` modifier by giving the member its own name, as in the following example. If the derived class only needs to change the value stored in the base property, use the base property instead of declaring a new one.
