# LAMA0201: The compile-time value contains a cyclic reference

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot serialize the compile-time value of type '<Type>' to a run-time value because it contains a cyclic reference or is nested more than 32 levels deep.` |

## Cause

When a template uses a compile-time value in a run-time context, Metalama generates C# code that creates an equivalent value at run time. For a collection, it generates a collection initializer and converts each item recursively. A value that references itself, directly or through other collections, can't be expressed as a C# expression.

Metalama doesn't track the objects it has already converted. Instead, it reports LAMA0201 when the conversion goes deeper than 32 levels of nesting, so a value that's nested very deeply without any cycle also causes this error. Metalama reports the error when it expands the template, on the target declaration of the aspect. In the message, `<Type>` is the static type of the nested value being converted, which is often `Object` for an item of a collection.

In the following example, a compile-time list of tags accidentally contains itself. The list is assigned to an `object` variable because Metalama would otherwise reject the `List<object>` type when it compiles the template, with LAMA0200.

## Resolution

Remove the cyclic reference from the compile-time value, or flatten a structure that's nested more than 32 levels deep. If the data is a graph, convert it to a structure without cycles before you use it in run-time code, for instance a list of nodes and a list of edges that identify the nodes by name.
