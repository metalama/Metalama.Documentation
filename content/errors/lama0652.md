# LAMA0652: A synthesized record member reads an overridable property

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Framework |
| **Message** | `The original implementation of '<Member>' generated for record '<RecordType>' reads the property '<Property>', whereas the C# compiler reads its backing field. The backing field of an auto-property cannot be read from source code. The two implementations differ when a derived type overrides the property. Declare the property explicitly with a backing field, or make it non-overridable.` |

## Cause

The C# compiler synthesizes the `Equals` and `GetHashCode` methods of a record and reads the backing fields of its automatic properties. When an aspect overrides one of these methods and calls <xref:Metalama.Framework.Aspects.meta.Proceed*?text=meta.Proceed()>, Metalama must write the original implementation as source code. Source code can't read the backing field of an automatic property, so the generated body reads the property instead.

The two implementations behave the same unless a derived type overrides the property. Metalama reports LAMA0652 as a warning when a property of the record is `virtual`, or is an `override` that isn't `sealed`, because the generated body would then call the overriding implementation, whereas the compiler would read the field. The `<Member>` placeholder is the synthesized method, `<RecordType>` is the record, and `<Property>` is the overridable property.

In the following example, the `TrackEquality` aspect overrides the `Equals` method of the `Product` record, whose `Price` property is virtual. The warning is reported on the property.

## Resolution

Do one of the following:

* Make the property non-overridable: remove the `virtual` modifier, or add `sealed` to an `override`.
* Declare the property explicitly with a backing field, instead of an automatic property.
* If the generated implementation is acceptable for your derived types, ignore the warning.
