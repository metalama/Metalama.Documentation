# LAMA0522: A finalizer can't be introduced with the New strategy

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce a finalizer into the type '<TargetType>' because the override strategy '<OverrideStrategy>' is not supported for finalizers. Use 'Fail', 'Ignore', or 'Override'.` |

## Cause

The <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceFinalizer*> advice adds a finalizer to a type. Its `whenExists` parameter, of type <xref:Metalama.Framework.Aspects.OverrideStrategy>, determines what happens when the type already has a finalizer.

`OverrideStrategy.New` means "introduce a new member that hides the existing one", like the `new` modifier in C#. This doesn't apply to finalizers: a type has at most one finalizer, and a finalizer can't hide the finalizer of its base type. Metalama reports LAMA0522 whenever `IntroduceFinalizer` is called with `OverrideStrategy.New`, even if the type doesn't have a finalizer yet.

## Resolution

Pass one of the supported strategies to the `whenExists` parameter:

* `OverrideStrategy.Override` introduces the finalizer if the type doesn't have one, and otherwise overrides the existing finalizer, which the template invokes with `meta.Proceed()`. This is usually the intended behavior. The following example shows this fix.
* `OverrideStrategy.Ignore` introduces the finalizer only if the type doesn't have one.
* `OverrideStrategy.Fail`, the default, introduces the finalizer and reports an error if the type already has one.
