# LAMA0532: An abstract member can't be introduced into a non-abstract type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot introduce the abstract member '<Member>' into the type '<TargetType>' because '<TargetType>' is not abstract.` |

## Cause

In C#, only an abstract class can declare abstract members. Metalama enforces the same rule for the members that aspects introduce with methods such as <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceMethod*>, <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceProperty*>, or <xref:Metalama.Framework.Aspects.AdviserExtensions.IntroduceEvent*>.

Metalama reports LAMA0532 when the build action of the advice, for instance the `buildMethod` argument of `IntroduceMethod`, sets the `IsAbstract` property of the member builder to `true` and the target type isn't abstract. In the message, `<Member>` is the introduced member and `<TargetType>` is the target type.

Templates behave differently: a public template without a body, or a template whose attribute sets `IsAbstract`, produces an abstract member only when the target type is abstract, and never causes this error.

In the following example, the `Validatable` aspect introduces an abstract `Validate` method, but it's applied to a class that isn't abstract.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0532/LAMA0532_Error.cs name="Error"]

## Resolution

Do one of the following:

* Make the target type abstract, as in the following example.
* If the aspect must also support non-abstract types, set `IsAbstract` only when the target type is abstract, and give the template a body, so that Metalama introduces a regular method into non-abstract types.
* Restrict the aspect to abstract types with an eligibility condition in its `BuildEligibility` method.
