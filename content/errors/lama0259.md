# LAMA0259: The null-conditional operator mixes compile-time and run-time parts

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The null-conditional operator cannot be used in the expression '<Expression>', because '<CompileTimeReceiver>' is compile-time, but '<RunTimeAccess>' is run-time. Consider using a separate null-checking 'if' statement instead of the null-conditional operator.` |

## Cause

In a T# template, the null-conditional operator (`?.`) must be evaluated entirely at compile time or entirely at run time. When the expression on the left of `?.` is compile-time, for instance a field of the code model, but the member on the right returns a run-time value, for instance <xref:Metalama.Framework.Code.IExpression.Value>, the null check would happen at compile time while the access happens at run time. Metalama can't generate code for such an expression and reports LAMA0259.

In the message, `<CompileTimeReceiver>` is the compile-time receiver and `<RunTimeAccess>` is the run-time access.

In the following example, the aspect looks for a `_log` field in the target type and uses `?.` to access the field's value only when the field exists.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0259/LAMA0259_Error.cs name="Error"]

## Resolution

Check the compile-time expression for `null` in a separate `if` statement. Because the condition is compile-time, Metalama evaluates it while expanding the template and generates the run-time code only when the condition is true, as shown in the following example.
