# LAMA0704: The dependency type is less accessible than the constructor

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Extensions.DependencyInjection |
| **Message** | `The dependency '<DependencyType>' cannot be pulled from the constructor '<Constructor>' because '<DependencyType>' has lower accessibility than the constructor.` |

## Cause

With the default .NET Core pattern, implemented by <xref:Metalama.Extensions.DependencyInjection.Implementation.DefaultDependencyInjectionFramework>, a dependency is _pulled_ from the constructors of the target type: Metalama adds a parameter of the dependency type to each constructor and assigns it to the dependency field or property. C# doesn't allow a parameter type to be less accessible than its method, so the parameter can't be added when the dependency type is less accessible than the constructor.

Metalama reports LAMA0704 when the effective accessibility of the dependency type is lower than the effective accessibility of the constructor. Effective accessibility takes the containing types into account: a public constructor of an internal class is effectively internal. In the message, `<DependencyType>` is the dependency type and `<Constructor>` is the constructor. When the target type has no explicit constructor, the diagnostic is reported on the type.

In the following example, the `Audit` aspect introduces an `IAuditSink` dependency, but `IAuditSink` is internal while `OrderService` and its implicit constructor are public.

## Resolution

Make the accessibility of the dependency type and of the constructor consistent:

* Make the dependency type at least as accessible as the constructor, as in the following example.
* Reduce the accessibility of the target type or of its constructors, for instance by making the class `internal`.
