# LAMA0021: The aspect order contains a cycle

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `A cycle was found in the specifications of aspect ordering between the following aspect layers: <Layers>.` |

## Cause

When several aspects are applied to the same declaration, Metalama must know in which order to apply them. You specify this order with the <xref:Metalama.Framework.Aspects.AspectOrderAttribute> custom attribute. Metalama combines all these attributes, including those of referenced assemblies, with the order of the layers within each aspect, and sorts the aspect layers accordingly.

Metalama reports LAMA0021 when these specifications contradict each other, so that no order satisfies all of them. For instance, one attribute says that `A` runs before `B` and another one says that `B` runs before `A`. In the message, `<Layers>` lists the full names of the aspect layers that form the cycle. The error is reported on the `AspectOrder` attributes involved, and Metalama doesn't transform the project.

In the following example, two attributes order the `Log` and `Measure` aspects in opposite directions.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0021/LAMA0021_Error.cs name="Error"]

## Resolution

Find the `AspectOrder` attributes that involve the aspects listed in the message, decide which order you want, and remove or correct the attributes that contradict it. Check the attributes in all files of the project, and remember that the attributes of referenced projects also apply. To avoid such conflicts, specify the order of a group of aspects in a single attribute.
