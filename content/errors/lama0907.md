# LAMA0907: The exclusion predicate type is invalid

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Extensions.Architecture |
| **Message** | `The type assigned to the ExclusionPredicateType property must be derived from ReferencePredicate.` |
| **Message** | `The type assigned to the ExclusionPredicateType property must have a public constructor accepting a single parameter of type ReferencePredicateBuilder.` |

## Cause

The usage validation attributes, such as <xref:Metalama.Extensions.Architecture.Aspects.CanOnlyBeUsedFromAttribute> and <xref:Metalama.Extensions.Architecture.Aspects.CannotBeUsedFromAttribute>, and the <xref:Metalama.Extensions.Architecture.Aspects.DerivedTypesMustRespectRegexNamingConventionAttribute> attribute have an `ExclusionPredicateType` property. It lets you exclude some references from the rule with a custom predicate: Metalama instantiates the given type and doesn't report any violation for the references that match the predicate.

To be instantiated, the type must satisfy two conditions, and LAMA0907 has one message for each:

* The type must be derived from <xref:Metalama.Extensions.Architecture.Predicates.ReferencePredicate>.
* The type must have a public constructor with a single parameter of type <xref:Metalama.Extensions.Architecture.Predicates.ReferencePredicateBuilder>. A default constructor isn't enough.

Metalama reports LAMA0907 on the target of the attribute when one of these conditions isn't met. The attribute is then skipped: although LAMA0907 is only a warning, the whole architecture rule isn't enforced.

## Resolution

Make the exclusion predicate a valid reference predicate:

1. Derive the class from `ReferencePredicate` and mark it with `[CompileTime]`.
2. Add a public constructor that accepts a `ReferencePredicateBuilder` and passes it to the base constructor.
3. Implement the `IsMatchCore` and `GetGranularity` methods.
