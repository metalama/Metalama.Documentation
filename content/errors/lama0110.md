# LAMA0110: A compile-time loop can't be used under a run-time condition

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The compile-time '<LoopKind>' loop is not allowed here because it is part of a block whose execution depends on the run-time condition '<RunTimeCondition>'. Move the loop out of the run-time-conditional block or use a compile-time 'foreach' loop instead.` |

## Cause

In a T# template, a `while` or `do` loop whose condition is a compile-time expression runs at compile time. Such a loop needs a compile-time variable that changes from one iteration to the next. However, the body of a run-time `if`, `else`, `for`, `foreach`, `while`, `switch`, `catch`, or `finally` executes only when the program runs, and Metalama doesn't allow modifying compile-time variables from such a block (see <xref:lama0108>).

For this reason, Metalama reports LAMA0110 when a compile-time `while` or `do` loop appears inside a run-time-conditional block. The first placeholder of the message is the kind of loop, and the second one is the statement that introduces the run-time condition. The check doesn't apply to `foreach` loops because their iteration variable can't be modified explicitly.

In the following example, the aspect uses a compile-time `while` loop to iterate over the parameters of the target method, inside an `if` statement whose condition, `result == null`, is a run-time expression.

## Resolution

Depending on your intent, do one of the following:

* Replace the `while` or `do` loop with a compile-time `foreach` loop. To iterate over a range of numbers, iterate over `meta.CompileTime( Enumerable.Range( 0, n ) )`. The following example uses a `foreach` loop.
* Move the loop out of the run-time-conditional block, for instance to compute a compile-time value before the block.
* Move the logic to a compile-time helper method that returns a collection, and iterate over that collection with `foreach`.
