# LAMA0703: The aspect target of [IntroduceDependency] must be a type or a type member

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Extensions.DependencyInjection |
| **Message** | `Cannot use the [IntroduceDependency] advice because the target declaration '<TargetDeclaration>' is not a type or a type member.` |

## Cause

The <xref:Metalama.Extensions.DependencyInjection.IntroduceDependencyAttribute> advice introduces the dependency into the type targeted by the aspect. When the aspect targets a member, such as a method, the dependency is introduced into the declaring type of that member.

Metalama reports LAMA0703 when the aspect's target has no such type, that is when the aspect is applied to the compilation (an assembly-level aspect) or to a namespace. In the message, `<TargetDeclaration>` is the target of the aspect.

In the following example, the `Audit` aspect derives from <xref:Metalama.Framework.Aspects.CompilationAspect> and is applied to the assembly, so there's no type into which the `_auditSink` dependency can be introduced.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0703/LAMA0703_Error.cs name="Error"]

## Resolution

Apply the aspect that introduces the dependency to types or type members:

* Change the aspect into a type aspect, for instance by deriving it from <xref:Metalama.Framework.Aspects.TypeAspect>, and apply it to each type that needs the dependency, as in the following example.
* To apply the aspect to many types, keep it a type aspect and add it from a fabric instead of using an assembly-level attribute.
