# LAMA0277: A called template can't receive a run-time type parameter as type argument

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The template '<Template>' cannot be called with the type argument '<TypeArgument>' because this type argument contains a run-time type parameter of the calling template.` |

## Cause

An auxiliary template can have type parameters, but they must be _compile-time_ type parameters, marked with `[CompileTime]`. Metalama replaces them with concrete types when it expands the template, so the type arguments of the call must be known at that moment.

A type parameter of the calling template that isn't marked with `[CompileTime]` is a _run-time_ type parameter. This is the case, for example, of the type parameter of a generic method introduced with `[Introduce]`: it's copied to the generated method, and its value is only known when the program calls the method. Metalama reports LAMA0277 when a type argument of the call to an auxiliary template is such a type parameter, or contains it, like `T[]` or `List<T>`. The first placeholder of the message is the called template, and the second one is the faulty type argument.

In the following example, the introduced generic method `LogType<T>` calls the auxiliary template `WriteTypeName` with its own type parameter `T`.

## Resolution

Depending on your intent, do one of the following:

* Pass the type as a run-time value instead of a type argument: replace the type parameter of the auxiliary template with a regular parameter of type <xref:System.Type> and pass `typeof(T)`. The following example uses this fix.
* Move the code of the auxiliary template into the calling template, where `T` can be used directly.
* If the type is known at compile time, pass a concrete type or a compile-time type parameter of the calling template.
