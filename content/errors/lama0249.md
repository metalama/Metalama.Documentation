# LAMA0249: A template can't be unsafe

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `'<Declaration>' cannot contain unsafe code because it is a template.` |

## Cause

A template is compiled into compile-time code that generates the run-time code, and Metalama doesn't support unsafe code in templates.

Metalama reports LAMA0249 when the declaration of a template has the `unsafe` modifier. This includes the template methods of aspects, such as `OverrideMethod`, methods marked with [<xref:Metalama.Framework.Aspects.TemplateAttribute>], and members marked with [<xref:Metalama.Framework.Aspects.IntroduceAttribute>]. The placeholder of the message is the template member.

When the `unsafe` modifier is on the aspect class itself, Metalama reports <xref:lama0248> instead.

In the following example, the `OverrideMethod` template of the `Log` aspect has the `unsafe` modifier.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0249/LAMA0249_Error.cs name="Error"]

## Resolution

Remove the `unsafe` modifier from the template. Then do one of the following:

* Rewrite the template without pointers, for instance with `Span<T>` or with the methods of the `Unsafe` and `MemoryMarshal` classes.
* If the generated code must contain unsafe code, build it as text with <xref:Metalama.Framework.Code.SyntaxBuilders.StatementFactory.Parse*> or <xref:Metalama.Framework.Code.SyntaxBuilders.ExpressionFactory.Parse*>. The target member or type must then provide the unsafe context, for instance by being declared `unsafe`.
