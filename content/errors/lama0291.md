# LAMA0291: Code that isn't compile-time references a Roslyn type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot reference '<ReferencedSymbol>' in '<DeclaringSymbol>' because '<ReferencedSymbol>' is compile-time-only but '<DeclaringSymbol>' is <DeclaringScope>. Roslyn types are compile-time-only because the MSBuild property 'MetalamaRoslynIsCompileTimeOnly' is set to true, which is the default when the project references the Metalama.Framework.Sdk package. Consider adding [CompileTime] to '<DeclaringSymbol>', or set <MetalamaRoslynIsCompileTimeOnly>false</MetalamaRoslynIsCompileTimeOnly> in your project file.` |

## Cause

The Metalama SDK lets compile-time code use the Roslyn API, that is, the types of the `Microsoft.CodeAnalysis` namespaces, such as `ISymbol` or `SyntaxNode`. When the `MetalamaRoslynIsCompileTimeOnly` MSBuild property is `true`, Metalama treats all Roslyn types as compile-time-only, like the code model. The `Metalama.Framework.Sdk` package sets this property to `true` by default. Without this package, the default is `false`, and Roslyn types can be used in both run-time and compile-time code.

Metalama reports LAMA0291 when Roslyn types are compile-time-only and a declaration whose scope is run-time or run-time-or-compile-time references one of them outside of a template, `typeof`, or `nameof`. It's the Roslyn counterpart of <xref:lama0117>. In the message, `<DeclaringSymbol>` is the declaration containing the reference, `<ReferencedSymbol>` is the Roslyn type or member, and `<DeclaringScope>` is the scope of `<DeclaringSymbol>`.

In the following example, the project treats Roslyn types as compile-time-only. The helper method `IsRoslynSymbol` of the `Log` aspect isn't marked `[CompileTime]`, so it's run-time-or-compile-time, but it uses the Roslyn interface `ISymbol`.

## Resolution

Depending on your intent, do one of the following:

* If the code is meant to run at compile time, add `[CompileTime]` to the declaration or to its containing type. The following example adds `[CompileTime]` to the helper method.
* If the project uses Roslyn in run-time code, for instance because it's a tool built on Roslyn, set `<MetalamaRoslynIsCompileTimeOnly>false</MetalamaRoslynIsCompileTimeOnly>` in a `PropertyGroup` of the project file. Roslyn types then become run-time-or-compile-time.
