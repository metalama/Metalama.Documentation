# LAMA1012: The call site can't be intercepted

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Extensions.Interceptors |
| **Message** | `The <Site> cannot be intercepted by the <Source> because <Reason>. The call site is left unchanged.` |

## Cause

The `Metalama.Extensions.Interceptors` package lets an aspect or a fabric replace the calls to selected methods with calls to another method, called an _interceptor_. The aspect or fabric registers the interception with `InterceptMethods`, and Metalama rewrites each call site that matches.

Some call sites can't be rewritten in this version of Metalama. When the registration doesn't skip such a site, Metalama reports LAMA1012 as a warning and leaves the call unchanged, so the original method runs. In the message, `<Site>` describes the call, `<Source>` is the interceptor and the aspect or fabric that registered it, and `<Reason>` explains the limitation. The most common reasons are:

* the call is in a lambda that the compiler converts to an expression tree, which describes the call instead of making it;
* the intercepted method returns by reference;
* a pointer type occurs in the signature of the method, in a type argument, or in the type of the receiver;
* the method uses `__arglist`, or its signature needs a `scoped` parameter;
* an omitted optional argument has a default value that can't be written in C#;
* an interceptor generated from a template can't handle the call, for instance a base call to a virtual method or a call whose receiver has a type parameter as its type.

To avoid the warning without changing the code, the registration can return `Skip` for the sites that it doesn't support. The `ForEachSite` method gives access to the reason through the `NonInterceptableReason` property of the site.

## Resolution

Depending on the reason given in the message, do one of the following:

* Change the code at the call site so that it doesn't hit the limitation. In the following example, the expression tree is replaced by a delegate.
* Select another method, or restrict the scope of the interception so that it doesn't include the call.
* Call `Skip` from a `ForEachSite` delegate for the sites with a limitation, and handle them in another way.
* Suppress the warning if you accept that the call is left unchanged.
