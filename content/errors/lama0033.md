# LAMA0033: The member used as a template doesn't have the [Template] attribute

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The class '<ClassName>' defines a member named '<MemberName>', but the member is not annotated with the [Template] custom attribute.` |

## Cause

When an aspect calls an advice method from `BuildAspect`, for instance `IntroduceMethod` or `Override`, it identifies the template by the name of a member of the aspect class, typically with `nameof`. Metalama treats a member as a template only if it has the <xref:Metalama.Framework.Aspects.TemplateAttribute> custom attribute, or another template attribute.

Metalama reports LAMA0033 when the aspect class has a member of the given name, but this member doesn't have a template attribute. In the message, `<ClassName>` is the full name of the aspect class and `<MemberName>` is the name of the member.

You typically get this error when you forget the `[Template]` attribute on a method that doesn't use any `meta` API. If the method uses `meta`, Metalama reports a different error first, because `meta` can only be used in templates.
