# LAMA0514: The target type already contains a member of the interface

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<AspectType>' cannot implement the interface member '<InterfaceMember>' in the type '<TargetType>' because the type already contains '<ExistingDeclaration>', which has the same signature. Set the WhenExists property of the [InterfaceMember] attribute to Ignore or MakeExplicit, or pass OverrideStrategy.Override to ImplementInterface.` |

## Cause

When an aspect calls <xref:Metalama.Framework.Aspects.AdviserExtensions.ImplementInterface*>, Metalama introduces the members of the aspect marked with <xref:Metalama.Framework.Aspects.InterfaceMemberAttribute?text=[InterfaceMember]> into the target type. By default, these members are introduced as implicit, public implementations.

An implicit implementation can't be introduced if the target type already contains a member with the same signature. This applies to methods, properties, and events, whether the existing member is declared in the target type or inherited from a base type. What Metalama does in this case depends on the <xref:Metalama.Framework.Aspects.InterfaceMemberAttribute.WhenExists> property of the <xref:Metalama.Framework.Aspects.InterfaceMemberAttribute?text=[InterfaceMember]> attribute. Metalama reports LAMA0514 when this property is:

* <xref:Metalama.Framework.Aspects.InterfaceMemberOverrideStrategy.Fail?text=Fail>, or
* <xref:Metalama.Framework.Aspects.InterfaceMemberOverrideStrategy.Default?text=Default> (the default value), and the `whenExists` parameter of <xref:Metalama.Framework.Aspects.AdviserExtensions.ImplementInterface*?text=ImplementInterface> isn't <xref:Metalama.Framework.Aspects.OverrideStrategy.Override?text=OverrideStrategy.Override>. This includes <xref:Metalama.Framework.Aspects.OverrideStrategy.Ignore?text=OverrideStrategy.Ignore>, which only applies when the type already implements the whole interface.

In the message, `<InterfaceMember>` is the interface member, and `<ExistingDeclaration>` is the existing member of the target type.

In the following example, the `Describable` aspect implements `IDescribable`, but the `Order` class already has a `Describe` method.

## Resolution

Choose how the aspect should handle the existing member:

* To use the existing member as the implementation of the interface member, set <xref:Metalama.Framework.Aspects.InterfaceMemberAttribute.WhenExists?text=WhenExists> to <xref:Metalama.Framework.Aspects.InterfaceMemberOverrideStrategy.Ignore?text=InterfaceMemberOverrideStrategy.Ignore>. The following example uses this fix.
* To keep the existing member and introduce the template as an explicit implementation, set `WhenExists` to <xref:Metalama.Framework.Aspects.InterfaceMemberOverrideStrategy.MakeExplicit?text=InterfaceMemberOverrideStrategy.MakeExplicit>, or set <xref:Metalama.Framework.Aspects.InterfaceMemberAttribute.IsExplicit> to `true`.
* To override the existing member with the template, pass <xref:Metalama.Framework.Aspects.OverrideStrategy.Override?text=OverrideStrategy.Override> to <xref:Metalama.Framework.Aspects.AdviserExtensions.ImplementInterface*?text=ImplementInterface> and leave `WhenExists` at its default value. The existing member must be public, and also virtual if it's inherited from a base class.
* Rename or remove the existing member of the target type.
