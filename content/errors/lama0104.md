# LAMA0104: The expression has the wrong scope

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The expression '<Expression>' is <ActualScope>, but it is expected to be <ExpectedScope> because the expression appears in <Context>.` |

## Cause

In a T# template, every expression is either _compile-time_, evaluated while Metalama compiles the target project, or _run-time_, emitted into the target code and evaluated when the program runs. Metalama infers the scope of each expression and reports LAMA0104 when an expression appears in a context that requires the other scope. The last part of the message describes this context.

The most common case is a run-time expression used where only a compile-time value makes sense, for instance as the index of a compile-time collection like `meta.Target.Parameters`. In the following example, the local variable `index` is initialized with a literal, so Metalama treats it as a run-time variable.

## Resolution

Make both sides of the expression agree on the scope:

* To make a local variable compile-time, initialize it with `meta.CompileTime(...)`, as in the following example, or with an expression that's already compile-time.
* To use a compile-time value in run-time code, convert it with `meta.RunTime(...)`.
* If you need run-time data, such as the value of a parameter, use the run-time members of the code model, like `IParameter.Value`, instead of indexing a compile-time collection at run time.
