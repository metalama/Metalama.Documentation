# LAMA0208: A serializable type can't declare several serializers

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The compile-time serializable type '<Type>' declares several nested types that implement ISerializer. Only one manual serializer is allowed.` |

## Cause

Metalama serializes aspects, fabrics, and other types implementing <xref:Metalama.Framework.Serialization.ICompileTimeSerializable> when they have cross-project effects. By default, it generates a serializer for each of these types. To override the generated serializer, you add a nested class that derives from <xref:Metalama.Framework.Serialization.ReferenceTypeSerializer`1> or <xref:Metalama.Framework.Serialization.ValueTypeSerializer`1>.

Metalama looks for the manual serializer among the nested types of the serializable type: it takes any nested type that implements <xref:Metalama.Framework.Serialization.ISerializer>, whatever its name. Metalama reports LAMA0208 when it finds more than one such nested type, because it can't choose between them. In the message, `<Type>` is the serializable type.

In the following example, the `RetryPolicy` class declares two nested serializers.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0208/LAMA0208_Error.cs name="Error"]

## Resolution

Keep a single nested type implementing <xref:Metalama.Framework.Serialization.ISerializer> in the serializable type:

* Remove the serializers you don't need.
* If you need another serializer for a different purpose, move it out of the serializable type. A serializer that isn't nested in the serializable type is ignored, unless you register it with <xref:Metalama.Framework.Serialization.ImportSerializerAttribute>, which is designed for types you don't own.
