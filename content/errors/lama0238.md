# LAMA0238: Only templates can use the dynamic type in compile-time code

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `'<Member>' cannot use the 'dynamic' type because it is not a template and its declaring type '<DeclaringType>' is <DeclaringTypeScope>. Only templates and members of run-time-only types can use the 'dynamic' type.` |

## Cause

In Metalama, the `dynamic` type has a special meaning: in a template, it represents a run-time value, such as the return value of `meta.Proceed()`. Outside of templates, compile-time code executes during compilation, where no run-time value exists, so `dynamic` has no meaning there.

Metalama reports LAMA0238 when a field that isn't a template uses the `dynamic` type, alone or in a constructed type like `dynamic[]` or `List<dynamic>`, and the field belongs to a type that isn't run-time-only, for instance an aspect, a fabric, or a type marked with <xref:Metalama.Framework.Aspects.CompileTimeAttribute>. The last placeholder of the message gives the scope of the declaring type, for instance `run-time-or-compile-time` for an aspect.

## Resolution

Depending on your intent, do one of the following:

* If the field holds a compile-time value, give it a concrete type. The value can still be used in templates, where Metalama inserts it into the generated code. The following example uses this fix.
* If the field must hold a run-time expression built at compile time, use <xref:Metalama.Framework.Code.IExpression> instead of `dynamic`, and use its <xref:Metalama.Framework.Code.IExpression.Value> property in templates.
* If you want to introduce the field into the target type, add the <xref:Metalama.Framework.Aspects.IntroduceAttribute> attribute, so that the field becomes a template.
