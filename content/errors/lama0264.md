# LAMA0264: A compile-time template parameter can't have a run-time-only type

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The compile-time template parameter '<Parameter>' cannot have the run-time-only type '<Type>'.` |

## Cause

A template method can have compile-time parameters, marked with the <xref:Metalama.Framework.Aspects.CompileTimeAttribute?text=[CompileTime]> attribute. The aspect passes their values when it adds the advice, and Metalama uses them while it expands the template, at compile time. For this reason, the value of a compile-time parameter must be of a type that exists at compile time: a compile-time-only type like `IField`, or a type that's both run-time and compile-time, like `string` or `int`.

Metalama reports LAMA0264 when the type of a compile-time template parameter is run-time-only. Typical cases are:

* The parameter type is a compile-time template type parameter, or a type built from one, like `T[]` or `List<T>`. A compile-time type parameter stands for a type of the _generated_ code, so its values only exist at run time.
* The parameter type is a run-time type, for instance a class of the target project, or a type built from a run-time type parameter.

In the message, `<Parameter>` is the name of the parameter and `<Type>` is its type.

In the following example, the `Log` template has a compile-time type parameter `T` and a compile-time parameter `message` of type `T`.

## Resolution

Depending on your intent, do one of the following:

* If the value is only known at run time, remove the `[CompileTime]` attribute from the parameter. It becomes a run-time parameter: a parameter of the introduced method or, for an overriding template, a reference to a parameter of the overridden method.
* If the value is known when the aspect adds the advice, change the parameter type to a type that's available at compile time, for instance `string`, a compile-time-only type, or a type marked with <xref:Metalama.Framework.Aspects.RunTimeOrCompileTimeAttribute?text=[RunTimeOrCompileTime]>.

In the following example, the `[CompileTime]` attribute is removed from the parameter, so the introduced `Log` method receives the message as a parameter of type `string`.
