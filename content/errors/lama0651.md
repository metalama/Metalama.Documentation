# LAMA0651: meta.Proceed() can't be used with a compiler-synthesized record member

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot use meta.Proceed() when overriding the compiler-synthesized record member '<Member>'. Remove the call to meta.Proceed() from the template.` |

## Cause

For every record, the C# compiler generates members that aren't written in the source code, such as `Equals`, `GetHashCode`, and `EqualityContract`. An aspect can replace these members, for instance by introducing a method with <xref:Metalama.Framework.Aspects.OverrideStrategy.Override?text=OverrideStrategy.Override>.

When Metalama overrides a member, <xref:Metalama.Framework.Aspects.meta.Proceed?text=meta.Proceed> inserts the original implementation. A synthesized record member has no implementation in your source code: once you declare the member yourself, the compiler stops generating it. Therefore, Metalama reports LAMA0651 when a template calls `meta.Proceed()` while overriding a synthesized record member. The `<Member>` placeholder is the overridden member.

The diagnostic has no source location. Look for aspects that introduce or override members of a record.

In the following example, the `CustomHashCode` aspect overrides `GetHashCode` of a record and calls `meta.Proceed()`.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0651/LAMA0651_Error.cs name="Error"]

## Resolution

Remove the call to `meta.Proceed()` from the template and implement the member completely in the template. For `GetHashCode` or `Equals`, iterate over the fields and properties of the type at compile time.
