# LAMA0401: The custom attribute type isn't available at compile time

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `Cannot instantiate a custom attribute: cannot find the compile-time type '<Type>'. Make sure that the type exists and is annotated with [CompileTime] or [RunTimeOrCompileTime].` |

## Cause

Compile-time code, such as an aspect or a fabric, can read the custom attributes of a declaration through the code model. Usually, it reads their constructor and named arguments. It can also get an _instance_ of the attribute class with the <xref:Metalama.Framework.Code.AttributeExtensions.TryConstruct*> or <xref:Metalama.Framework.Code.AttributeExtensions.Construct*> methods. To create this instance, Metalama must load the attribute class at compile time, which is only possible when the class is part of the compile-time code of the project or of its references.

Metalama reports LAMA0401 when it must instantiate an attribute, but the attribute type `<Type>` isn't available at compile time. Typically, the attribute class is a plain run-time class: it isn't annotated with <xref:Metalama.Framework.Aspects.RunTimeOrCompileTimeAttribute?text=[RunTimeOrCompileTime]> or <xref:Metalama.Framework.Aspects.CompileTimeAttribute?text=[CompileTime]>. The error is reported on the custom attribute.

In the following example, the `Log` aspect calls `TryConstruct` to read the category given by a `[LogCategory]` attribute, but `LogCategoryAttribute` is a run-time-only class.

## Resolution

Depending on your situation, do one of the following:

* Annotate the attribute class with <xref:Metalama.Framework.Aspects.RunTimeOrCompileTimeAttribute?text=[RunTimeOrCompileTime]>, so that it's available both at run time and at compile time. The project that declares the attribute then needs a reference to the `Metalama.Framework` package. The following example shows this fix.
* If you can't change the attribute class, for instance because it comes from a package you don't control, don't instantiate the attribute. Read its arguments with the <xref:Metalama.Framework.Code.IAttributeData.ConstructorArguments> and <xref:Metalama.Framework.Code.IAttributeData.NamedArguments> properties instead.
