# LAMA0065: The options can't be set on the declaration

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The option '<OptionName>' cannot be applied to the <DeclarationKind> '<Target>' because <Reason>.` |

## Cause

Aspects can expose configuration through _hierarchical options_, which are classes implementing <xref:Metalama.Framework.Options.IHierarchicalOptions`1>. Like an aspect, an options class can also implement <xref:Metalama.Framework.Eligibility.IEligible`1> and define _eligibility conditions_ in its `BuildEligibility` method. These conditions describe the declarations on which the options can be set.

Metalama reports LAMA0065 when you set options on a declaration, typically with the `SetOptions` method in a fabric, but the declaration doesn't satisfy one of these conditions. In the message, `<OptionName>` is the name of the options class, `<DeclarationKind>` and `<Target>` are the kind and the name of the declaration, and `<Reason>` explains which condition failed.

In the following example, `LoggingOptions` can only be set on non-static types, but the fabric sets the options on all types of the project, including the static class `MathHelper`.

## Resolution

Depending on your intent, do one of the following:

* Filter the declarations on which you set the options, for instance with the `Where` method, so that only eligible declarations are selected. The following example skips static types.
* Change the declaration so that it satisfies the condition given in the message.
* If you're the author of the options class and the condition is too strict, relax the condition in its `BuildEligibility` method.
