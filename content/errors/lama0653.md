# LAMA0653: A synthesized record member reads a replaced property

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Framework |
| **Message** | `The original implementation of '<Member>' generated for record '<RecordType>' reads the property '<Property>', whereas the C# compiler reads its backing field. An aspect overrides the property with a template that does not call the original implementation, so the property has no backing field left and the generated body reads the value that the aspect returns instead of the value that the record stores. Call 'meta.Proceed()' in the template that overrides the property.` |

## Cause

The C# compiler synthesizes the `Equals` and `GetHashCode` methods of a record and reads the backing fields of its automatic properties. When an aspect overrides one of these methods and calls <xref:Metalama.Framework.Aspects.meta.Proceed*?text=meta.Proceed()>, Metalama writes the original implementation as source code, which reads the properties.

If the same aspect, or another one, overrides an automatic property of the record with a template that doesn't call `meta.Proceed()`, the property loses its backing field, and the value it returns no longer comes from the state of the record. The generated `Equals` or `GetHashCode` would then use the value that the aspect returns, not the stored value. Metalama reports LAMA0653 as a warning in this case. The `<Member>` placeholder is the synthesized method, `<RecordType>` is the record, and `<Property>` is the overridden property.

In the following example, the `TrackQuantity` aspect overrides both the `Equals` method and the `Quantity` property of the `OrderLine` record, but the getter template returns a constant. The warning is reported on the property.

## Resolution

Call <xref:Metalama.Framework.Aspects.meta.Proceed*?text=meta.Proceed()> in the getter and setter templates that override the property, so that the property keeps its backing field. If the aspect must replace the value of the property, consider whether the record should still use value-based equality.
