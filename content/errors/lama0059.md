# LAMA0059: An aspect class can't be generic

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Framework |
| **Message** | `The type '<AspectClass>' is not a valid aspect type because it is generic and not abstract. Only abstract aspect types can be generic.` |

## Cause

When Metalama loads the aspect classes of a project, it checks each of them. Metalama doesn't support aspect classes with type parameters, so it reports LAMA0059 for every non-abstract aspect class that's generic, whether or not the aspect is used. Since C# 11 allows generic attributes, this typically happens when you write an aspect meant to be used as `[MyAspect<int>]`.

An abstract generic class is accepted, because Metalama never instantiates it directly. In the message, `<AspectClass>` is the generic aspect class.

In the following example, the `Id` aspect is generic so that you can choose the type of the introduced `Id` property.

[!metalama-test ~/code/Metalama.Documentation.SampleCode.Errors/LAMA0059/LAMA0059_Error.cs name="Error"]

## Resolution

Remove the type parameters from the aspect class, and pass the information in another way:

* Pass the type as a `Type` argument of the aspect constructor, for example `[Id( typeof(int) )]`, and convert it to an `IType` with <xref:Metalama.Framework.Code.TypeFactory.GetType*> in `BuildAspect`. Then use the programmatic advice API, such as `IntroduceAutomaticProperty`, instead of declarative `[Introduce]` members.
* Alternatively, keep a generic base class but make it `abstract`, and derive one non-generic aspect class for each type argument you need.
