# LAMA0282: The aspect uses a newer C# version than the project

| | |
|---|---|
| **Severity** | Warning |
| **Reported by** | Metalama.Framework |
| **Message** | `The aspect '<Aspect>' uses features of C# <RequiredCSharpVersion>, but it is used in a project built with C# <TargetCSharpVersion>. Consider specifying <LangVersion><RequiredCSharpVersion></LangVersion> in this project or removing newer language features from the template '<Template>' and then specifying <MetalamaTemplateLanguageVersion> in the aspect project.` |

## Cause

When Metalama compiles a template, it records the highest C# version that the syntax of the template requires, including the syntax of its compile-time parts. When the template is expanded in a project whose C# version, given by the `LangVersion` MSBuild property, is lower than this version, the generated code may not compile.

Metalama reports LAMA0282 when an aspect defined in one project, typically an aspect library, is applied in another project that uses an older version of C#. The placeholders of the message are the aspect, the C# version required by the template, the C# version of the current project, and the template. Metalama reports the warning once per aspect class, on a declaration to which the aspect is applied.

When the newer syntax ends up in the generated code, the C# compiler additionally reports an error, for instance CS8936 for a raw string literal. In the following example, the raw string literal is a compile-time argument of `meta.InsertComment`, so the generated code still compiles, but Metalama reports the warning because the template requires C# 11 and the target project uses C# 10.

## Resolution

Depending on your role, do one of the following:

* If you use the aspect, raise the `LangVersion` property of your project to at least the version given in the message.
* If you author the aspect, remove the newer language features from the template, as in the following example where the raw string literal is replaced by a regular string literal. To make sure that your templates stay compatible with older C# versions, set the `MetalamaTemplateLanguageVersion` property of the aspect project to the lowest C# version you want to support. Metalama then reports LAMA0232 on any template syntax that requires a later version.
