# LAMA1002: A declaration introduced by an aspect can't be an interception scope

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Extensions.Interceptors |
| **Message** | `The <Source> cannot use '<Scope>' as an interception scope because '<Scope>' is introduced by an aspect. Interceptors apply only to call sites that exist in the source code.` |

## Cause

Metalama.Extensions.Interceptors lets an aspect or a fabric replace the calls to selected methods, in the source code of the current project, with calls to other methods. An aspect or fabric registers an interceptor with the `InterceptMethods` method of its adviser, builder, or amender. The declaration on which you call this method is the _interception scope_: only the calls located inside this declaration are intercepted.

Interceptors apply only to the calls that are written in the source code. A member or type that an aspect introduces doesn't exist in the source code, so the calls it contains can't be intercepted.

Metalama reports LAMA1002 when the scope is a declaration introduced by an aspect, for example the result of `IntroduceMethod`. In the message, `<Source>` describes the aspect or fabric, and `<Scope>` is the introduced declaration.
