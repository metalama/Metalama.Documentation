# LAMA5205: Several members match the naming convention

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Wpf |
| **Message** | `Several members, including this <Kind>, can be used as the <Role> for <TargetDescription>'<Target>' <AsRequired>by the '<NamingConvention>' naming convention. Rename or remove the members that must not be used, so that only one member matches.` |

## Cause

The <xref:Metalama.Patterns.Wpf.CommandAttribute?text=[Command]> and <xref:Metalama.Patterns.Wpf.DependencyPropertyAttribute?text=[DependencyProperty]> aspects find their helper members by name: the can-execute method or property of a command, and the property-changed and validate methods of a dependency property. Each role must be filled by a single member.

Metalama reports LAMA5205 when more than one member with a valid signature matches the same role. The diagnostic is reported on each of these members, and the aspect isn't applied to the target. Typical cases are:

* For a command named `Save`, the class has both a valid can-execute method and a valid can-execute property, for example a `CanSave()` method and an `IsSaveEnabled` property. The default naming convention accepts the names `CanExecuteSave`, `CanSave`, and `IsSaveEnabled`, as methods or properties.
* Several overloads of the helper method have a valid signature, for example `CanSave()` and `CanSave( object parameter )`, or `OnFooChanged()` and `OnFooChanged( int value )`.
* A custom naming convention uses a pattern, such as <xref:Metalama.Patterns.Wpf.Configuration.CommandNamingConvention.CanExecutePatterns>, that matches several members.

In the message, `<Kind>` is the kind of the reported member, `<Role>` is the role, `<Target>` is the aspect's target, and `<NamingConvention>` is the naming convention. `<AsRequired>` is `as required` when the member is required, for example because its name was set explicitly in the attribute.

## Resolution

Make sure that exactly one member matches each role:

* Remove the members that duplicate the logic, or rename the ones that aren't meant to be helpers of the aspect.
* Merge overloads of the helper method into a single method.
* For a command, name the intended member explicitly with <xref:Metalama.Patterns.Wpf.CommandAttribute.CanExecuteMethod> or <xref:Metalama.Patterns.Wpf.CommandAttribute.CanExecuteProperty>. Only methods or only properties are then considered, which removes an ambiguity between a method and a property.
* For a dependency property, name the intended method explicitly with <xref:Metalama.Patterns.Wpf.DependencyPropertyAttribute.PropertyChangedMethod> or <xref:Metalama.Patterns.Wpf.DependencyPropertyAttribute.ValidateMethod>. This doesn't help with overloads of the same name.
