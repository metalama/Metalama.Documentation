# LAMA5101: The invalidating method can't provide the instance of the cached method

| | |
|---|---|
| **Severity** | Error |
| **Reported by** | Metalama.Patterns.Caching |
| **Message** | `The [InvalidateCache] aspect applied to '<InvalidatingMethod>' cannot invalidate '<CachedMethod>': the 'this' parameter cannot be mapped because '<CachedMethod>' is an instance method, the IgnoreThisParameter option is not enabled for '<CachedMethod>', and '<InvalidatingMethod>' is either static or declared in the type '<InvalidatingMethodDeclaringType>', which is neither '<CachedMethodDeclaringType>' nor derived from '<CachedMethodDeclaringType>'.` |

## Cause

By default, the cache key of an instance method cached with the <xref:Metalama.Patterns.Caching.Aspects.CacheAttribute?text=[Cache]> aspect includes the instance on which the method is called, that is, the `this` parameter. To remove a value from the cache, the <xref:Metalama.Patterns.Caching.Aspects.InvalidateCacheAttribute?text=[InvalidateCache]> aspect must rebuild the same key, so it passes its own `this` as the instance of the cached method.

This is only possible when the invalidating method is an instance method of the type that declares the cached method, or of a type derived from it. Metalama reports LAMA5101 when all of the following conditions are true:

* The cached method `<CachedMethod>` is an instance method.
* The <xref:Metalama.Patterns.Caching.Aspects.CachingBaseAttribute.IgnoreThisParameter> option isn't enabled for the cached method.
* The invalidating method `<InvalidatingMethod>` is static, or its declaring type `<InvalidatingMethodDeclaringType>` is neither the declaring type of the cached method, `<CachedMethodDeclaringType>`, nor derived from it.

## Resolution

Do one of the following:

* If the result of the cached method doesn't depend on the instance, for instance because the type is a singleton service, exclude the instance from the cache key by enabling `IgnoreThisParameter`. You can set it on the `[Cache]` attribute, as in the following example, with the <xref:Metalama.Patterns.Caching.Aspects.CachingConfigurationAttribute?text=[CachingConfiguration]> attribute on the type or the assembly, or with a fabric.
* Move the invalidating method to the type that declares the cached method, or to a derived type, and make it an instance method.
* Invalidate the cache imperatively by calling the `Invalidate` method of the caching service with the right instance, instead of using the `[InvalidateCache]` aspect.
