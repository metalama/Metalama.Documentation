# Claude Code Instructions

This is the Metalama documentation repository. Documentation is generated by DocFx.

## Metalama concepts glossary

| Term | Definition |
|------|------------|
| Aspect | A class that transforms code at compile time. Applied via custom attributes or fabrics. |
| Fabric | A class that programmatically applies aspects or validators to multiple declarations. |
| Advice | Instructions provided by aspects specifying what code transformations to apply. |
| Template | C# code in aspects that generates run-time code. Uses `meta.*` API for metaprogramming. |
| Introduced member | A field, property, method, or event added to a type by an aspect. |
| Override | Replacing the implementation of an existing member while preserving access to original via `meta.Proceed()`. |
| Validator | Code that validates declarations or references against rules, reports diagnostics. |
| Diagnostic | A warning or error reported during compilation. |
| Code fix | A suggested correction attached to a diagnostic, shown in IDE lightbulb menu. |
| Compile time | Code that executes during compilation (aspects, templates, fabrics). |
| Run time | Code that executes when the compiled program runs. |
| Declaration | A code element: type, method, property, field, event, parameter, etc. |

## When to use what

| Goal | Use | Article |
|------|-----|---------|
| Add logging to methods | `OverrideMethodAspect` | `overriding-methods` |
| Add validation to parameters | `ContractAspect` or `Metalama.Patterns.Contracts` | `contracts`, `contract-patterns` |
| Add members to a type | `IntroduceMethod`, `IntroduceProperty`, etc. | `introducing-members` |
| Implement an interface | `ImplementInterface` | `implementing-interfaces` |
| Apply aspects to many declarations | `ProjectFabric` or `TypeFabric` | `fabrics` |
| Validate code against rules | `Metalama.Extensions.Validation` | `validation` |
| Share configuration across projects | `TransitiveProjectFabric` | `fabrics-many-projects` |
| Make aspects work with DI | `Metalama.Extensions.DependencyInjection` | `dependency-injection` |

## Common mistakes and pitfalls

| Mistake | Correct approach |
|---------|------------------|
| Using `nameof` in templates for introduced members | Use string literals; `nameof` resolves at compile time of aspect, not target |
| Forgetting `partial` on target classes | Classes receiving introduced members need `partial` for design-time support |
| Accessing run-time values at compile time | Use `meta.RunTime()` to convert compile-time expressions to run-time |
| Modifying aspect fields expecting per-target state | Aspect instances may be shared; use `IAspectState` or tags |
| Using `internal` members in templates | Templates generate code in target assembly; use `public` or `InternalsVisibleTo` |
| Expecting validators in `Metalama.Framework` | Validators are in `Metalama.Extensions.Validation` (separate package) |

## Writing documentation

### Article structure

* **toc.yml files** control navigation. There are several: `content/toc.yml` (root), `content/conceptual/toc.yml` (main), `content/patterns/toc.yml`, `content/videos/toc.yml`, `content/overview/toc.yml`. When creating a new article, always add an entry to the appropriate `toc.yml`.
* Each entry in `toc.yml` has `name:` (display title) and `topicUid:` (matches the `uid` in the article's frontmatter). Nesting uses `items:`.
* Every article starts with YAML frontmatter: `uid`, `level` (100/200/300), `summary`, `keywords`, `created-date`, `modified-date`.
* **Non-leaf pages** (parent pages with children) must end with a table listing all child articles with title and short description. Use this format:

```markdown
| Article | Description |
|---------|-------------|
| <xref:child-uid> | Short description of what this article covers. |
| <xref:another-child-uid> | Short description of the next child article. |
```

* Cross-references use `<xref:uid>` syntax, not markdown links.

### Code samples — no inline code

* **All C# code examples must be compilable files** in test projects under `code/`. Never write inline C# code blocks in markdown articles. Every example must be a real, compilable `.cs` file referenced from the article.
* Reference samples from articles using: `[!metalama-test ~/code/ProjectName/SampleName.cs name="Display Name"]`
* Alternative for non-test code: `[!code-csharp[](~/code/ProjectName/File.cs)]` or with range: `[!code-csharp[](~/code/ProjectName/File.cs?range=3-999)]`

### Sample code projects

* Sample code is under `code/` in separate C# files.
* Two types of samples:
  * **Snapshot-based tests** (`Metalama.Documentation.Snippets.TestBased.sln`): Test files `Foo.cs` with transformed output `Foo.t.cs` and auxiliaries `Foo.*.cs`.
  * **Project-based tests** (`Metalama.Documentation.Snippets.ProjectBased.sln`): Standard projects without snapshot testing.
* Multi-project examples: Use `Foo.Dependency.cs` as the referenced project and `Foo.cs` as the referencing project.
* Classes receiving introduced members must be marked `partial` (not helper classes like `Program`).
* To reference introduced members in tests, wrap with `#if TESTRUNNER`.
* To skip copyright headers: `[!code-csharp[](path?range=3-999)]`
* If a warning is desired output, it should appear in the `*.t.cs` file.
* Running a single test: `dotnet test --filter "FullyQualifiedName~TestName"`. HTML output under `(Project)/obj/html`.

## Building

* Markdig extensions changed: `Build.ps1 build` (avoid, slow)
* Sample changed: `dotnet test` for snapshot tests, `dotnet build` for other.
* Only Markdown changed: `update-html.ps1`
* Output: `artifacts/site`
* Fix file locks: `build.ps1 tools kill` (only if error shows lock)
* Local preview: HelpBrowser at `https://localhost:56539` (in `../HelpBrowser`, don't start it - doesn't run in background)
* URL notes: No `.html` suffix needed; `path/README.md` maps to `path`; `parent/parent` maps to just `parent` (`parent.md` is the index file).

## Cross-references (xrefs)

* API xrefs must match UIDs in `artifacts/api/*.yml`
* Warnings starting with `@` (like `@sharing-state-with-advice`) are resolved by a different script - do not fix
* For inherited members, use the declaring interface UID (e.g., `IHasParameters.Parameters` not `IMethod.Parameters`)
* For method overload groups, append `*` (e.g., `TypeFactory.GetType*`)

## Git commits

* Keep messages very short
* Include issue `#number` (same repo) or full link (other repo)
* No bold, backticks, or Claude signature in commit messages

## Terminology

* `runtime` = the CLR
* `run-time` = executes when the program runs (not during compilation)
